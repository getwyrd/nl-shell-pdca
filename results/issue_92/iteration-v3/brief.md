## Motivation

ADR-0023 moves everything OS-specific into one folder per supported OS so a later port
swaps a folder, not code. The gate (#12) needs its allowlist from that folder, and the
REPL must refuse to pretend a target fits an OS it was never checked on.

## Design

- Selection result: active target, whether it matches, the detected `ID`/`VERSION_ID`,
  and — when it doesn't match — the reason string "target does not match this OS"
  (spec §7.7), which #12 turns into degraded mode.
- Refusals exit before the REPL starts, with a non-zero status and a one-paragraph
  message on stderr.
- The candidate folder for automatic selection is `targets/<ID>-<VERSION_ID>`; its
  `target.toml` match fields must equal the os-release values too.
- Allowlist file: one table per command word (e.g. `[[command]]` entries or
  `[commands.ls]` — Do's choice), plus the spec version, documented by a comment at the
  top of the file that cites spec §6.2.

## Alternatives considered

- Falling back via `ID_LIKE` or the nearest version: rejected by ADR-0023 (a target
  never inherits another's allowlist).
- Keeping the allowlist in `src/nl_shell/policy/readonly.toml` (the pre-ADR-0023 plan):
  superseded by ADR-0023 §Follow-up.

## Impact & compatibility

On an OS with no target, nl-shell now refuses to start unless `--target` is given. On
Ubuntu 26.04 nothing changes for the user except a `:status` line. Every allowlist entry
lands in SUMMARY §6 for human review at sign-off.

## Open questions

- Should the allowlist content be its own slice, reviewed separately from the loader
  code? Kept together here because the issue asks for both and the test (g) pins the
  command set; split if review of the entries looks too large for one sign-off.
- Does "code outside `targets/` must not name an OS" cover the product tagline in
  `__init__.py:1`, `cli.py:14` and `pyproject.toml:8`? This brief says no; it is an
  exception to an ADR-0023 MUST and needs the human's approval at sign-off.
- "Degraded" in the issue's Done-when: degraded mode is a gate behaviour (spec §7.7) and
  the gate is #12. This bundle can only record the mismatch (flag, reason, warning,
  `:status` line); sign-off should accept that as meeting the issue's "(degraded)" wording,
  with the behaviour itself arriving in #12.
- Leaving `command` and `ip` off the v1 file differs from the spec §6.4 table; confirm at
  sign-off (the alternative is a §6.2 amendment).
