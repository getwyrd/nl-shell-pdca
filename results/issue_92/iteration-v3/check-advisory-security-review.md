# Security review — issue 92 / os-target-folder-and-selection

**Attacker-reachable inputs this diff touches:** none of the new code reads an untrusted input. The loader reads `/etc/os-release` (root-owned), `config.toml` and `targets/` (trusted, threat model §Trusted) and `--target` (typed by the user). But `targets/ubuntu-26.04/allowlist.toml` decides what #12's gate will run with no confirm. So each entry is reviewed against what untrusted input can reach once #12 reads the file: session environment (threat model input 3, e.g. a repo's `.envrc` loaded by direnv) and file contents/names (input 2).

## Findings

- NEEDS-HUMAN [human] — **Critical once #12 reads this file (nothing runs from it today)**. `targets/ubuntu-26.04/allowlist.toml:391-395` (`dpkg`, `dpkg-query`), `:406-411` (`rocminfo`, `vulkaninfo`) and `:340-341` (`man`). These entries are safe only if the environment can't change what the program runs. Spec §7.5 (`docs/design/specs/policy-gate/v1.md:192-195`) checks only `PAGER`, `MANPAGER`, `SYSTEMD_PAGER`, `GIT_PAGER`, `LESSOPEN`, `LESSCLOSE`, `LD_PRELOAD`, `LD_LIBRARY_PATH`, `BASH_ENV` and `ENV` against the baseline. Several variables outside that list make an allowlisted command run another program or load a library:
  - `DPKG_PAGER`, and `SHELL`, which runs it. dpkg-query(1): the pager is "executed with «$SHELL -c»" and `DPKG_PAGER` overrides `PAGER`. nl-shell runs commands in a PTY, so stdout is a terminal and `dpkg -l` pages. Reproducer: a cloned repo with `.envrc` containing `export DPKG_PAGER='sh -c "id > /tmp/pwned"; cat'`. After `cd` into it (direnv runs), a proposal of `dpkg -l` passes every §6/§7 check and runs `id` with no confirm. `SHELL=./evil` has the same effect, and also changes what `less`'s `!` runs.
  - `VK_ADD_LAYER_PATH` + `VK_INSTANCE_LAYERS` (or `VK_LOADER_LAYERS_ENABLE`, `VK_ICD_FILENAMES` / `VK_DRIVER_FILES`). The Vulkan loader then `dlopen`s a `.so` from a path in the repo. Reproducer: `.envrc` sets `VK_ADD_LAYER_PATH=$PWD/layer` and `VK_INSTANCE_LAYERS=VK_LAYER_evil`; then `vulkaninfo --summary` runs the repo's code. `HSA_TOOLS_LIB` does the same for `rocminfo` (the ROCm runtime loads the listed libraries).
  - `MANROFFOPT=-U`. man(1): "Every time man invokes the formatter … it adds the contents of $MANROFFOPT". groff `-U` turns on unsafe mode, which allows `.sy`. Reproducer: `.envrc` sets `MANROFFOPT=-U` and the repo ships `doc/x.1` containing `.sy id`; then `man ./doc/x.1` runs `id`.

  The file already admits the same kind of gap for `MANOPT` and `LESS` (`allowlist.toml:336-339`) and leaves it to sign-off. These variables are more of the same, and the list is probably still incomplete. Builders can't fix it alone, because brief criterion (g) fixes the command set exactly. Choose one: (a) extend §7.5's variable list (a spec change, through #12); (b) have #12 run allowlisted commands with a pinned or filtered environment; (c) drop `dpkg`/`dpkg-query`/`vulkaninfo`/`rocminfo` from v1 until (a) or (b) exists, as was done for `command` and `ip`.
- NEEDS-HUMAN [impl] — **Low (documentation and test gap)**. `targets/ubuntu-26.04/allowlist.toml:336-339`: the comment that tells #12 which environment variables §7.5 doesn't cover names only `MANOPT` and `LESS`. It should also name, next to the affected entries, `DPKG_PAGER` and `SHELL` (on `dpkg`/`dpkg-query`), `VK_*` and `HSA_TOOLS_LIB` (on `vulkaninfo`/`rocminfo`) and `MANROFFOPT` (on `man`). Then whoever builds #12 inherits the full list. `tests/test_targets.py:554` already pins the `less` `+cmd` note this way, and the same kind of test could pin these comments. This doesn't replace the human decision above. It only keeps the gap from getting lost.

## Checked, no finding

- **Path traversal through the target id.** `--target`, `target =` in `config.toml`, and the auto-selected `<ID>-<VERSION_ID>` all go through `_ID.fullmatch` (`src/nl_shell/targets.py:35`, `:130`, `:242`). That pattern rejects `/`, `..` as the first character, and empty ids. Its `id` must also equal the folder name (`:170`). `--target ../../tmp/x` is refused, so no allowlist can be loaded from outside `targets/`. In any case, the inputs are trusted.
- **Mismatch recording.** `Selection.matches` / `reason` (`targets.py:77-89`) carry the "target does not match this OS" state that spec §7.7 needs. No code path lets a named, non-matching target show up as matching.
- **Start-up errors.** `os_release.read` (`src/nl_shell/os_release.py:77-92`) now falls back only on `FileNotFoundError`, and turns read errors and bad UTF-8 into a refusal. `cli.py:36-38` catches all three error types. This fixes the earlier round's traceback. The error messages echo only os-release, config and target paths, all from trusted sources.
- **Last round's allowlist items.** `hostname` no longer allows resolver flags (`allowlist.toml:304-306`, tested at `tests/test_targets.py:542`). `nvidia-smi`/`rocminfo`/`vulkaninfo` have `max_operands = 0` (`:402-411`, tested at `:548`). The `less`/`more` `+cmd` route is documented for #12 and pinned by a test (`:343-349`, `tests/test_targets.py:554`). Whether `less` stays on v1 is already deferred to the human, so I'm not raising it again. The same goes for the T2 threat-model-touch item and the `command`/`ip` omissions.
- **Other entries, read option by option against §6.3.** `ls`, `tree`, `stat`, `file`, `realpath`, `readlink`, `cat`/`head`/`tail`, `od`, `strings`, the checksum tools, `cmp`, `diff`, the `grep` family, `sort`, `uniq`/`cut`/`tr`/`column`/`base64`/`xxd`, `jq`, `echo`/`printf`, `du`/`df`/`free`/`ps`/`ls*`, `date`, `env`/`printenv`, `history`, `systemctl`, `journalctl`, `ss` and `apt`/`apt-cache`. None of their listed options writes a file, runs a program or opens a connection. The pagers that `systemctl` and `journalctl` use are covered by `SYSTEMD_PAGER` in §7.5.
- **Gates.** C4 and T3 pass (`gate-logs/C4-verify.log`, `gate-logs/T3-suite.log`: 225 passed). I didn't run anything against a real dpkg, Vulkan or man-db. The reproducers above come from the tools' own man pages (`dpkg-query(1)` DPKG_PAGER, `man(1)` MANROFFOPT) and the Vulkan loader's documented environment variables. They can't run end to end until #12 exists.
