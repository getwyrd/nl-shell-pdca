# Security review (advisory): issue 92, os-target-folder-and-selection

**Attacker-reachable inputs this diff touches:** the read-only allowlist (`targets/ubuntu-26.04/allowlist.toml`). It decides which **model proposals** (threat model, untrusted input 5) run without a confirm, and its effect also depends on **session state** (input 4: env vars set by a confirmed `source` or by repo tooling). The Python code (`config.py`, `os_release.py`, `targets.py`, `cli.py`, `repl.py`) reads only trusted input: what the user types (`--target`), the user's own `config.toml`, and the root-owned os-release file.

Rubric: `.oss-scanner/threat_model.md` (read). `AGENTS.md` has no reviewer protocol or tracked deferrals.

## Findings

- NEEDS-HUMAN [human] — **Critical (conditional on how #12 parses `+` words)**, `targets/ubuntu-26.04/allowlist.toml:338-340` (`[commands.less]`). **Input:** a model proposal (untrusted, item 5). **What goes wrong:** `less` treats any argument that starts with `+` as an initial command, and that command can be `!cmd` (run a shell command), `|` (pipe to a command) or `v` (open an editor). Spec §1.1 allows a LF inside quotes in a proposal. So a proposal like `less '+!touch /tmp/pwned<LF>q' README.md` is just `less` plus one operand under §6.2, with no `-` option. The entry has no `max_operands` and no field that can forbid `+` words, so unless the #12 gate treats `+…` as an unlisted option, this runs a program with no confirm. **Reproduced here:** `script -qc "less '+!touch ./pwned-by-less<LF>q' in.txt"` created `./pwned-by-less` (less 668). The brief's rule (Scope (2)) is "if no §6.2 shape is safe, leave the word off — decided here, not by Do". That makes this a brief/spec decision, not a builder fix. Options: (a) leave `less` off v1, as was done for `command` and `ip`; (b) state in spec §6.2 that a word starting with `+` counts as an option (so it is unlisted, so `mutating`) for `less`/`more`, and pin that for #12; (c) have #12 always run `less` with `LESSSECURE=1`. `more` (`:342-344`) only takes `+NUM`/`+/pattern` and is not affected the same way.
- NEEDS-HUMAN [impl] — **Medium (test gap)**, `tests/test_targets.py:463`. The (g) restriction checks for `man`/`less`/`more` only assert that `-P`, `-H`, `--pager`, `--html` and `-k` are absent. Nothing records the `+cmd` route above, either as a test, or as a comment on the `[commands.less]` entry warning #12 that `+` words must not count as plain operands. Whichever way the human decides the item above, add a file comment on the `less` entry and a test that pins the decision (for example: `less` absent, or a vector `less '+!id' f` → `mutating` handed to #12's vector list).
- NEEDS-HUMAN [human] — **High**, `targets/ubuntu-26.04/allowlist.toml:335-344, 379-383, 392-393` (`man`, `less`, `dpkg`/`dpkg-query`, `vulkaninfo`), against spec `policy-gate/v1` §3 and §7.5. **Input:** session environment (items 3 and 4). For example, a repo script the user confirmed as `source scripts/env.sh`, or a direnv `.envrc`, sets a variable that these entries read but that the §7.5 baseline check (`PAGER`, `MANPAGER`, `SYSTEMD_PAGER`, `GIT_PAGER`, `LESSOPEN`, `LESSCLOSE`, `LD_PRELOAD`, `LD_LIBRARY_PATH`, `BASH_ENV`, `ENV`) does not cover. A later "read-only" proposal then runs code with no confirm, and the gate never sees the session change. **Reproduced here:** `LESS='+!touch ./pwned-by-LESS-env<LF>q' less in.txt` created the file. The same class covers `MANOPT` (man-db reads options from it, including `-P`/`-H`, the very options this entry excludes), `DPKG_PAGER` (used by `dpkg -l`/`dpkg-query -l` on a terminal), `VK_LAYER_PATH`/`VK_ADD_LAYER_PATH`/`VK_ICD_FILENAMES` (make `vulkaninfo` load an arbitrary shared library), and `LD_AUDIT` (only `LD_PRELOAD`/`LD_LIBRARY_PATH` are snapshotted). This is a spec gap, not a builder bug. This diff is the first allowlist to depend on it, and the allowlist header (`:333-334`) claims the pager variables are covered by §7.5. A human should decide whether to extend the §3/§7.5 variable lists (in #12 or a spec amendment) or to hold back these words until they are extended.
