- NEEDS-HUMAN [impl] — **A small `[model] timeout_s` still crashes the REPL with an uncaught `TimeoutError`.** This is the low-end twin of iteration-5 finding 1. `config.valid_timeout` (`src/nl_shell/config.py:99`) accepts any value > 0. But `TeacherClient.complete` calls `self._connection(watch)` at `src/nl_shell/teacher_client.py:356`, and the connection constructors call `watch.left()` at `:267`, `:288` and `:301`. `left()` raises a bare `TimeoutError` (`:199`) once the deadline has passed. That call sits **outside** `_exchange`'s `try`, so the error is never turned into a `TeacherError`. `Repl._propose` catches only `BackendError` (`src/nl_shell/repl.py:156`), so the session dies. Concrete case: `config.toml` with `[model]\ntimeout_s = 1e-5` loads fine, and the first natural-language line kills the REPL. I measured 50/50 escapes at 1e-9, 1e-6 and 1e-5 on the unix path. On the `https://` path 20/20 escape at `timeout_s=0.001`, because `ssl.create_default_context()` runs first (`:300`). Fix: move `_connection` inside the `try` (or catch `TimeoutError` around it and map it to `_timed_out`), and/or set a sane lower bound in `valid_timeout`. Add a regression test, e.g. `timeout_s=1e-9` → reply `could not be used … within`, REPL keeps reading.
