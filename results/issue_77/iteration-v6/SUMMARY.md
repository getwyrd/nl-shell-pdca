## 1. Spec (from brief.md)              ← Check verifies against THIS
- Defect / goal: nl-shell sends its model input to an OpenAI-compatible chat endpoint (llama.cpp `llama-server` or vLLM, no API key) and gets a `proposal/v1` answer back, using constrained decoding. It does this as a backend for #143's `Backend` interface, so the interactive REPL actually proposes commands. By default it talks only to the local model socket `$XDG_RUNTIME_DIR/nl-shell/model.sock`. Any other endpoint is used only when the user passes `--dev-teacher` for that session. A `teacher_url` in `config.toml` alone is refused with a message. A non-loopback `http://` URL gets a warning to use an SSH tunnel or TLS, because the state block goes out in clear text.
- Success criterion: `python3 -m pytest tests/test_teacher_client.py` passes. The test runs a fake OpenAI-compatible HTTP server (stdlib `http.server`) on `127.0.0.1` port 0 and on a Unix socket, and covers:
  **(a) request shape.** A valid response whose `choices[0].message.content` is a `proposal/v1` object → the client returns that content string. The fake server received exactly one `POST /v1/chat/completions`. Its JSON body has `messages` equal to the model input as `[{"role": m.role, "content": m.content}, …]`, in order. It has a JSON-schema `response_format` whose schema is `==` `nl_shell.proposal.SCHEMA` (#143's object, imported, never a copy). It has no `Authorization` header. With `teacher_model = "m1"` in `config.toml` the body has `"model": "m1"`; without that key the body has no `model` key.
  **(b) strict transport handling.** Each case below is rejected, never repaired, with a reason and no retry: an HTTP error status; a 3xx redirect (not followed: the fake server sees one request, and a second listener named in `Location` sees none); a body that isn't JSON; JSON without a string `choices[0].message.content`; a body over the size cap (the client stops reading past the cap); a server that never answers (client built with `timeout_s=0.5`, server sleeps 2 s, test finishes in under 2 s); a **slow-drip** body (valid status line and headers, then one body byte every 0.2 s for longer than the timeout; client built with `timeout_s=0.5` gives up in under 2 s, so the timeout is a total deadline, not a per-read one); the deadline comes from `model.timeout_s`: `config.load` on a file without `[model]` gives `model_timeout_s == 10`, on `[model]\ntimeout_s = 0.5` gives `0.5`, and a non-number, a bool or a value <= 0 raises `ConfigError`; and `cli.main` with `[model] timeout_s = 0.5`, the slow-drip fake server on the default socket and one natural-language line → `out` shows the `could not be used` reply and the run finishes in under 2 s; an `https://127.0.0.1:<port>` URL pointed at the plain-HTTP fake server → rejected with a TLS error and no plain-HTTP request sent.
  **(c) endpoint rules.** No flag and no config URL → the default socket is used (a fake server on that path answers). `teacher_url` in `config.toml` without `--dev-teacher` → refused with a message on stderr, the default socket is used, and a fake server at that URL receives nothing. The same config URL with `--dev-teacher` (no argument) → used. `--dev-teacher <URL>` on the command line → used, and it wins over `teacher_url`. A non-loopback `http://` URL with the flag → the warning. The endpoint rules are tested by calling `teacher_client.select_endpoint` directly (signature in Scope (3)) and checking the returned endpoint and message list, so nothing connects off the host; the refusal and the warning reaching stderr is tested once each through `cli.main` with `capsys`.
  **(d) through `Repl`, with `Repl(read, out, backend=<the client>, prompts=<loaded prompts>)` pointed at the fake server.** A natural-language line → `out` shows #143's framed proposal for the fake server's answer (`Proposed command (risk: …`). Each `proposal/v1` §Conformance reject case, delivered as `message.content`, → `out` shows exactly `No usable proposal came back from the model.` and the REPL keeps reading. The cases are: extra property, missing `risk`, `command` with `reason`, `command` over 2000 code points, invalid JSON, a JSON array. (The "risk lower than the gate's class" case needs #12.) With the default socket absent → `out` shows exactly the new fixed "model server isn't running" reply, nothing raises, and the next line is still read. A transport failure whose server text holds control characters → no ESC, BEL or CR reaches `out`. The server here sends HTTP status line `HTTP/1.1 500 \x1b]52;c;ZWNobyBwd25lZA==\x07\x1b[2K\rnl> fake`, and the fake also sends an error body. The same holds for the client's error reason string itself (`"\x1b" not in reason`).
  **(e) `:status`.** `cli.main` builds `:status` lines naming the endpoint in use and the backend kind (checked through `cli.main` the way `tests/test_cli.py:29-46` captures `status_lines`).
  **(f) no TCP on the default path.** `socket.socket.connect` and `socket.create_connection` are patched to record their calls. Then `cli.main([], targets_root=…, os_release_paths=[…])` runs with a matching os-release and a target that has a `prompts/prompts.yaml`, as `tests/test_cli.py:29-46` does. It runs with `teacher_url = "http://127.0.0.1:<port>"` in `config.toml`, no flag, a fake server at that URL, and a scripted `Repl` input of one natural-language line, then EOF. The result: zero `AF_INET` / `AF_INET6` connects, **exactly one** `AF_UNIX` connect, and its address is `$XDG_RUNTIME_DIR/nl-shell/model.sock`. This goes red if endpoint selection leaks the config URL, and red if the REPL is not wired to the client.

- Scope (one logical fix) / out of scope: (1) **Client** — new `src/nl_shell/teacher_client.py`. It holds a class implementing #143's `Backend` protocol (`complete(messages) -> str`, as `RecordingStub` does in `src/nl_shell/backend.py`). It speaks OpenAI chat-completions over HTTP to a TCP URL (`http://`, `https://`, using the stdlib `http.client`) or to the Unix socket (ADR-0018 §1). The request carries the messages, `response_format` = a JSON-schema wrapper around `proposal.SCHEMA`, and `model` only if `teacher_model` is set. A URL with userinfo is refused. Certificate and hostname checks are on, with no plain-HTTP fallback. It opens no connection. `cli.main` writes each message to stderr. `--dev-teacher [URL]` in `cli.py` enables a non-default endpoint for this session, taking the URL from the flag or else from `teacher_url`. `teacher_url` without the flag is refused with a stderr message and the default is used. A non-loopback `http://` host gets the SSH-tunnel / TLS warning (loopback = `localhost`, `127.0.0.0/8`, `::1`; any other hostname counts as non-loopback, with no DNS lookup). `config.py` gains `teacher_url` and `teacher_model` (strings, type-checked like `target`, `config.py:60-63`). (4) **Errors into the REPL** — add one exception type to #143's backend interface (`backend.BackendError`, in `src/nl_shell/backend.py`; its only change). The client raises a subclass of it. `Repl._propose` (`repl.py:142-150` on main+#143) catches `BackendError` around `self._backend.complete(...)` and returns a fixed reply. That reply is exactly `The model server isn't running (no answer at <socket path>).` for an absent or refused default socket, and a fixed `The model server could not be used: <reason>.` otherwise. Server-supplied text in `<reason>` is passed through `render.escape` when the error is built (the reason phrase, error body excerpt and `{exc}` text). This is on top of the REPL's existing escape of every reply, so the reason string is already safe for logs. The REPL keeps running. (5) **Wiring** — `cli.main` builds the client for the chosen endpoint and passes it as `backend=` to `Repl.interactive` (`cli.py:65` on main+#143; today it passes `prompts=` only), replacing #143's interactive "no backend configured" default. `NO_BACKEND` stays for a `Repl` built without a backend. (6) **`:status`** — two lines appended in `cli.main` with the other session lines: the endpoint in use and the backend kind (ADR-0020 §4). / out of scope: starting or installing `llama-server` or the systemd user service (#48); the student model (#42); the reader's request (#61); API keys or any credential (ADR-0006/0015); retries and streaming; the rest of ADR-0018 §7 — the *unavailable* state, the `/health` check, background retry and "model is back" notice, non-blocking requests, `model.cpu_fallback` (see Decisions); any change to `proposal/v1`, `proposal.py`, `render.py` or the proposal rendering (#143/#144 own them); the hidden-character set (#144); the policy gate and the "risk below the gate's class" vector (#12); the architecture doc 05 table (one docs pass after the batch).

For `http://[::1]/` with no port, `urlsplit` gives hostname `::1` and port `None`, and `HTTPConnection('::1', None)` reads the trailing `:1` as a port. I checked this on 3.14.4: the result is host `:`, port 1. `_is_loopback` reports `::1` as loopback, so no clear-text warning is shown, but the connection then fails rather than going to some other host. ## What I checked and found sound
