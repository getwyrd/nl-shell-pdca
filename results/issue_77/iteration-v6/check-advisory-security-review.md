# Advisory security review — issue 77 (teacher client, `--dev-teacher`)

Attacker-reachable inputs this diff touches: threat-model item 11 (the dev teacher endpoint: a LAN peer controls the HTTP status line, reason phrase, headers, body and timing), item 8 (the local model socket, same user only) and item 5 (the model's answer, `message.content`). The URL itself comes from argv or `config.toml`, which the threat model counts as trusted (`.oss-scanner/threat_model.md:94-101`).

Grounding caveat: the C4 gate failed because `patch.diff` did not apply to the target checkout. `$PDCA_TARGET` (`/home/eddie/nl-shell/nl-shell.pdca-wt-l1`, HEAD `0771812`) has no `src/nl_shell/backend.py`, `proposal.py`, `render.py` or `prompts.py`, so #143 is not in that base. Because of that, the `path:line` references below for new code point to lines in `patch.diff`, not to files in the target. I could not check `render.escape` (from #143) against real source, and I did not run the test suite.

## Findings

- NEEDS-HUMAN [human] — The review base is missing #143, so nothing here was checked against applied code. C4 fails with `worktree-mismatch` (`check-gates.json`, row C4): the patch "did not apply onto 'origin/pdca-integration/main-r2546dbf9639f'". `teacher_client.py` imports `nl_shell.render`, `nl_shell.backend` and `nl_shell.proposal`, and none of them exist at `$PDCA_TARGET`. The two escape guarantees (invariant (2) in brief.md:31, the must-hold at threat_model.md:131) depend on `render.escape` removing ESC, BEL and CR. I could not confirm that. The test `test_server_text_is_escaped` (patch.diff:1645-1662) would confirm it once it runs on a base that has #143 folded in. This is a base/scheduling problem for the human or driver to fix. The builder can't fix it by iterating.

- Low — `src/nl_shell/teacher_client.py`, `TeacherClient.complete` → `_connection` (patch.diff:645, 676-683). A `--dev-teacher` or `teacher_url` host with a space or control character gets past `_check_url` (patch.diff:423-438). `http.client.HTTPConnection.__init__` then raises `http.client.InvalidURL`. That call sits outside the `try` in `_exchange` (patch.diff:695-735), so it is not turned into a `TeacherError`. `Repl.run` catches only `EOFError` and `KeyboardInterrupt` (`src/nl_shell/repl.py:62,64` at the target), so the first natural-language request crashes the REPL. Input: `nl-shell --dev-teacher 'http://a b:80/'`, then any request. I checked on Python 3.14.4 that `HTTPConnection('a b', 80)` raises `InvalidURL: URL can't contain control characters`. Only the user's own trusted argv or config can reach this, so it counts as a user misconfiguration (Low). It is still a crash, not a fixed reply. The fix is either to reject such hosts in `_check_url` (with a test) or to build the connection inside the `try`. Also, the same URL is printed unescaped to stderr in `CLEAR_TEXT_WARNING` and in the `EndpointError` messages (patch.diff:419, 428-437). That is the user's own text, so it is not a finding by itself.

- Low (not a security break; it fails closed) — the same `_connection` path. For `http://[::1]/` with no port, `urlsplit` gives hostname `::1` and port `None`, and `HTTPConnection('::1', None)` reads the trailing `:1` as a port. I checked this on 3.14.4: the result is host `:`, port 1. `_is_loopback` reports `::1` as loopback, so no clear-text warning is shown, but the connection then fails rather than going to some other host. Nothing leaks. I mention it because the warning check and the connect target disagree. The fix is to pass a default port (80/443) whenever `parts.port` is `None`.

## What I checked and found sound

- **No TCP in the default config** (threat_model.md:143). `select_endpoint` (patch.diff:394-420) returns the Unix endpoint whenever `dev_teacher is None`, and only adds a notice if a config URL is present. `test_default_path_opens_no_tcp` (patch.diff:1684-1709) patches `socket.socket.connect` and `socket.create_connection`, puts a live TCP fake at the config URL, and asserts zero `AF_INET`/`AF_INET6` connects, exactly one `AF_UNIX` connect, and that the TCP fake received nothing. That covers the attacker-relevant case: a copied config with a LAN URL.
- **Server text reaching the terminal** (threat_model.md:131). The reason phrase, the 200-byte error-body excerpt, `ssl.SSLError` text, connect errors and the generic `{type}: {exc}` text (which carries `BadStatusLine` and `LineTooLong` content) all go through `_escape` (patch.diff:715-735). The fixed messages (redirect, size, not JSON, timeout) contain no server text. `test_server_text_is_escaped` sends the OSC 52 (terminal clipboard-write escape) + CR + fake `nl>` status line from the brief and checks both the reason string and the REPL output for ESC, BEL and CR. The generic exception-text path has no dedicated test, but it uses the same `_escape` call, and the REPL escapes each reply again.
- **Redirects, proxies, credentials**. The client uses `http.client` directly: it follows no redirect and ignores `HTTP(S)_PROXY`. 3xx is rejected before the body is read (patch.diff:710-713), and the test checks that a second listener named in `Location` sees nothing. URLs with userinfo or `@` are refused (patch.diff:432). No `Authorization` header is sent (checked in `test_request_shape`).
- **TLS**. `ssl.create_default_context()` verifies certificates and host names. The handshake runs in `connect` before any request bytes go out, so the state block is never sent over a failed or plain connection. The test points `https://` at the plain-HTTP fake.
- **Resource use from a hostile server**. The body is capped at 64 KiB (`_read`, patch.diff:752-775). `http.client` caps header count and line length (as `HTTPException`, which is caught). `json.loads` `RecursionError` is caught (patch.diff:781). A per-request `threading.Timer` shuts down whichever socket is current and bounds total time, even for a drip-fed chunk-size line after `Connection: close`. That case has its own test (patch.diff:1381). `[model] timeout_s` is bounded to 3600 s, which removes the earlier `OverflowError` crash.
- **Model output**. `complete` returns raw `message.content` with no parsing or repair (patch.diff:778-789). `Repl._propose` sends it to #143's `proposal.parse` (patch.diff:281). The test `test_repl_rejects_bad_proposals_and_keeps_reading` covers the conformance reject cases. Nothing runs yet (no gate wiring), so no proposal can execute.
- **Local socket** (item 8). The client trusts whatever answers at `$XDG_RUNTIME_DIR/nl-shell/model.sock` and does not check the socket's owner or mode. Only a misconfigured `XDG_RUNTIME_DIR` (for example, a world-writable dir) would let another user plant a socket. Same-user code is out of scope (threat_model.md:54-56), so I am not filing this.
