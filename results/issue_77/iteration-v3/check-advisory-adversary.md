# Adversarial review — issue 77 (teacher client, `--dev-teacher`)

The gates are green (C4 red 43/98 → green 98/98, T3 366 passed, per gate-logs). I could not re-run pytest here (`No module named pytest` in this sandbox), so I relied on the frozen logs for that. The logs show the tests pass. The problem is what the tests check: the feature in the brief is not wired up.

- NEEDS-HUMAN [human] — **The client is never used in production.** `TeacherClient` is built only in tests. `src/nl_shell/cli.py:53` computes an endpoint, but `src/nl_shell/cli.py:82` still calls `Repl.interactive(status_lines=...)` with no backend. A natural-language line still gets `NATURAL_LANGUAGE_NOT_YET` ("the model backend arrives in M0.8", `src/nl_shell/repl.py:25-31`). Concrete failing case: run `nl-shell --dev-teacher http://127.0.0.1:8080` with a live server and type "list the files here". The server gets no request, and the user gets the placeholder. Brief Scope (4) and success criterion (d) ("through `Repl` with the client pointed at the fake server: a natural-language line shows the fake server's proposal; when the default socket is absent, the reply says the model server isn't running") have no code and no test behind them. `:status` now says "backend: OpenAI chat completions", but no such backend is running. I tag this [human] because of the next bullet: the gap exists because the dependencies are missing.
- NEEDS-HUMAN [human] — **The #16 dependency is not on the base.** The target has no backend interface, no `proposal/v1` parser and no schema. `grep -rn -i 'backend|proposal|schema' src` finds only the new `teacher_client.py` and the M0.8 placeholders in `repl.py`/`input_modes.py`. The brief (branch-target line) says: "if any is not accepted, this bundle is not scheduled. … do not invent stand-ins." The builder used a stand-in instead: `tests/test_teacher_client.py:28` `SCHEMA` is a hand-written two-field object, not "the same object #16's parser uses". So criterion (a)'s schema check is a tautology (the client echoes whatever dict it was given). None of the (b) `proposal/v1` §Conformance reject cases are tested or handled: extra property, missing `risk`, `command` with `reason`, `command` over 2000 code points, invalid JSON, JSON array. `complete()` returns raw `content` at `src/nl_shell/teacher_client.py:308-320` with no `proposal/v1` validation. Either the wave was scheduled without #16, or the base is wrong. A human has to decide whether to reschedule this after #16 lands or accept a reduced scope.
- NEEDS-HUMAN [impl] — **The (f) "no TCP on the default path" test proves nothing.** `tests/test_teacher_client.py:506-530` asserts that no AF_INET/AF_INET6 connect happens after `cli.main([])` plus one natural-language line. Nothing in the REPL path ever opens a socket (see the first bullet), so the assertion holds whether or not `choose_endpoint` refuses the config URL. Concrete case: change `choose_endpoint` (`src/nl_shell/teacher_client.py:157-161`) to return `Endpoint(url=config_url)` when the flag is absent, and this test still passes (only the stderr text check would catch it, and that does not test connections). The brief's (f) also expects "only the AF_UNIX attempt to the default socket", but the test never asserts that an AF_UNIX attempt happened. Once the client is wired in, assert that exactly one AF_UNIX connect went to the default socket path.
- NEEDS-HUMAN [impl] — **Part of the C4 "red" comes from test edits, not the fix.** Many red-leg failures in `gate-logs/C4-verify.log` are the existing `test_cli.py`/`test_targets.py` assertions. They fail only because the patch appended two `:status` lines (`tests/test_cli.py:48`, the `MODEL_LINES` additions in `tests/test_targets.py`). That is status-text churn. It does not show that the client or the endpoint rule works. The 43-failure count overstates how much the evidence covers. Criteria (d) and (f) have no test that would go red for the right reason.
- Attempted, could not refute: endpoint selection and the client's rejection paths. Redirect status is checked before the body is read (`src/nl_shell/teacher_client.py:298-301`). The size cap reads at most `max+1` bytes, chunked bodies included. The TLS context is `ssl.create_default_context()` with no plain-HTTP fallback. Credentials in the URL are refused (`check_url`). A relative or unset `XDG_RUNTIME_DIR` gives no default socket. The loopback check does no DNS lookup, and odd forms like `127.1` or `localhost.` fall into the warning, which is the safe side. The timeout test bounds itself at 2 s. I found no input that breaks these pieces when they are tested on their own.
