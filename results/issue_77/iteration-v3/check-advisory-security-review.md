# Security review (advisory) — issue 77 / teacher-client-dev-teacher-flag

Attacker-reachable inputs this diff touches: threat-model item 11 (the dev teacher endpoint: a LAN peer can answer or watch it once `--dev-teacher` is on), item 8 (the local model socket, same-user only), item 5 (model output, i.e. `choices[0].message.content`), and the trusted-input exception "a model endpoint in config is refused without `--dev-teacher`" (`teacher_url` in `config.toml`).

## Findings

- NEEDS-HUMAN [impl] — **Low today, would be High once the reason is printed** (rubric: "printed text … spoofs the confirm UI" / "output writes the clipboard"). `src/nl_shell/teacher_client.py:312-314` (`_read_body`) puts the server's HTTP reason phrase (`response.reason`) into `TeacherError.reason` as is. The text comes from whoever answers the dev teacher URL (a LAN peer, item 11). `http.client` decodes the status line as latin-1 and filters nothing, so ESC/BEL/CR survive. I reproduced it against the patched client: the status line `HTTP/1.1 500 \x1b]52;c;ZWNobyBwd25lZA==\x07\x1b[2K\rnl> fake` gives `reason == 'the model server answered with HTTP 500 \x1b]52;c;ZWNobyBwd25lZA==\x07\x1b[2K\rnl> fake'`. That is an OSC 52 clipboard write plus a fake `nl>` prompt. Nothing displays `reason` yet, because the client isn't wired into the REPL (see the next bullet). But the brief's (d) wants the reason shown to the user, and the must-hold "output rendering is filtered everywhere" would then break. Fix: drop `response.reason` or escape non-printables (`repr` / `ascii`), and do the same for the `{exc}` text at `:257` and `:278`. Add a test whose fake server sends a reason phrase with control characters.
- NEEDS-HUMAN [human] — **No severity (scope).** `src/nl_shell/repl.py:20-31,71` is unchanged. Natural-language lines still get the fixed `NATURAL_LANGUAGE_NOT_YET` reply, and `TeacherClient.complete` (`src/nl_shell/teacher_client.py:236-281`) returns raw `content` without the `proposal/v1` check. Item 5 (model output) is therefore never validated. The #16 parser, schema and backend interface that the brief depends on don't exist on this base: `grep -rn -i proposal src/` only hits comments in the new file. Three security results follow. (1) The brief's (b) `proposal/v1` reject cases (extra property, missing `risk`, `command` with `reason`, over 2000 code points, array) aren't tested. The fake `SCHEMA` at `tests/test_teacher_client.py:28-33` is a stand-in. (2) The (f) test `test_config_url_without_the_flag_makes_no_tcp_connection` (`tests/test_teacher_client.py:506-530`) passes without ever building a client: the REPL makes no model call, so the "no outbound connection in the default config" guarantee is only checked at the `choose_endpoint` level, not end to end. (3) When #16 is wired in later, nothing forces the parser onto `complete()`'s output. A human should decide whether this bundle can be accepted without #16, against the brief's "if any is not accepted, this bundle is not scheduled".
- NEEDS-HUMAN [impl] — **Low** (a hang reachable from untrusted input, behind `--dev-teacher`). `src/nl_shell/teacher_client.py:258` sets `READ_TIMEOUT_S` as a per-socket-operation timeout, not a deadline for the whole response. A peer at the dev teacher address that sends one byte every 119 s never trips it. `read(self._max_bytes + 1)` at `:318` would keep going for up to 64 KiB × 119 s. Test: a fake server that sends a valid status line and headers, then one body byte every 0.4 s, against a client with `read_timeout=0.5`. Today `complete` doesn't return within a few seconds. Fix: track a total deadline (`time.monotonic()`) and check it while reading in chunks.
- **Note, not rated** (gate gap). `gate-logs/T2-threat-model.log` says "no security-relevant path touched", but this diff adds the first network client and the endpoint rules (the must-hold "no outbound connection in the default config"). The threat model already describes item 11 and the config exception, so the code doesn't contradict it. Still, the T2 path list probably should treat `teacher_client.py` / `cli.py` endpoint changes as security-relevant. That is for the harness owner, not this patch.

## Checked, no finding

- Default path: `default_socket` (`teacher_client.py:116-122`) returns `None` for an unset or relative `XDG_RUNTIME_DIR` (no `/run/user/<uid>` guess). Without the flag, `choose_endpoint` (`:160-164`) never uses `config_url`; it only shows it, through `!r`, so a copied config can't inject escapes into that message. `_UnixHTTPConnection` opens only `AF_UNIX`.
- Credentials: `check_url` (`:135-145`) refuses userinfo URLs, and no `Authorization` header is sent. `http.client` (unlike `urllib`) ignores `HTTP(S)_PROXY`, so the state block can't be diverted through an env-set proxy.
- TLS: `ssl.create_default_context()` keeps certificate and hostname checks on, and nothing falls back to plain HTTP (`:294-298`, test at `tests/test_teacher_client.py:320-327`).
- Redirects: any 3xx is rejected before the body is read and never followed (`:307-310`). The test checks the redirect target gets nothing.
- Size cap: a `Content-Length` precheck plus `read(max+1)` caps chunked bodies too. Tested with a 4 MiB chunked stream.
- The clear-text warning (`is_loopback_host`, `:125-132`) errs toward warning (`localhost.`, `127.1`, `::ffff:127.0.0.1` and any hostname count as non-loopback) and does no DNS lookup. It is a warning only, as the brief asks.
- The `teacher_model` / `teacher_url` type checks in `config.py` reject non-strings.
