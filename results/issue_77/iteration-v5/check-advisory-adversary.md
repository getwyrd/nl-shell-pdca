# Adversarial review — issue 77 (teacher client, `--dev-teacher`)

I could not re-run pytest here (`pytest` is not installed in this sandbox). I judged the gates from the frozen logs (C4: 224 passed green, 131 of 224 failed red; T3: 441 passed). I ran the production client directly with `python3 -I` against `$PDCA_TARGET/src`.

## Findings

- NEEDS-HUMAN [impl] — A large `[model] timeout_s` crashes the REPL. `src/nl_shell/config.py:76-82` accepts any finite number > 0, so `timeout_s = 1e10` loads (I checked: `config.load` returns `10000000000.0`). The client then calls `sock.settimeout(1e10)` (`src/nl_shell/teacher_client.py:171`, and `_tick` at `:328` / `http.client`'s own connect on the TCP path). On Linux/CPython 3.14 that raises `OverflowError: timestamp out of range for platform time_t`. That is not caught by `_exchange` (`teacher_client.py:293-306` catches only `TeacherError`, `SSLError`, `OSError`, `HTTPException` and `ValueError`), so it escapes `complete()`. `Repl._propose` catches only `BackendError` (`src/nl_shell/repl.py:156`), so the first natural-language line ends the session with a traceback. The `threading.Timer` thread also dies with the same error (`teacher_client.py:202`). I reproduced this: `TeacherClient(Endpoint("unix", "/nonexistent/model.sock"), timeout_s=1e10).complete([...])` → `UNCAUGHT OverflowError`, and the same on an `http://127.0.0.1:1` endpoint. This breaks the brief's "nothing raises" and "the REPL keeps running" (Scope (4), criterion (d)). `test_model_timeout_from_config` (`tests/test_teacher_client.py:413`) only tries `nan`/`inf`/`0`/`-1`/bool/string/array, so it never catches this. Fix: put an upper bound on `timeout_s` in `config.load` (raise `ConfigError`), or turn `OverflowError` into a `TeacherError`, and add a case such as `1e10` to the test.

- NEEDS-HUMAN [human] — The patch brings in all of #143 as new files instead of building on a folded #143 base. `patch.diff` creates `src/nl_shell/backend.py`, `proposal.py`, `render.py`, `prompts.py`, `targets/ubuntu-26.04/prompts/prompts.yaml` and `tests/test_backend.py` (`new file mode`, patch.diff:57, 411, 638, 795, 1435, 1474), and rewrites `repl.py`/`input_modes.py` on top of a main without #143. The brief says #143 must already be in the wave base, and that this bundle must not edit `render.py`, `proposal.py` or `tests/test_backend.py` (brief.md:26-29). The C4 red leg shows it: its first failures are `ModuleNotFoundError: No module named 'nl_shell.backend'` in `tests/test_backend.py:133` (gate-logs/C4-verify.log). So the red base was main, not main+#143. In substance the red still holds for #77's own tests (each one imports `nl_shell.teacher_client` inside the function, and that module is new). But "131 of 224 failed" mixes #143's tests with #77's, so the number doesn't show that #77 alone flips anything. A human needs to confirm whether #143 was accepted and folded, and whether these files are byte-for-byte #143's accepted patch. If they aren't, this bundle ships its own copy of #143 (including `BackendError` and the `not_running_at` field in `backend.py:24-37`), which the brief ruled out.

## Lower-severity notes (no rebuild needed for these alone)

- The "total deadline covers connect" claim doesn't fully hold on the TCP path. `http.client.HTTPConnection.connect` uses `socket.create_connection`, which gives *each* resolved address the full `timeout_s`. The `_cut` timer (`teacher_client.py:310-319`) does nothing while `conn.sock` is still `None` during connect. A `--dev-teacher http://host` whose A and AAAA records are both blackholed waits about 2 × `timeout_s`. DNS lookup isn't bounded at all. This only affects the dev flag path. The default Unix socket path is fine.
- `teacher_client.py:239` appends `/v1/chat/completions` to the URL path. A URL written the OpenAI-SDK way, `http://localhost:8080/v1`, becomes `POST /v1/v1/chat/completions` → 404 → "could not be used: HTTP status 404". Nothing in the brief or the ADRs fixes the URL form, but the `--dev-teacher` help text (`cli.py`, diff hunk at patch.diff:142-151) doesn't say "base URL without /v1" either. Worth fixing in the same rebuild: strip a trailing `/v1`, or document it.

## Attempted and could not refute

- **Slow-drip test checks the right thing.** `tests/test_teacher_client.py:381-400` sends one byte every 0.2 s against a 0.5 s timeout. A per-read socket timeout would never fire there, so only the monotonic check in `_read`/`_tick` (`teacher_client.py:322-355`) or the `_cut` timer can make it pass. It tells the two designs apart.
- **(f) runs the production path.** `test_default_path_opens_no_tcp` (`tests/test_teacher_client.py:645-670`) patches `socket.socket.connect` and `socket.create_connection` (which `http.client` looks up at call time). It runs `cli.main` with a live TCP fake at `teacher_url`, and asserts exactly one `AF_UNIX` connect to the default socket and no requests at the TCP fake. Not a copy of production code.
- **Escaping.** Every error built from server or exception text goes through `render.escape` (`teacher_client.py:291, 296, 300, 302, 306`). The REPL also escapes every reply (`repl.py`, `print(render.escape(...))`). The OSC 52 status-line test drives a real raw status line through `http.client`.
- **Timeout race.** The deadline is taken before the timer starts (`teacher_client.py:200-204`), so when `_cut` shuts the socket, `time.monotonic() >= deadline` is already true. The EOF this causes turns into the "no complete answer within" reason, not a misleading parse error. A late timer after `close()` hits a socket whose fd is -1 and the `OSError` is swallowed. No fd-reuse hazard.
- **Endpoint rules.** I tried `--dev-teacher ""`, `http://user@host`, `http://[::1]`, `http://127.9.9.9`, `http://LOCALHOST` and a query string. All are handled as the brief says (`teacher_client.py:119-148`). Without the flag the config URL is never parsed or used.
