# Adversarial review — issue_140 (persistent-bash-session-core), round 4

Re-ran attacks against the patched target with real bash 5.3.9 and ptyprocess. pytest is not
installed here, so I could not re-run the suite. I drove `Session` directly with small scripts
in my scratch dir instead. The C4 log shows 95/95 red (every red is `ModuleNotFoundError:
nl_shell.session`, as expected for new code, gate-logs/C4-verify.log:47) and 95 passed green
(:13). T3 is 332 passed. The evidence holds up. The two findings below are holes in the fix.

- NEEDS-HUMAN [impl] — **The per-function trace flag (`declare -ft`) gets around the round-3 functrace fix and breaks I2.** `src/nl_shell/session.py:88-89` and spec `docs/design/specs/pty-protocol/v1.md:138` say "each hook first turns functrace off, so no DEBUG trap runs inside it after `H` is taken". That is false. `set +T` (session.py:118, :136) clears only the global option. `declare -ft __nls_snap` sets the function's own trace flag, which `set +T` does not clear. `declare -f` in H (session.py:154) does not print that flag, and neither does `__nls_f`, which looks only at `$-`. Repro on a fresh session:
  `declare -ft __nls_snap; trap 'case $BASH_COMMAND in *"set +T"*) [[ -n ${zz+x} ]] && PS0=$zz;; "__nls_enc V"*) zz=$PS0; PS0=;; esac' DEBUG`
  then `true` → `ran=False`, healthy. Then `touch MARK; echo printed; (exit 7)` → `ran=False st=7 out=''`, healthy, and **MARK exists**. Every later command is also reported "nothing ran", and the session never degrades. The trap clears PS0 after H is taken and puts it back before the next H, so H never differs. This is the round-3 item 2 attack again, just one step around the fix. `tests/test_session.py:640-668` (`_FUNCTRACE_ATTACKS`, the `debug-trap-functrace` row) tests only global `set -T`, so it stays green. Fix: add `\builtin declare -F -t` to the H block (it prints `declare -ft __nls_snap` when the flag is set; I checked this on 5.3.9) or `declare -pF` of each hook. Add a `declare -ft __nls_snap` / `declare -ft __nls_done` row to `_TABLE_A_ROW_1` and `_FUNCTRACE_ATTACKS`. If the flag is left out of H, the docs must say I2 does not hold against it.

- NEEDS-HUMAN [impl] — **`read -u 2 x` (a read of the terminal on fd 2) dodges the prompt rule, so `run()` without a timeout hangs forever.** `src/nl_shell/session.py:701-702` counts `read` as a terminal read only when `arg0 == 0`. fd 2 is the same PTY. Measured: `read x </dev/tty` and `read x <&2` degrade after 1.1 s (the round-3 fix works), but `read -u 2 x` hit my 8 s caller timeout with no degrade, so with `timeout=None` it never returns. This is the same class as round-3 item 3, which was fixed only for fd 0. Fix: for `read`, accept any fd whose `/proc/<pid>/fd/<n>` is the PTY slave or `/dev/tty`, not only fd 0. Then add `read -u 2 x` to the `test_read_with_no_input_degrades` parametrize (`tests/test_session.py:746`).

- Not a finding: I checked the "hidden" functrace test row (`tests/test_session.py:658-660`). Its trap runs `set +T` when the top-level `__nls_snap` call fires the trap, so functrace is already off inside `__nls_snap` and the `"PS1="*` branch can never fire inside the hook. That row cannot go red for the reason it claims to test. It is weak but harmless, so it is worth replacing with the `declare -ft` row above.

- Attempted and could not break: alias shadowing with `\builtin` in PS0, `__nls_done` and the `$( … )` bodies (aliases on `printf` via `builtin=" "` cannot reach in, because the first word is backslash-quoted); a global `set -T` plus DEBUG trap (caught by `__nls_f` in H); `read x </dev/tty` and `read x <&2` (both degrade in 1.1 s). The gate evidence (C4/T3) is consistent with the patch.

# Advisory security review — persistent-bash-session-core (round 4)

Attacker-reachable inputs this diff touches: **session state** (threat model "Where untrusted input enters" item 4: functions, traps, hooks set by `~/.bashrc`, raw `\cmd` input or a confirmed `source`) and **command output** (item 1) reaching the PTY parser and the output cut. Control records on fd 3 written by a command are out of scope (settled decision 1, #135; threat model "Known gaps": child processes inherit fd 3).

## Findings

- NEEDS-HUMAN [impl] — **High** (threat model: "a session change (alias, function, hook) goes undetected"; it breaks the brief's invariant I2). `src/nl_shell/session.py:89-90`, `:133-134`, `:170`, `:173`; spec `docs/design/specs/pty-protocol/v1.md:138`. **Input:** a confirmed command or a sourced script (session state, item 4) sets the per-function **trace attribute** (`declare -ft`) on a hook function and installs a DEBUG trap. **What goes wrong:** the round-3 fix only turns off the shell-wide `functrace` option (`set +T`) and records it in `__nls_f`. The trace attribute on a single function does the same job (DEBUG and RETURN traps then run inside that function), but `set +T` doesn't clear it and `declare -f` doesn't print it, so `H` can't see it. On this host, `bash -c 'f(){ :; }; declare -ft f; declare -f f'` prints the body with no attribute. The trap runs inside `__nls_snap` after `H` is sampled, empties `PS0` at the `PS1=` line, and puts `PS0` back from the top-level DEBUG trap before the user's first simple command. Result: no `S` record, `D n+1` arrives, the snapshot's `H` matches the baseline, and every later command is reported `ran=False` with its output dropped, **while the session stays healthy** and the commands really run. **Reproducer** (run against the patched target with real bash 5.3.9 and the system `ptyprocess`, using `Session.run(cmd, timeout=5)`):
  1. `declare -ft __nls_snap; trap 'if [[ ${FUNCNAME[0]-} == __nls_snap && $BASH_COMMAND == "PS1="* ]]; then __x=$PS0; PS0=; elif [[ -z ${FUNCNAME[0]-} && -n ${__x-} ]]; then PS0=$__x; __x=; fi' DEBUG` → ran=True, healthy
  2. `true` → ran=False, healthy
  3. `touch MARK; echo printed; (exit 7)` → **ran=False, status=7, output `b''`, degraded=False; `MARK` exists**
  4. `echo hello` → ran=False, output `b''`, healthy

  `__nls_enc` is a second target, since `__nls_snap` calls it for every record after `H` (`declare -ft __nls_enc`). The rcfile comment at `session.py:89-90` and spec `:138` ("each hook first turns functrace off, so no DEBUG trap runs inside it after H is taken") are false for this case. The Known-gaps bullet (`.oss-scanner/threat_model.md:170-176`) names only `extdebug` + DEBUG trap as unclaimed. **Test gap:** `_FUNCTRACE_ATTACKS` (`tests/test_session.py:653`) covers only `set -T`. **Fix for the builder:** clear the trace attribute on all four hook functions (`__nls_done`, `__nls_snap`, `__nls_enc`, `__nls_ret`) and record it in `H` so the change degrades at its own snapshot, then add the reproducer above, plus an `__nls_enc` variant, to `_FUNCTRACE_ATTACKS`. If it can't be held, the round-3 sign-off ruling applies: the rcfile comment, spec §1.3 and the threat-model bullet must say I2 is not claimed against the function trace attribute, the same way they already do for `extdebug`.

## Checked, no finding

- **Alias shadowing inside the hooks (round-3 item 1).** `PS0`, `PROMPT_COMMAND` and every `$( … )` body in `__nls_snap` use `\builtin`. `__nls_snap` turns `expand_aliases` off before its command substitutions and turns it back on only if it was on (`session.py:134-171`). Both round-3 reproducers are in `tests/test_session.py:678`. The old claim that an alias change changes `H` is gone from the rcfile comment.
- **`read x </dev/tty` (round-3 item 3).** `_stdin_is_terminal` (`session.py:686-707`) accepts device (5,0), and fd 0 is read through `proc_root`. If that can't be read, the session fails closed with `_ProcUnreadable`.
- **Paste bytes (§5).** `check_command` (`pty_protocol.py`) refuses `ESC [201~` and every C0 byte except TAB and LF before any write. `run()` writes exactly `PASTE_START + data + PASTE_END + CR` (`session.py:507`). Degraded mode raises before writing (`:497-505`).
- **Printed text forging records or the output cut.** Status comes only from the fd-3 parser. The end-of-output marker carries a random 128-bit token per start (`session.py:351-353`), so printed text can't end the output early. The parser bounds record length, digit count and escapes (`pty_protocol.py`), and a malformed record degrades the session.
- **Function shadowing of `builtin`/`command`/`eval`/`return`, other traps, `bind`, `set +o emacs`/`vi`, Table B.** These are listed in the threat model's interim Known-gaps bullet (#141), so they are not re-raised.
- **Gates.** C4 is red→green with 95 of 95 tests (`gate-logs/C4-verify.log`) and T3 is green with 332 passed (`gate-logs/T3-suite.log`). Both are consistent with the finding above: no test exercises the trace attribute.
