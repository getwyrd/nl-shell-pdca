# Security review — issue_140 (persistent-bash-session-core)

**Attacker-reachable inputs this diff touches:** session state (threat model "Where untrusted input enters" item 4: aliases, functions, hooks set by `~/.bashrc`, raw `\cmd` or a confirmed `source` of a repository script), and command output (item 1) on the PTY stream that `_Output` cuts. Rated on `.oss-scanner/threat_model.md`'s scale. Toolchain: bash 5.3.9 and `ptyprocess` are present; pytest is not. I ran the reproducer below directly against `target/src` with `python3 -I`.

## Findings

- NEEDS-HUMAN [impl] — **High** (a session change, here an alias, goes undetected; it also breaks the brief's invariant I2) — `src/nl_shell/session.py:120` (PS0), `:145-175` (every `$( … )` in `__nls_snap`), and the claim at `:102-104` (repeated in `docs/design/specs/pty-protocol/v1.md:129-131`). **Input:** aliases defined by a confirmed command or a confirmed `source` of a repository script (item 4). **What goes wrong:** bash parses each `$( … )` again when it runs, with the user's aliases. `declare -f` still prints the original text, so `H` does **not** change. That makes the comment and the spec ("an alias that changes one changes `H`") false. An alias named `builtin` whose value ends in a space makes the next word go through alias lookup too, so the attacker can replace `printf`, `alias`, `compgen`, `declare` and so on inside the hooks. Both cases below ran on a real session and stayed **healthy**:
  - *S suppressed (I2 broken):* `__p(){ [[ $1 == S* ]] || builtin printf "$@"; }; alias builtin=" " printf=__p`, then `touch MARK; echo printed; (exit 7)` → `ran False`, `status 7`, output `''`, `degraded False`, and `MARK` exists. Every later command (`echo ok`) is also reported as not run.
  - *Aliases hidden from `L`:* `alias ls='touch PWNED' builtin=' ' alias=':'`, then `ls` → `L` is `''`, session healthy, `PWNED` exists. The same trick works on `F` (`compgen`) and `B`/`X`. Once the gate (#12) reads `L`/`F`, this lets a "read-only" `ls` run something else without a confirm (Critical then). Today nothing calls the session (#78), so I rate it High.

  This is not the Known-gaps item about *functions* named `builtin`/`command`/`eval`/`return`. Aliases are a different mechanism, and the patch's docs claim aliases are detected. **Fix:** write `\builtin` (backslash-quoted, so it is never alias-expanded), as `PROMPT_COMMAND` at `session.py:181` already does, everywhere inside `PS0` and the `$( … )` bodies of `__nls_snap`. I checked that `x=$(\builtin printf %s hi)` still gives `hi` under `alias builtin=' ' printf='echo X'`. Then add the two cases above to `tests/test_session.py`: each must end DEGRADED or report the command as ran with its real output, and `L` must still list `ls`. None of the current tests covers alias shadowing inside the hooks (the alias tests at `tests/test_session.py:220`, `:728`, `:767`, `:782` cover only the normal case). If the fix is not made, correct `session.py:102-104` and spec `:129-131`, and widen the Known-gaps bullet (`.oss-scanner/threat_model.md`, "session core is partial") to name alias shadowing as #141 scope.

## Checked, no finding

- **Forging status/completion from output:** status and completion come only from fd-3 records (`pty_protocol.py:214-258`). Repro A above does not forge `D`, because `D` is printed from the function body (`session.py:134`), which is not parsed again. Writes to fd 3 by a command are out of scope (#135).
- **Output boundary:** the end marker uses a random 128-bit token for each start (`session.py:412-415`). `declare -f` shows it as the literal text `\033`, not the escape bytes, so printed text from an untrusted file cannot cut the output early. The output starts after readline's `ESC [?2004l`, which comes before the command runs. The pasted command cannot contain ESC (`pty_protocol.py:139-148`). Output (`MAX_OUTPUT`), records (`MAX_RECORD`) and the leftover bytes kept between reads (`_pending`) all have size limits. A PATH over 1 MiB degrades the session (it fails closed) rather than growing memory.
- **Command refusal (§5.2):** `check_command` rejects `ESC [201~`, ESC and every C0 control except TAB/LF before anything is written (`session.py:503`). Bytes from 0x80 to 0x9F arrive as UTF-8 inside the bracketed paste and are not run as key bindings.
- **Prompt rule:** it now also requires bash's fd 0 to be this PTY (`session.py:675-691`), fixing the iteration-1 redirect case. An unreadable `/proc` file fails closed (`:561-565`, `:623-625`).
- **TERM:** it is in `H` (`session.py:146`), and a `dumb` TERM in the environment is replaced at start (`:350-352`). Turning bracketed paste off with `bind` and the `builtin`-function shadowing are listed in Known gaps (#141), so I don't raise them again.
- **Rcfile/token exposure:** `mkdtemp` creates the rcfile directory with mode 0700, and it is removed once bash has read it (`session.py:452`). `on_record` exposes `H`/`V`/`P`, but nothing logs it yet.
- **Baseline poisoning from `~/.bashrc`** (for example `readonly PS0`): writing `~/.bashrc` takes code running as the user, which the threat model puts out of scope. Not filed.
