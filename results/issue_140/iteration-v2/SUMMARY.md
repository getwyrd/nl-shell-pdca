# Adversarial review — issue_140 (persistent-bash-session-core)

I tried to break the fix by running `nl_shell.session.Session` directly against the host's bash 5.3.9, with `ptyprocess` and `python3 -I`. pytest is not installed in this sandbox, so I could not re-run the suite. Instead I drove the production class itself, not a copy. Scripts and output are in `scratch/` (`probe.py`, `probe2.py`).

## Evidence (C4 red→green)

- `gate-logs/C4-verify.log`: the red leg is 86/86 `ModuleNotFoundError: No module named 'nl_shell.session'`. That is the right shape for new code, and it shows each test imports the module inside the test. It does **not** show that any single test is sharp, because no test ever ran against a partly wrong implementation. I read the key tests for tautologies and found none:
  - the I2 test (`tests/test_session.py:660-680`) asserts `ran/status/text == (True, 7, "printed\n")` and that the marker file exists on its healthy path;
  - `tests/test_session.py:945-957` pins the exact output bytes;
  - the prompt-rule tests check the reason text and that nothing was written to the PTY.
  
  Not a refutation.

## Attacks that failed (the fix held)

- **An alias that suppresses `S` (I2).** `PS0` re-parses `$(builtin printf "S …")` with the user's aliases at prompt time, and the comment at `src/nl_shell/session.py:113` ("defined with alias expansion off") does not cover that. But `alias builtin=:` and `alias builtin='builtin '; alias printf=:` both degrade at **their own** snapshot. The `H` command substitution at `src/nl_shell/session.py:153-169` is re-parsed the same way, so its text changes. The next command never ran (MARK absent). It fails closed. To hide `S` selectively you would need a deliberate wrapper function, which is I1 tampering and belongs to child-2.
- **`set -u`, `set -e`, `set -o posix`.** All stay healthy with correct status and output.
- **Multi-line input.** `echo a\necho b; (exit 4)` gives one S/D pair, status 4. `echo a\nfi` reports ran, status 2, both outputs.
- **Leading CR in output.** `printf '\rX'` and `printf '\r\rY'` come back exact. The single-CR skip at `src/nl_shell/session.py:326-330` does not eat command output.
- **Turning off line editing.** `set +o emacs +o vi` and `bind 'set enable-bracketed-paste off'`: the next command degrades with "output could not be delimited" (`src/nl_shell/session.py:639-643`). It is never reported healthy. Note that with editing off, the pasted bytes still reach bash and run as a garbled command (status 127) before the degrade. That is readline state, Table A row 6, which belongs to child-2.
- **`unset PROMPT_COMMAND`.** Degrades by the prompt rule in 1.0 s.

## Findings

- NEEDS-HUMAN [human] — `src/nl_shell/session.py:283-338` (`_Output`): **bash's own job notices are reported as the next command's output.** Reproduced: run `sleep 0.2 &`, wait, then `sleep 0.6; echo x`. The result's `output` is `b'[1]+  Done                       sleep 0.2\r\nx\r\n'`, with the session healthy. With `set -b` it is `...sleep 0.2\r\r\nx\r\n`. Bash prints the notice after readline's `ESC [?2004l` and before the command runs, so it falls inside the S..D window by design. The brief's (q) says "return exactly the command's own output", but tests only the user `PROMPT_COMMAND` case. The brief forbids parsing PTY text, so the builder can't fix this by iterating. A human should decide whether job notices count as "PTY output between S and D" (and say so in the spec) or need another cut point.
- NEEDS-HUMAN [human] — `src/nl_shell/session.py:709-724` (prompt rule): **healthy commands that end by themselves get degraded.** `read -t 2 x; echo st=$?` degrades after 1.0 s with "no done record after the shell returned to a prompt" and `result=None`, even though it would finish with status 142. The same goes for any timed or single-key read from the terminal (`read -n1 -t …`, a `select` menu). This sits in the same class as the accepted `read x` limit (#136, brief (k)), so it is not a defect against this brief. But the spec, threat model and #136 should name timed reads explicitly, so nobody later reads "only `read x` with no input" as the whole limit.
- `src/nl_shell/session.py:113`: the comment says the hooks are "defined with alias expansion off". In fact every `$( … )` inside `PS0`, `__nls_snap` and `__nls_enc`'s callers is re-parsed at run time with the user's aliases (shown above). It fails closed today only because `H` is itself built inside such a substitution. A future edit that moves `H` out of a command substitution would quietly open an I2 hole. This is a comment-accuracy nit; it does not refute the fix.
- Out of scope, noted only: with `stty -isig`, `interrupt()` returns True, writes `^C`, and `sleep 5` runs the full 5 s. With `stty -echo`, `echo hi` returns `b'\r\nhi\r\n'`, an extra blank line. Both are termios state, which is Table B (child-2). I am not filing them against this diff.

## Verdict on check-gates.json

I see no unwarranted claim. The C4 "red without the fix (86 of 86 failed)" is literally true but weak as evidence (see above). T4 is honestly marked `deferred`. I attempted to refute I2 (aliases, shell options), output delimiting (CR, multi-line, line editing off), sequencing (multi-line, syntax errors) and the prompt rule (unset hooks, timed reads), and could not break the brief's stated invariants. The two NEEDS-HUMAN items are limits of the chosen design, not builder bugs.

# Security review (advisory) — issue_140, persistent-bash-session-core

Attacker-reachable inputs this diff touches: **command output** (threat model input 1, the PTY stream `_Output` cuts), **session state set by confirmed code** (input 4: functions, hooks, `PROMPT_COMMAND`, `~/.bashrc`), and **the model's proposal as the command bytes pasted** (input 5, `check_command`). Nothing calls the session yet (#78), so none of this is reachable from a running nl-shell today; findings are rated against the design the code implements.

## Findings

- NEEDS-HUMAN [human] — **High** (threat model: "a session change (alias, function, hook) goes undetected by the gate"; it also forges exit codes, which "What must hold" says the control channel guarantees). `src/nl_shell/session.py:128-189` (rcfile hooks) and `src/nl_shell/pty_protocol.py:324` (the H check). Input: one confirmed command, e.g. from a `source scripts/env.sh` a README asked for (input 4). Every hook write to fd 3 and every snapshot query goes through `builtin printf` / `builtin declare` / `builtin compgen`. The rcfile comment (`session.py:108-110`) says that stops `PATH`/`hash` swaps. But bash lets a **shell function named `builtin`** override the builtin, and H does not cover it. Once that function is defined, it produces every control record. It can hide itself from `F` at the very snapshot of the command that defined it, report any `$?`, and keep `H` byte-identical. The session stays healthy. Reproduced on this host (bash 5.3.9, the patched `Session`): run
  `builtin(){ if [[ $1 == printf && $2 == 'D %s %s%s\n' ]]; then command builtin printf "$2" "$3" 0 ""; elif [[ $1 == compgen ]]; then local f; for f in $(command builtin compgen -A function); do [[ $f == builtin ]] || command builtin echo "$f"; done; else command builtin "$@"; fi; }`
  and the result is `ran=True status=0 degraded=False`, with `builtin` absent from `F`. Then `touch MARK_X; (exit 7)` gives `ran=True status=0 pipestatus=() degraded=False`, and `MARK_X` was created. A function named `command`, `return` (used by `__nls_ret`) or `eval` works the same way. The brief puts I1 against tampering in child-2, but the interim Known-gaps bullet this patch adds (`.oss-scanner/threat_model.md:318-325`) says hook changes **are** detected at the snapshot. It lists traps, xtrace, disabled builtins and the rest as the open gaps, and does not mention shadowing the builtins the hooks call. So the docs say more than the code does. A real fix is not obvious: anything the hooks run in bash can itself be shadowed, and H is gathered through the same calls. A human needs to decide one of two things. (a) Widen the interim Known-gaps bullet (and spec §4.2 / the rcfile comment) to say that confirmed code shadowing `builtin`/`command`/`eval`/`return` with a function is not yet detected, and add this case to #141's scope. (b) Hold this child until the hooks have a defense, for example an out-of-shell check, or posix-mode lookup for special builtins plus refusing a function named `builtin` at the gate.

- **Low** (no tag, informational). `src/nl_shell/session.py:139,168`. Input: command output (input 1). The per-start end-marker token is printed in plain text by `declare -f __nls_done` (or `type __nls_done`), which a read-only proposal may run. If that output reaches someone who can then plant the real bytes `ESC ]7700;<token> BEL` in a later command's output (a file being `cat`ed), the capture ends early (`_Output.feed`, `session.py:331-335`). Everything after the marker is dropped from `output`, and the result still counts as cleanly delimited. A text-only attacker cannot see the token unless it is sent back out somehow, so this is Low. A token chosen per command, not per start, would remove the issue if it ever matters.

## Checked, no finding

- **Forged control records from output:** `printf 'D 99 0 0\n'` and OSC 133 text go to the PTY, not fd 3. Status and completion come only from `ProtocolTracker` (`pty_protocol.py:216-288`). Malformed, oversized (`MAX_RECORD`, `pty_protocol.py:30,224`), CR-bearing and out-of-order records all degrade. Numeric fields are capped at 18 digits, so `int()` can't raise on huge input.
- **What is confirmed vs. what runs:** `check_command` (`pty_protocol.py:159-173`) refuses `ESC [201~`, ESC and every C0 byte except TAB/LF before anything is written. `run` writes exactly `PASTE_START + data + PASTE_END + CR` (`session.py:552`). The rcfile sets `set +H` after `~/.bashrc`. `test_vector12_forbidden_bytes_are_refused_unsent` (`tests/test_session.py:308-331`) covers the attacker case: it spies on PTY writes, checks that nothing was written and no file was touched, and checks the sequence number did not move. DEL and C1 bytes are allowed, as the spec says; inside a bracketed paste readline inserts them literally.
- **Degraded mode is sticky and stops writes:** `run` checks `_raise_if_degraded` three times before `_write_all`. `interrupt` writes `\x03` only while in the RUNNING phase.
- **Resource use:** captured output is capped (`MAX_OUTPUT`, tail kept, truncated flag set). The control buffer is capped. The prompt rule fails closed when `/proc/<pid>/syscall` or `fd/0` cannot be read, and since iteration 1 it checks that fd 0 is the session PTY.
- **Rcfile handling:** it lives in a `mkdtemp` (0700) directory and is removed once the baseline arrives. History is off (`unset HISTFILE`), so pasted commands are not written to `~/.bash_history` by this session.
- Gate evidence: C4 passes (86/86 red without the fix, green with it) and T3 passes. Neither gate covers the finding above, because no test shadows `builtin`.
