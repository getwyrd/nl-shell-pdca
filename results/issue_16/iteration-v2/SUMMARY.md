A probe of `proposal.parse('{"kind":"command","command":"ls<X> x","risk":"read-only"}')` returned `CommandProposal` for X = U+200B (zero-width space), U+200D, U+2060, U+FEFF, U+00AD (soft hyphen), U+2028/U+2029 (line/paragraph separators) and U+E0041 (a tag character). - NEEDS-HUMAN [human] — `src/nl_shell/render.py:48`: the escaping is not one-to-one. `escape_hidden("a\x1bb") == escape_hidden("a\\x1bb")` is `True`, so in `:context` a request holding a real ESC looks the same as one where the user typed the four characters `\x1b`. The brief asks for this form ("ordinary text is byte-identical"), but it weakens the claim that `:context` shows "the exact model input". The fix would be to also escape a literal backslash; a human should decide whether that matters.
- `src/nl_shell/prompts.py:178` (low, the user's own file, no tag): `json.dumps` runs on an example `response` before its keys are checked. So a YAML alias "billion laughs" (a few lines whose aliases expand to a huge structure) in a junk key of `response` is fully expanded before it is rejected. Six levels of ten (a 538-byte file) took 0.55 s. Each extra level costs about 10x more time and memory, so at depth 8–9 start-up hangs. Only the person who controls the config file can do this, so it hurts no one else. A cheap fix: check `set(response)` against `SCHEMA["properties"]` and that every value is a `str` before calling `json.dumps`.
- `src/nl_shell/prompts.py:87-103` (low, no tag): the duplicate-key check runs after `flatten_mapping`, so a valid YAML merge override (`- <<: *e` then `request: r2`) is refused with "duplicate key 'request'". YAML 1.1 says explicit keys override merged ones. It fails closed with the file path in the message, so the only cost is convenience. Either document that `<<` overrides are not supported or skip merged keys in the duplicate check.

# Security review — issue 16 (prompts YAML, `:context`, recording stub)

Attacker-reachable inputs this diff touches: **the model's response (threat model item 5)**. It enters at `proposal.parse` (`src/nl_shell/proposal.py:155`) and its result is printed at `src/nl_shell/repl.py:115` / `repl.py:149`. The other new inputs are trusted under the threat model: the request text (typed by the user), `prompts.yaml` (the user's own config file, or the target's file in the repo), and `:context` (built only from those two today, since the state block slot stays empty until #11).

## What I checked (no finding)

- **Last round's crash vectors are fixed and tested.** A 5000-digit integer is rejected (`proposal.py:118-121`). A lone surrogate in `command` is rejected through `is_hidden` (`render.py:189-200`), and `prompts.py:222-225` rejects it in prompts. Both are covered in `tests/test_backend.py:458,462`, with a strict UTF-8 `TextIOWrapper` at `:552`. A duplicate key, deep nesting (`[`×100000), a bare JSON string and a surrogate in a property name all come back as `Rejected` with no exception. I ran these against the patched tree.
- **Hidden characters in proposals.** C0 except LF/TAB, DEL, C1 and the bidi set are rejected before display (`proposal.py:144-146`). The U+202E and ESC vectors are tested (`tests/test_backend.py:517`, `:578`). `risk` and `reason` are enum-checked, so only fixed strings reach the screen. `Rejected.why`, which can hold model-chosen key text, is never printed (`repl.py:152-154`).
- **Rendering.** Every reply goes through `escape_hidden` (`repl.py:115`), including `:context` and `BackendError` text. The ESC and U+202E/U+0085 `:context` vectors are tested (`tests/test_backend.py:246-261`).
- **Prompt construction.** `_volatile` uses plain replacement, not `str.format` (`prompts.py:309-311`), so braces in the request can't pull in other fields.

A YAML alias bomb inside `examples[].response` could make `json.dumps` blow up at `prompts.py:245`. The file is trusted user config, though, so that would be a self-inflicted misconfiguration at most (Low) and is not filed.
- **Threat model.** `.oss-scanner/threat_model.md` "How to exercise it" is updated as the brief asked. The T2 gate passed.

- NEEDS-HUMAN [human] — **No rating today; would count as "what is shown differs from what runs" once #78 runs proposals.** `src/nl_shell/render.py:182-200`. Input: the model's `command` (item 5). No other finding. The patch's own tests cover the attacker-reachable cases for the vectors in the brief's set (malformed JSON, schema breaks, hidden characters, surrogates, large integers, and unsafe YAML tags), not only the friendly path.
