# Adversarial review — issue 16 (prompts-yaml-context-recording-stub)

Summary: I could not break the core fix. Both round-1 crash cases are closed: a JSON integer over 4300 digits is now caught at `src/nl_shell/proposal.py:118-121`, and a lone surrogate is rejected through `is_hidden` (`src/nl_shell/render.py:29-40`, used at `src/nl_shell/proposal.py:144`). The new tests check this on a real UTF-8 `TextIOWrapper`, not only on `StringIO`. The gate logs are consistent. C4 is red pre-fix with 90 failed and 18 errors. Most of those are the in-function import failures the brief expects, but some are real behaviour failures (for example `test_repl_without_a_backend_says_so` fails on an assertion). C4 is green post-fix, and T3 passes 325 tests. pytest is not installed in this sandbox, so I did not re-run the suite myself. I ran the probes below directly against `$PDCA_TARGET/src`.

Refutation attempts that failed (the code held): duplicate JSON keys, NaN/Infinity, a UTF-8 BOM, numbers or lists in enum fields, deep nesting, YAML tags (`!!binary`, timestamps, `!!python/*`), unhashable YAML keys, a directory where the user `prompts.yaml` should be, a backend error before `:context`, and `{`/`}` in the request (handled by plain replacement, not `str.format`).

Findings:

- NEEDS-HUMAN [human] — `src/nl_shell/render.py:22-40`: the hidden set is exactly what the brief pins, but other invisible characters still get through the parser and are shown unescaped. A probe of `proposal.parse('{"kind":"command","command":"ls<X> x","risk":"read-only"}')` returned `CommandProposal` for X = U+200B (zero-width space), U+200D, U+2060, U+FEFF, U+00AD (soft hyphen), U+2028/U+2029 (line/paragraph separators) and U+E0041 (a tag character). A zero-width space inside an argument (`rm -rf /tmp/a<ZWSP>b`) changes what would run, but it looks the same on screen. The threat-model must-hold says "bidi or control characters"; most of these are Unicode format characters (category Cf), and U+2028/U+2029 act as line breaks. Whether to widen the set (for example to all Cf/Zl/Zp characters) before #78 starts running commands is a scope call. The patch follows the brief as written, so this is not a builder slip.
- NEEDS-HUMAN [human] — `src/nl_shell/render.py:48`: the escaping is not one-to-one. `escape_hidden("a\x1bb") == escape_hidden("a\\x1bb")` is `True`, so in `:context` a request holding a real ESC looks the same as one where the user typed the four characters `\x1b`. The brief asks for this form ("ordinary text is byte-identical"), but it weakens the claim that `:context` shows "the exact model input". The fix would be to also escape a literal backslash; a human should decide whether that matters.
- `src/nl_shell/prompts.py:178` (low, the user's own file, no tag): `json.dumps` runs on an example `response` before its keys are checked. So a YAML alias "billion laughs" (a few lines whose aliases expand to a huge structure) in a junk key of `response` is fully expanded before it is rejected. Six levels of ten (a 538-byte file) took 0.55 s. Each extra level costs about 10x more time and memory, so at depth 8–9 start-up hangs. Only the person who controls the config file can do this, so it hurts no one else. A cheap fix: check `set(response)` against `SCHEMA["properties"]` and that every value is a `str` before calling `json.dumps`.
- `src/nl_shell/prompts.py:87-103` (low, no tag): the duplicate-key check runs after `flatten_mapping`, so a valid YAML merge override (`- <<: *e` then `request: r2`) is refused with "duplicate key 'request'". YAML 1.1 says explicit keys override merged ones. It fails closed with the file path in the message, so the only cost is convenience. Either document that `<<` overrides are not supported or skip merged keys in the duplicate check.
- No unwarranted claim found in `check-gates.json`. The C4 summary "red without the fix (90 of 183 failed)" is accurate. The red is mostly the import failures the brief allows, plus real reply-text failures on the `Repl` paths. T4 is `deferred` (the PR text is not written yet), so it is not a pass.
