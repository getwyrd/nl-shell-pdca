# Adversarial review — issue 16 (iteration 3)

I tried to break the evidence, the parser, the escaping and the framing. Most of it held up. I found two display holes and one unfiltered error path. None of them breaks the brief's criteria (a)–(f) as written. All of them sit inside the threat-model rule "rendering is filtered everywhere", which the iteration-2 sign-off made the updated requirement.

**Evidence.** `pytest` is not installed in my sandbox, so I could not re-run C4/T3. I judged the gates from `gate-logs/`. C4 shows green (227 passed) and red (116 of 209 failed). The `tests/test_backend.py` tests go red for the right reason: the in-function imports of `nl_shell.backend` / `nl_shell.prompts` fail, which shows up as fixture ERRORs. `context_form` (`tests/test_backend.py`, the `escape`/`context_form` helpers) rebuilds the text form inline and never calls `backend.context_text`, as the brief requires. Its `hidden()` is a hand copy of `render.is_hidden`, so the escape tests cannot catch a wrong *set*, only a wrong *encoding*. The named vectors (U+200B, U+FEFF, U+2028, U+E0041) cover that gap for the characters the sign-off listed. I ran the production modules directly with `python3 -I` (PyYAML 6.0.3 is present) for the probes below.

**Attempts that did not break it:** an integer over the digit limit and deep nesting (`src/nl_shell/proposal.py:205-210`, caught); a lone surrogate written to a real UTF-8 `TextIOWrapper` (`src/nl_shell/render.py:62`, rejected by the parser and escaped in `:context`); a leading BOM (rejected); NEL / VT / FF / CR / U+2028 as fake line breaks (all hidden, so `show_proposal` only splits on LF, `src/nl_shell/repl.py:77`); a fake header on a later LF line (prefixed with `  | `); duplicate JSON keys; YAML `!!python` tags, sequence keys and duplicate keys (`src/nl_shell/prompts.py:87-103`); braces in the request (`prompts.py:242-244` uses plain replacement); double escaping of `:context` (the second pass at `repl.py:133` finds nothing left to escape, and backslashes are only doubled once).

- NEEDS-HUMAN [human] — `src/nl_shell/render.py:50-64`: invisible characters outside general category Cf still get through the parser and are printed raw. The module's own definition (`render.py:4-5`, "or not show up at all") says they should not. I ran these and each was **accepted** as a `CommandProposal` and printed unescaped to a UTF-8 stream: `{"kind":"command","command":"ls ️ x","risk":"read-only"}` (U+FE0F variation selector, category Mn), `"ls ㅤx"` (U+3164 Hangul filler, Lo, renders as blank), and `"ls 󠄀"` = U+E0100 (variation selector supplement, Mn, outside the tag block `render.py:45`). U+115F, U+1160, U+FFA0 and U+2800 behave the same way. The sign-off listed only Cf, U+2028/9 and the tag block, so the build matches the letter of that list. Whether the "hidden" set should also cover Mn variation selectors and the known blank-rendering letters is a scope call for the human. If yes, it is a small change to `is_hidden` plus vectors.
- NEEDS-HUMAN [human] — `src/nl_shell/repl.py:71-80`: framing each line with `  | ` only frames *logical* lines. The terminal wraps long lines, so a command can still fake a header on its own *visual* row. Failing case (run): `command = "rm -rf ~/" + " "*70 + "Proposed command (risk: read-only, 1 line):"` is accepted. It prints as one logical line (`1 line`), but on an 80-column terminal the fake header wraps onto a new row with no `  | ` prefix, directly above the real `Not run:` line. The 2000-code-point limit leaves plenty of room to pad to any common width. The sign-off's vector (a fake header on a *later LF line*) is covered. This one is not, and line-prefix framing can't cover it without knowing the terminal width (or collapsing / marking long whitespace runs). Fixing it is a design decision about the renderer, and #74 owns the full confirm UI.
- NEEDS-HUMAN [impl] — `src/nl_shell/prompts.py:126-127` with the new `prompts.PromptsError` branch in `src/nl_shell/cli.py` (`print(f"nl-shell: {exc}", file=sys.stderr)`): the start-up error for a malformed `prompts.yaml` includes PyYAML's snippet of the offending line **unescaped**. Failing case (run): a user `prompts.yaml` holding `system: ok <U+202E>  here: [` gives a `PromptsError` whose text contains the raw U+202E (`... line 1, column 19: system: ok ‮ here: [ ^`, where `‮` is the real character). That goes straight to the terminal on stderr. PyYAML's reader rejects C0/C1 itself, but it allows bidi controls, Cf and the other characters above. The file path itself (from `$XDG_CONFIG_HOME`) is also printed raw. The person who wrote the file is the user, so the risk is low. Still, it breaks "rendering is filtered everywhere", and the fix is one line: `escape_hidden(str(exc))` in that `print`, plus a test using the U+202E vector.
- On the verdict, I disagree with one claim. The gate summary "C4 PASS — red without the fix (116 of 209 failed)" overstates how much of the red comes from this bundle's tests. Many of the red failures are in `tests/test_repl.py`, `tests/test_targets.py` and `tests/test_input_modes.py`, which fail only because the patch rewrote their pinned reply literals. That is valid red (the literals change with the fix), but the number says little about how strong `tests/test_backend.py` is on its own. I judged that file directly instead (above). Not a refutation, so not tagged.

Bottom line: I tried to refute the parser's strictness, the surrogate and big-integer fixes from iteration 1, and the backslash one-to-one fix and Cf/separator/tag widening from iteration 2, and could not. What's left is the three bullets above. Two are scope calls for the human; one is a small implementation fix. Because `pytest` is missing here, my reading of the red→green proof rests on the frozen gate logs, not a re-run.
