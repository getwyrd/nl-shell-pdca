## Motivation

Prompt transparency is a design goal (`docs/plan.md`: "`:context` shows the exact model
input"). Every later safety test that involves a model — the sudo password never reaching
a prompt (#13, #75), the gate on proposed commands (#78), the reader (#61) — needs a
backend that returns fixed answers and shows what it was sent.

## Design

- Model input: an ordered list of chat messages (system, examples, user), because the
  teacher speaks the OpenAI chat API (#77). The backend gets the list. `:context` prints
  its text form, which is fixed and documented: for each message, a line `--- <role> ---`
  followed by the message content, messages separated by one `\n`, with hidden characters
  escaped as in Scope (5). Tests rebuild this form themselves, so the check is not
  circular.
- Parser output: a small typed value (`command` + `risk`, or `clarify` / `refuse` +
  `reason`) or a rejection with a reason for the log; nothing in between.
- The stub is plain Python in `src/` (so #13/#78 tests can use it), not a test fixture.

## Alternatives considered

- Free-text proposals parsed by regex: rejected by ADR-0018.
- Prompts in TOML: ADR-0020 picks YAML for multi-line text.

## Impact & compatibility

New runtime dependency `PyYAML`. Natural-language input now produces "no model backend
configured" instead of "arrives in M0.8" in the interactive REPL until #77 lands.

## Open questions

- A malformed user `prompts.yaml` refuses start-up (consistent with #92's handling of a
  malformed `target.toml`). The alternative is to warn and use the defaults.
