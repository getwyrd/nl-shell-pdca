### Advisory — adversary

# Adversarial review: issue #16 (prompts YAML, `:context`, recording stub, proposal/v1 parser)

I tried to break the red→green evidence, the parser, the prompts loader and the REPL wiring. The evidence holds up. The parser does not: two model responses crash the REPL instead of being rejected. I reproduced both against the patched source in `$PDCA_TARGET`.

## Findings

- NEEDS-HUMAN [impl] — `src/nl_shell/proposal.py:111-118`: `parse` lets a `ValueError` escape. Python's `json.loads` raises a plain `ValueError` (not `JSONDecodeError`) for an integer longer than 4300 digits. Only `JSONDecodeError` and `RecursionError` are caught. Failing case: the stub response `{"kind": 1` + `"0"*5000` + `}` makes `proposal.parse` raise `ValueError: Exceeds the limit (4300 digits) for integer string conversion`. Through `Repl(..., backend=RecordingStub([raw]), prompts=...).run()` the REPL crashes with a traceback. It should print "No usable proposal came back from the model." This breaks spec rule 5 ("MUST be rejected", `docs/design/specs/proposal/v1.md:60-61`) and the docstring's promise that `parse` returns exactly one of three values (`proposal.py:7-11`). Fix: catch `ValueError` as well (`JSONDecodeError` is a subclass, so one `except ValueError` covers both), or pass `parse_int=` with a length guard. Add the vector to `test_invalid_responses_are_rejected_not_repaired`.
- NEEDS-HUMAN [impl] — `src/nl_shell/proposal.py:139-142` with `src/nl_shell/render.py:26-31` and `src/nl_shell/repl.py:115`: the parser accepts a lone surrogate in `command`, and printing it crashes the REPL. JSON `"\ud800"` decodes to an unpaired surrogate code point. `is_hidden` says it is not hidden, so the proposal is accepted: `CommandProposal(command='ls \ud800', risk='read-only')`. The REPL then prints it to a UTF-8 text stream and gets `UnicodeEncodeError: ... surrogates not allowed`. I reproduced this with `io.TextIOWrapper(io.BytesIO(), encoding="utf-8")` as `out`. The real interactive path writes to `sys.stdout`, so a model response can kill the session. The tests miss it because every REPL test writes to `io.StringIO`, which accepts surrogates. A lone surrogate can't be valid UTF-8 (RFC 8259 / the spec's "UTF-8" convention, `v1.md:32`), so rejecting it in the parser matches the strict, reject-not-repair rule. Fix: reject U+D800–U+DFFF in `command` (or treat them as hidden, so `escape_hidden` also covers `:context`). Add a test that runs the REPL with a UTF-8 `TextIOWrapper`, not `StringIO`.
- `tests/test_backend.py:270-296` (the `start` fixture) monkeypatches `Repl.interactive`, so the `cli.main` tests never run the real `interactive()` (`repl.py:87-98`). I accept this: the brief rules out a user-facing switch to pick the stub, and the part that matters, passing `prompts=` from `cli.main` (`cli.py`, `Repl.interactive(status_lines=..., prompts=loaded)`), does go through the patched code. Not a refutation.
- `src/nl_shell/render.py:39-41`: `escape_hidden` does not escape a backslash. So a request typed as the four literal characters `\x1b` and a request holding a real ESC look the same in `:context`. The brief pins this exact form (Scope 5, criterion (b)), so this is a spec choice and not a builder defect. I'm noting it without a tag because it needs no action unless someone wants `:context` to be unambiguous.

## Attempted and could not refute

- **Red→green evidence** (`gate-logs/C4-verify.log`): the red leg fails for the right reasons. Test-time imports raise `ModuleNotFoundError: nl_shell.backend`, and the old replies don't match. That gives 82 failed and 12 setup errors, not a collection error, and 187 pass in the green leg. T3 shows 311 passed on the full suite. The `:context` test compares against a `context_form` the test builds itself (`tests/test_backend.py:170-180`), not the module's `context_text`, so the check is not circular.
- **Parser rules**: duplicate keys, `NaN`/`Infinity`, deep nesting, array top level, `command`+`reason`, a missing `risk`, extra properties, more than 2000 code points, CR/ESC/DEL/C1/U+202E are all rejected. `clarify`+`risk` is accepted, but spec rule 2 and the schema allow it.
- **Prompts loader**: the `!!python/object` tag is refused by the SafeLoader subclass (`prompts.py:77-96`). Braces in the request are not formatted, because `_volatile` uses plain replacement (`prompts.py:220-222`). Example responses are checked through the same parser. A missing default layer plus a partial user layer gives an error that names the file.
- **`:context` drift**: `_last_input` is the same tuple handed to `complete` (`repl.py:141-144`), and it is set before the backend call, so a `BackendError` still leaves `:context` correct.

Verdict: the C4/T3 "pass" is genuine for what the tests cover. The claim behind criterion (d), that every invalid response is "rejected, never repaired; the REPL then says no usable proposal came back", is too strong: the two inputs above get through and crash the REPL. Both are small parser fixes.

# Advisory security review — issue 16 (prompts YAML, `:context`, recording stub, proposal parser)

Attacker-reachable inputs this diff touches: **threat-model item 5, the model's own output** (the raw response text that `nl_shell.proposal.parse` reads and the REPL prints). The other new inputs are trusted under the threat model: the user's typed request, and nl-shell's own config file (`$XDG_CONFIG_HOME/nl-shell/prompts.yaml`) plus the target's `prompts/prompts.yaml`.

Threat model read: `.oss-scanner/threat_model.md`. AGENTS.md read: it has no reviewer protocol or tracked deferrals that apply here.

## Findings

- NEEDS-HUMAN [impl] — **Low** (the scale has no denial-of-service row; this is the closest fit), `src/nl_shell/proposal.py:110-142` together with `src/nl_shell/repl.py:115`. **Input:** the model's response (item 5). An attacker can steer it through text the model reads, or later through the dev teacher endpoint (item 11). **What goes wrong:** `json.loads` turns a JSON escape for a lone surrogate (`\ud800`, which is half of a UTF-16 pair and not a real character) into a Python string that holds the bare surrogate. The parser does no Unicode check, and `is_hidden` (`src/nl_shell/render.py:26-31`) does not count surrogates as hidden. So the proposal is **accepted** as a `CommandProposal`. Then `print(...)` at `repl.py:115` raises `UnicodeEncodeError: surrogates not allowed`, and the exception ends the whole REPL session. It also breaks the "reject, never repair" rule: the response is not valid Unicode text, but it is accepted. Once #78 lands, the same string would reach the code that sends commands to the PTY. **Reproducer (I ran it on the patched tree and it crashes):** use `RecordingStub(['{"kind":"command","command":"ls \\ud800","risk":"read-only"}'])` with any prompts, give the REPL one natural-language line, and `Repl.run()` dies with `UnicodeEncodeError`. `proposal.parse` returns `CommandProposal`. **Fix:** in `_check`, reject any string value that holds a code point in U+D800–U+DFFF (or fail `value.encode("utf-8")`). Add this case to the §(d)/(e) vectors in `tests/test_backend.py`. Today no test covers it.

## Checked, no finding

- **Hidden characters in proposals** (`proposal.py:139-141`, `render.py:20-31`): the parser rejects C0 except LF/TAB, DEL, C1 (U+0080–U+009F) and the full bidi set the brief pins (U+061C, U+200E/F, U+202A–E, U+2066–9). Rejected responses are never echoed (`repl.py:152-154`, where `why` is not printed). Tests cover ESC, CR, DEL, C1 and U+202E. The set is exactly what the brief asked for. It leaves out other invisible characters (U+200B zero-width space, U+FEFF, U+2028/2029 line and paragraph separators, U+00AD soft hyphen). These are not bidi or control characters in the threat model's wording, and the confirm-UI renderer is #74's job. I'm noting it only so #74 picks it up, not filing it as a finding.
- **Output escaping:** every REPL reply, including `:context` and the backend error text (`BACKEND_FAILED.format(error=exc)`, which the model client can fill later), goes through `escape_hidden` at `repl.py:115`. OSC 52 and other escape sequences start with ESC (0x1B) or C1 0x9D/0x9B, so they get escaped. No path prints model text without escaping.
- **Multi-line commands:** LF is shown as-is (spec rule 3). A model can put text shaped like a second `Proposed command (risk: read-only):` line inside `command`. Nothing runs yet and there is no confirm UI, so nothing breaks today. #74 must render the command so that it can't fake the risk line or the `nl> ` prompt. Same for `:context`: once #11 puts an untrusted state block into the user message, LF in it could fake a `--- system ---` header. Not filed: neither surface exists in this diff.
- **Template injection:** `prompts._volatile` (`prompts.py:220-222`) uses plain slicing and `replace`, not `str.format`, so braces in the request (or the future state block) are just text. The template comes from trusted config anyway.
- **YAML loading:** `_SafeLoader` subclasses `yaml.SafeLoader` (`prompts.py:77-96`), so `!!python/object/apply` is refused, and the test checks the `touch <tmp>/pwned` vector. The file is trusted config in any case. A deeply nested user file could raise `RecursionError`, which `cli.main` doesn't catch. That only happens through the user's own misconfiguration (Low, below the line), so it's not filed.
- **Secrets / sudo password:** the model input is built only from the prompts and the user's typed request. The state-block slot is always `""` (`repl.py:141`, the default `state` argument). No environment or command output reaches `:context` or the backend in this diff.
- **Gates:** `check-gates.json` overall pass. C4 is red without the fix (82 of 175 failed) and green with it.
- **No-backend default:** `Repl.interactive` builds no backend (`repl.py:97-98`), so the interactive REPL makes no model call or network connection. The "locally complete" must-hold still holds.
