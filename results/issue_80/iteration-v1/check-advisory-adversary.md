# Adversarial review — issue 80 / pinned-tldr-snapshot

Verdict: **refuted**. The patch does not include the snapshot it claims to deliver, so the green half of red→green never happened. Both gating runtime gates (C4, T3) are red for that reason, not because of the environment.

- NEEDS-HUMAN [impl] — **The corpus, metadata and license are missing from the patch.** patch.diff adds only `data/tldr/README.md` and `data/tldr/NOTICE.md`. There are no `data/tldr/pages.jsonl`, `data/tldr/source.json` or `data/tldr/LICENSE.md` hunks; `ls $PDCA_TARGET/data/tldr` shows only `NOTICE.md README.md`. The reader opens all three at scripts/tldr_snapshot.py:22, :31 and :37. The frozen gate evidence shows the result: gate-logs/C4-verify.log has the green leg failing both attempts with `No such file or directory ... data/tldr/source.json` (tests/test_tldr_snapshot.py:61) and `real pinned corpus must be shipped` (tests/test_tldr_snapshot.py:105); gate-logs/T3-suite.log shows the same 2 failures among 1332 passes. This is a real defect, not a toolchain gap: the tests ran and failed on assertions. The README's rebuild recipe (data/tldr/README.md:41–82) asserts the anchor, count and byte total, but nothing in the bundle shows it was ever run against the real upstream. Do must acquire the pinned source, generate the three files, and include them in the patch. If Do had no GitHub access (brief line 17 needs it), a human has to provide it.

- NEEDS-HUMAN [impl] — **No valid red→green proof exists.** C2 has no gate configured and C4 stopped at the green leg, so neither "red without the fix" nor "green with it" has been shown for this round. Every claim about the export, determinism, provenance and the inventory anchor (tests/test_tldr_snapshot.py:59–93) is unproven until the corpus ships. Only `test_audit_positive_controls` (:96) passed, and it doesn't touch production code.

- NEEDS-HUMAN [impl] — **Splitting on `str.splitlines()` will corrupt records whose content holds U+2028, U+2029 or U+0085.** The corpus is written with `ensure_ascii=False` (data/tldr/README.md:52), and `json.dumps` escapes only characters below U+0020, so those code points stay raw inside the JSON string. scripts/tldr_snapshot.py:40 (`corpus.decode("utf-8").splitlines()`) and tests/test_tldr_snapshot.py:89 (`read_text().splitlines()`) split on all three. Concrete case: `json.dumps({"c":"a b\x85c"}, ensure_ascii=False)` gives 3 pieces with `str.splitlines()` and 1 with `bytes.splitlines()` (checked locally). Any upstream page containing one of these characters makes `json.loads` raise, and the real snapshot gets rejected. I couldn't check whether the pinned pages contain them because the corpus is missing. Fix: split on `b"\n"` (or use `bytes.splitlines()`) in both places. The test's own export parsing at :67 already uses bytes, which is correct.

- NEEDS-HUMAN [impl] — **The corruption test only reaches the first check.** tests/test_tldr_snapshot.py:106–110: appending `{}` to pages.jsonl is caught by the whole-file `corpus_sha256` check (scripts/tldr_snapshot.py:38). Changing the revision is caught by the identity check (:23–30). The license mutation is caught at :32. None of the three reaches the per-page check (:61), the path check (:50–56), or the fixed inventory/byte-total anchor (:64). The brief (line 7) asks that "a fabricated corpus with a recomputed manifest still fails that anchor". That exact case is never fed to the production reader. Add a mutation that edits one page's content *and* recomputes `corpus_sha256` and that page's manifest entry. It must still be rejected at :64. Without it, deleting the anchor check from production would leave the test green. (The test's own recomputation at tests/test_tldr_snapshot.py:71–83 checks the shipped data, not the reader's rejection path.)

- NEEDS-HUMAN [impl] — **The threat-model edit also strips the local-reference label from man pages and `--help`.** .oss-scanner/threat_model.md:101 (patched) now lists "dpkg-owned man pages and an allowlist of `--help` outputs" under Trusted with no annotation. The removed text `(local-reference, ADR-0016)` covered that whole bullet. ADR-0016 (docs/design/adr/0016-taint-model-v2.md:43) labels dpkg man pages and `--help` as **local-reference** in the same row as tldr. So the patch fixes tldr's grouping but leaves man pages and `--help` looking plainly trusted, which goes against ADR-0016. The brief said to "retain the dpkg/man/help wording", and that should include its label. Keep `(local-reference, ADR-0016)` on line 101, or move man pages and `--help` into the new Local-reference paragraph too. If the brief really meant to drop the label, a human should confirm, since this changes how a security document describes trust.

- Minor: tests/test_tldr_snapshot.py:89 and :92 call `read_text()` without `encoding="utf-8"`, so they depend on the locale. Python 3.14 usually forces UTF-8 under a C locale, but the script itself passes the encoding explicitly (scripts/tldr_snapshot.py:22, :34). The test should do the same.

What I tried and could not break: the audit wrapper's positive controls are real, not empty. `connect_ex` raises `socket.connect` and `subprocess.run` raises `subprocess.Popen`. Both fire before the operation runs, and the attempts list is kept even if the hook's exception is caught (tests/test_tldr_snapshot.py:16–41, passing in the C4 log). The reader imports only the standard library and launches nothing (scripts/tldr_snapshot.py:3–7). The reader validates everything before it writes any output (:77–82). Path traversal is blocked by the 3-part and `..` checks (:50–56).
