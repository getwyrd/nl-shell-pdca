# Plan advisory — plan-reviewer — issue 62 / failure-classes-by-exit-code

- NEEDS-HUMAN — **The 127 lookup uses the wrong command word, so it will suggest the wrong package.** Scope (2) takes "the first shell word of the confirmed command" via `router.first_token` (`src/nl_shell/router.py:38-48`). Scope (1) also says to use "the command's last pipeline status as the exit status (bash's `$?`)". Those two rules disagree for pipelines and lists. With `cat log | htopp` or `make && htopp`, `$?` = 127 comes from the *last* command, but `first_token` returns `cat`/`make`. The lookup then suggests `coreutils`/`make` as the fix for a missing `htopp`. That is a confident wrong answer in the class that is supposed to be "no model needed". `FOO=1 htop` (127) gives the token `FOO=1`; `router.py:9-10` already says leading assignments are not recognised. `env x`, `nohup x` and `time x` give the wrapper's name. The brief's own input wording ("the command word that would have been not found") admits the word can differ from the first token, but the success criterion only tests single-word commands (`htop`). Fix: when the confirmed command contains `|`, `;`, `&&`, `||` or a leading assignment, return not-found *without* a suggestion. Add a criterion row such as `cat f | htopp` with 127 → not-found, no package suggested.
- NEEDS-HUMAN — **Part of the "Plus:" criteria can't be checked as written.** "the classifier takes the exit status from the session's done-record type (#10), not from a bare integer" and "never reads stderr" are design properties. No listed test makes them go red. Either name the observable check (passing a bare `int` raises `TypeError`; the classify signature has no stderr/output parameter, asserted with `inspect.signature`), or mark them as reviewer-checked. The same applies to "the classifier module names no OS path": add a test that greps the module source for `/var/`, `/usr/` and `commands.db`. Otherwise the C4 red leg doesn't cover them and Check can't falsify them.
