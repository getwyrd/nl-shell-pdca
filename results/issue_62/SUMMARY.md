- [x] **The 127 lookup uses the wrong command word, so it will suggest the wrong package.** Scope (2) takes "the first shell word of the confirmed command" via `router.first_token` (`src/nl_shell/router.py:38-48`). Scope (1) also says to use "the command's last pipeline status as the exit status (bash's `$?`)". Those two rules disagree for pipelines and lists. With `cat log | htopp` or `make && htopp`, `$?` = 127 comes from the *last* command, but `first_token` returns `cat`/`make`. The lookup then suggests `coreutils`/`make` as the fix for a missing `htopp`. That is a confident wrong answer in the class that is supposed to be "no model needed". `FOO=1 htop` (127) gives the token `FOO=1`; `router.py:9-10` already says leading assignments are not recognised. `env x`, `nohup x` and `time x` give the wrapper's name. The brief's own input wording ("the command word that would have been not found") admits the word can differ from the first token, but the success criterion only tests single-word commands (`htop`). Fix: when the confirmed command contains `|`, `;`, `&&`, `||` or a leading assignment, return not-found *without* a suggestion. Add a criterion row such as `cat f | htopp` with 127 → not-found, no package suggested.
