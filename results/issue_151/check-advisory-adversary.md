# Adversarial review — issue #151 (teacher-client-transport), iteration 3

I could not break the client. I tried hard on the transport, the deadline and the escaping, and every hostile input I built ended in a `BackendError` within the deadline. Two small findings are below. Neither is a refutation.

## What I attacked and could not break

- **Red→green evidence.** `gate-logs/C4-verify.log`: 79 of 79 tests fail with the fix reverted and pass with it. The red run fails for the right reason: every import is inside a test function, so the run gives 79 failures, not a collection error. The stub-backend leg (`tests/test_teacher_client.py:759`) raises a plain `backend.BackendError` and never imports `teacher_client`. If only the `try/except` at `src/nl_shell/repl.py:166-169` were reverted, the error would escape `Repl.run` (`repl.py:137`, no catch around `_reply`) and the test would fail. That leg is real. pytest is not installed in my sandbox, so I did not re-run the suite. I ran the production code directly with stdlib fakes instead (below). T3 (the full suite) is green: 560 passed.
- **URL parsing** (`src/nl_shell/teacher_client.py:240-271`). I sent `http://h:-1/`, `:99999`, `:+80`, `:1_0`, `:80:90`, `http://[::1/`, `http://[::1%25eth0]/`, `http://[v1.x]/`, `http://%41/`, `http://-/`, `http:h`, `http:/h`, `http://h\@evil/` and an Arabic-digit port through both `http_target` and `complete`. Each one became `BadEndpoint` or `TransportError`. None raised `InvalidURL` or `ValueError`. Building the URL target and the connection happens inside the worker (`:516-518`), so every error goes through `_as_backend_error` (`:490`).
- **timeout_s edge values** (`:274-292`). `1e308`, `1.7e308`, `10**308`, `-0.0` and `5e-324` all ended in a `BackendError` subclass. Nothing overflowed. Waits are clamped by `_wait_for` (`:295`).
- **The deadline.** A server that floods `HTTP/1.1 100 Continue` forever (http.client skips these in a loop) was cut off at 0.50 s with `DeadlineExceeded`. During the TLS handshake, `abandon()` (`:337`) can't wake the worker, because `wrap_socket` detaches the only socket the exchange tracks (`:392-393`). I built a slow-drip handshake server to exploit that, but CPython puts one total deadline on the whole `do_handshake`. The worker exited with the caller, and no thread leaked.
- **Escaping.** `render.escape` covers C1 controls (`\x9b`), bidi controls (`‮`), zero-width characters and ` `. `_excerpt` (`:224`) folds LF before escaping, which closes the iteration-1 `BadStatusLine` finding.
- **TLS.** An `https://` URL pointed at a plain-HTTP fake fails at once with `TransportError: TLS failed: SSLError … RECORD_LAYER_FAILURE`. The fake saw no request.

## Findings

- NEEDS-HUMAN [impl] — The TLS test is looser than the brief. `tests/test_teacher_client.py:461-463` accepts `teacher_client.DeadlineExceeded` as well as `TransportError` for the `https://` URL pointed at the plain-HTTP fake. The brief asks for "TLS error". A client that stalled the handshake until the 3 s timeout ran out would pass this leg. In practice the client fails straight away with `TransportError` ("TLS failed: …", `src/nl_shell/teacher_client.py:503-504`; I checked against a stdlib `http.server` fake). Fix: tighten the assertion to `TransportError` and check that the text starts with `TLS failed`.
- NEEDS-HUMAN [human] — Ctrl-C during a model request will end the REPL session. This is latent: nothing builds a `TeacherClient` yet, because `src/nl_shell/cli.py:65` passes no backend. `Repl.run` catches `KeyboardInterrupt` only around `read` (`src/nl_shell/repl.py:126-131`), not around `_reply` (`:137`). `TeacherClient.complete` passes `KeyboardInterrupt` on unchanged (`teacher_client.py:493-494`), after `abandon()`. This patch adds the first backend call that can block for up to `timeout_s`. Once child-2 wires it in, a user who presses Ctrl-C at a slow server gets a traceback and exits the shell, instead of the bash-like "clear and continue" that `repl.py:131` promises for the prompt. Non-blocking requests were deferred by Plan, so this is a scope call: handle it in child-2 (catch it in `_propose`) or accept it for now.
