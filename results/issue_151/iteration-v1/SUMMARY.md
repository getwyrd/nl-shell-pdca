### Advisory — adversary

# Adversarial review — issue #151 (teacher-client-transport)

The red→green evidence holds up. `gate-logs/C4-verify.log` shows 72/72 failing with the production files reverted. The failures are the in-function `ImportError` for `nl_shell.teacher_client` and the missing `backend.BackendError`, which is the failure the brief predicted. With the fix, 72/72 pass. T3 (the whole suite) passes with 553 tests. The tests drive the real `TeacherClient` and `Repl` against a stdlib fake server. They do not test a copy. The stub-backend leg (`tests/test_teacher_client.py:754`) does go through the `Repl._propose` catch. I found one concrete crash, plus two smaller points.

- NEEDS-HUMAN [impl] — `src/nl_shell/teacher_client.py:304`: `TeacherClient(Endpoint("http", "http://127.0.0.1:1"), timeout_s=10**400)` raises an uncaught `OverflowError: int too large to convert to float` from `math.isfinite`. I ran this against the target source and confirmed it. The brief says the constructor and edge cases "must raise `BackendError` (never `OverflowError` …)". `isinstance(timeout_s, (int, float))` accepts any Python int, so a large int from config (child-2) gets past the type check and then crashes. The unusable-timeout test (`tests/test_teacher_client.py:482`) only covers `0, -1, nan, inf`, so it would not catch this. Fix: convert with `float(timeout_s)` inside a `try` that maps `OverflowError` to `BadEndpoint`, or check the float form. Then add `10**400` to that parametrize list.
- `src/nl_shell/teacher_client.py:269` / `:359`: when a name lookup (`getaddrinfo`, the system call that turns a host name into addresses) hangs, the caller gets control back at the deadline, as required. The worker thread stays blocked, though, because nothing can wake `getaddrinfo`. So every request against a resolver that hangs leaves one daemon thread behind. If enough pile up, `worker.start()` at `:359` raises `RuntimeError: can't start new thread`. That call runs outside the error mapping, so the error would escape `Repl._propose`. The brief accepted the worker-thread design (iteration-v6), so this is a known limit, not a regression. I'm noting it without a tag because it isn't a sign-off item.
- `src/nl_shell/repl.py:76`–`:80`: `backend_failure` formats `str(exc)` without escaping it. It relies on each backend having called `render.escape` already, as the `backend.py` docstring requires. `TeacherClient` does escape. A future backend that raises `BackendError` with raw server text would put that text on the terminal. Also, `repl.py` now imports `teacher_client` to pick the "isn't running" reply, so the generic REPL depends on one specific backend. Both are design choices the brief allows ("Server text … goes through `render.escape` when the error is built"). Not a defect in this diff; mentioned only so the human sees the contract.

Things I tried that did not break the fix:
- Redirect, error status, non-JSON body, and missing or non-string `content`. Also `doc` as a string, list or dict with `choices` of the wrong type, which raises `TypeError` and gets mapped.
- A hostile reason phrase or body. ESC, BEL and CR are escaped or removed by the whitespace split.
- The chunked slow drip. The caller's `abandon()` calls `shutdown()`, which wakes `readline`.
- A hung TLS handshake. The SSL socket isn't tracked yet at that point, but the caller still returns at the deadline, and the handshake has its own timeout of the time left.
- `1e10`, `1e308` and `10**20` timeouts all work.
- `/v1`, `/v1/` and `/api/v1` paths, IPv6 Host brackets, uppercase schemes, and userinfo or query in the URL.

# Security review (advisory): teacher-client-transport

**Attacker-reachable inputs this diff touches:** everything the model server sends back — the status line and reason phrase, headers, error bodies, the chat-completions body, and its timing (threat model "Where untrusted input enters" items 5, 8 and 11; the LAN peer when the endpoint is the dev teacher). The endpoint URL and socket path come from nl-shell's own config or `XDG_RUNTIME_DIR`, so they are trusted. No code in this diff picks a non-default endpoint (that is child-2).

## Findings

- NEEDS-HUMAN [impl] — **Low** (threat model: "information leaks in error messages"; not a UI spoof). `src/nl_shell/teacher_client.py:128` (`_describe`) and `:387` (`return TransportError(_describe(exc))`). **Input:** the server's status line, which the model server or a LAN peer at the dev teacher address controls. **What goes wrong:** when the status line doesn't parse, `http.client` raises `BadStatusLine(line)` and puts the whole raw line in it, up to about 64 KiB. `_describe` escapes it but never shortens it, so the server's own text reaches the REPL reply in full. That gets around the 200-character limit (`EXCERPT_CHARS`, `:67`, `:431`) the patch applies to error bodies, and the trailing LF passes through, because `render.escape` leaves LF alone. No ESC, BEL or CR gets through: `_quote` escapes them, and `Repl.run` escapes the reply again (`src/nl_shell/repl.py:138`). What's left is a server able to print a long run of its own text (for example `Proposed command (risk: read-only) …`) after the fixed `The model server could not be used: BadStatusLine:` prefix. **Reproducer, run against the patched target:** a TCP fake that answers `b"HTTP/1.1 Proposed command (risk: read-only) " + b"A"*5000 + b"\x1b[2K\r\n\r\n"` makes `repl.backend_failure(exc)` return 5108 characters, starting `'The model server could not be used: BadStatusLine: HTTP/1.1 Proposed command (risk: read-only) AAAA…'` and ending `'…AAA\\x1b[2K\\x0d\n.'`. **Fix:** cut the text in `_describe` (or in `_as_backend_error`) to `EXCERPT_CHARS` and fold whitespace the same way the body excerpt does (`" ".join(text.split())`). Then add a test with a malformed, oversized status line and assert on the reply's length and that it has no LF. The current hostile-status test (`tests/test_teacher_client.py:773`) uses a status line that parses, so this path isn't covered.

## Checked, no finding

- **Escaping server text.** Reason phrase (`_content`), error-body excerpt (cut and whitespace-folded, then escaped), exception text (`_describe`) and the Unix socket path all go through `render.escape` before they are put in the error. `Repl.run` escapes the reply again before printing. The test at `tests/test_teacher_client.py:773-792` covers OSC 52, BEL, CR and ESC in both the status line and the body, and checks the raised error's text as well as `out`.
- **Strict parsing.** The client returns `choices[0].message.content` unchanged and `Repl._propose` passes it to `proposal.parse`. There is no repair and no retry. If `json.loads` raises `RecursionError` (deep nesting) or `ValueError` (including Python's limit on long integer strings), that becomes `BadResponse`.
- **Size and time.** `read1` is capped at `cap + 1` per read; a `Content-Length` over the cap is refused before any of the body is read; the header and chunk-size line limits are `http.client`'s own. The caller thread waits in `done.wait` only until the deadline, then shuts the sockets down. Tests cover a slow drip, a chunked slow drip, a slow status line, a hanging lookup and several hanging connects. I also probed a TLS handshake fed one byte every 0.3 s with `timeout_s=1.0`: `DeadlineExceeded` came at 1.0 s, and the worker thread was gone 5 s later (CPython applies one deadline to the whole handshake). So a hostile server leaves no thread behind.
- **Transport.** `http.client` reads no proxy variables. A 3xx is refused before the body is read (tested with a second listener). TLS uses `create_default_context()` with `CERT_REQUIRED` and `check_hostname=True`, with no fallback to plain HTTP (tested). No `Authorization` header is sent. A URL with user info, controls, spaces, non-ASCII characters, a query or a fragment is refused before any connection is made.
- **REPL keeps running.** Every exception the worker can raise becomes a `BackendError` subclass, except non-`Exception` `BaseException`s. Those are only raised on the main thread, which this design keeps out of the worker. `Repl._propose` catches `BackendError`. The stub-backend test (`:754`) fails if only the catch in `repl.py` is reverted.
- **Outbound data.** The request carries the model input (prompt plus state block) to whatever endpoint the client is given. This diff adds no way to choose a non-default endpoint, so the default config still makes no network connection. Data sent to the dev teacher is already covered by threat model item 11.
- **T2 gate (threat model not updated).** In my view this diff needs no threat model change. It adds no new untrusted input and moves no trust boundary: the socket (item 8) and the dev teacher (item 11) are already listed. "How to exercise it" will need a line about the fake server in `tests/test_teacher_client.py` sooner or later, but the brief puts doc edits out of scope. The T2 gate already sends this choice to sign-off, so I'm not adding a separate bullet.
- **Gates.** C4 shows the test red before the fix and green after it (72 of 72), and T3 shows the full suite green (553 passed), per `gate-logs/`.
