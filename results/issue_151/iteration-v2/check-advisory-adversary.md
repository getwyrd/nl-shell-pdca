# Adversarial review — issue #151 (teacher-client-transport)

pytest is not installed in this sandbox, so I did not re-run the suite. I read the frozen C4 log instead (`gate-logs/C4-verify.log`: 79 passed with the fix, 79 of 79 failed with non-`tests/` files reverted, no collection errors) and ran my own stdlib probes against `target/src`. The red leg is real: every test imports `nl_shell.teacher_client` / `backend.BackendError` inside the function, and both are new in this patch. The tests go through the production `TeacherClient.complete` and `Repl.run`, not a copy.

## Findings

- NEEDS-HUMAN [human] — `target/src/nl_shell/repl.py:130` and `target/src/nl_shell/teacher_client.py:399-400`: pressing Ctrl-C while a model request is waiting ends the whole REPL session. `Repl.run` only catches `KeyboardInterrupt` around `self._read`. During `complete`, the interrupt lands in `done.wait` (`teacher_client.py:384`), `abandon()` runs, and `_as_backend_error` lets `KeyboardInterrupt` through on purpose, so it escapes `_reply` (`repl.py:138`). I checked this: a TCP fake that accepts and never answers, `timeout_s=5`, SIGINT after 0.5 s → `REPL ENDED BY KeyboardInterrupt`, and the second input line is never read. Before this patch no backend could block, so this is new behavior. It matters because `timeout_s=1e10` is accepted by design, which leaves Ctrl-C as the only way out of a hung server, and that kills the session. This goes against brief invariant (3) ("never ends the REPL session"). Catching it in `_propose` would be a small change, but it needs a new reply text, and the brief defers non-blocking requests and the ADR-0018 §7 unavailable state. So a human has to decide: fix it here, or record it for the §7 bundle.
- Tried, could not refute — TLS handshake outliving the deadline (`teacher_client.py:297-299`). `wrap_socket` detaches the raw socket before the handshake, so `abandon()` cannot shut down a socket stuck mid-handshake. In practice CPython bounds the whole handshake by the socket timeout set at `:297`. A probe with a server sending one handshake byte every 0.3 s against `timeout_s=0.5` had the caller give up at 0.50 s, the worker hang up at about 0.9 s, and no leftover worker thread. Not a defect.
- Tried, could not refute — the round-1 carry-forward fixes. `10**400`, `-(10**400)` and `10**5000` now raise `BadEndpoint` through the `float()` try (`teacher_client.py:192-195`) and are in the test list (`tests/test_teacher_client.py:484`). A malformed `BadStatusLine` now goes through `_excerpt` (`teacher_client.py:137,143`): whitespace folded, cut to 200 characters, then escaped. Both legs are covered by `tests/test_teacher_client.py:818`.
- Tried, could not refute — the deadline and edge cases: a lookup that sleeps, several hanging connects (one deadline in total, `:308`), a chunked slow drip (the caller thread gives up at the deadline whatever `http.client` is blocked in), a redirect checked before the body (`:448`), a declared length over the cap (`:457`), `read1` cut to `cap+1` (`:477`), an empty or BOM body, deep JSON nesting (`RecursionError` caught at `:493`), and URL refusals (userinfo, query, control characters) checked before any lookup (`:151-168`). I found no input that lets a non-`BackendError` escape `complete` other than `BaseException`s that are not `Exception`s.
- Note, not a new finding — T2 is `unverifiable` (`gate-logs/T2-threat-model.log`). The brief puts `.oss-scanner/threat_model.md` out of scope, and the round-1 sign-off already sent this to the human (deferred-findings). The patch adds nothing that changes that question.

Summary: I tried to refute the red→green evidence, the deadline and escaping work, the round-1 fixes and the TLS path, and could not. The one real gap is that Ctrl-C during a request ends the session. That is a scope call, not a build bug.
