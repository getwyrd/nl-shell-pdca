# Security review — session-terminal-ownership (#102)

**Attacker-reachable inputs this diff touches:** command output (threat model "Where untrusted input enters" item 1), which now flows through `_Ownership.mirror` → the real terminal and through `_AltScreen.filter` → the capture; and session state (item 4), which the new stdin drain in the prompt hook runs inside. Keys typed on the real terminal are the user's own and trusted.

Rubric: `target/.oss-scanner/threat_model.md` (present). `AGENTS.md` has no reviewer protocol beyond change discipline. The drain race and the unfiltered mirror are already listed in Known gaps (`threat_model.md`, the two new #102 bullets), and the brief already sends the race to the human at sign-off, so I do not raise either one again.

## Findings

- NEEDS-HUMAN [impl] — **Low.** `src/nl_shell/session_terminal.py:56` (`_ALT_SEQUENCE`). The input is command output, which the text-only attacker controls. The regex only matches the single-parameter 7-bit form `ESC [?1049h`. xterm and VTE also switch to the alternate screen on combined parameters (`ESC [?25;1049h`, `ESC [?1049;25h`) and on 8-bit CSI (`0x9b ?1049h`, where the terminal accepts C1 codes). For those forms the real terminal goes to the alternate screen but capture keeps going. So text drawn there and then wiped by the matching reset reaches the capture (and later the state block) while the user never sees it on the main screen. That breaks §6.2's "capture MUST stop on the alternate screen" for crafted output. It doesn't cross a confirm, since captured output is untrusted anyway, so the impact is small. I confirmed it by calling `_AltScreen` directly: `filter(b"A\x1b[?25;1049hSECRET")` returns `b"A\x1b[?25;1049hSECRET"`, and the plain `\x1b[?1049h` form returns `b"A"`. Fix: parse the whole private-mode parameter list (`\x1b\[\?([0-9;]*)([hl])`, then act on any 47/1047/1049 in it). Add the combined-parameter case to `test_alternate_screen_is_mirrored_but_not_captured` (`tests/test_session_terminal.py:174`). Today that test only covers the friendly single-parameter path.

- NEEDS-HUMAN [impl] — **Low.** `src/nl_shell/session_terminal.py:142,271,310` (`mirror_dropped`) and `src/nl_shell/session.py:863` (`_result`). The input is command output volume, which the attacker controls (for example a 1 MiB+ burst while the real terminal is slow). Past `MIRROR_LIMIT`, or after the 1 s settle, the copy to the real terminal is dropped while the capture keeps it. The result is that the state block can hold output the user never saw. The cut can also land in the middle of an escape sequence or swallow an `ESC [?1049l`, which leaves the user's terminal on the alternate screen. The patch records this in `_Ownership.mirror_dropped`, but nothing reads it: `CommandResult` gets `input_forwarded` and not this flag, so #78 has no way to tell the user "output was cut on screen". Check: `grep -rn mirror_dropped src tests` finds only the three assignments. Fix: add a `mirror_dropped` field to `CommandResult` next to `input_forwarded`, and assert it in `test_a_terminal_that_stops_reading_does_not_stall_the_run` (`tests/test_session_terminal.py:460`).

## Checked, no finding

- **Paste integrity (Critical class "what runs differs from what was confirmed").** `begin()` makes the session master non-blocking before the paste (`session_terminal.py:159`). `_write_all` (`session.py:1229-1237`) retries on `BlockingIOError`, so a long paste is still written whole. Forwarding only starts in `_wait_for_result`, after the paste and `\r` are fully written (`session.py:722-723`), so typed bytes can't interleave with the paste. readline returns at the `\r`, so later bytes can't join the confirmed line. Bytes typed before the run are flushed (`session_terminal.py:157`).
- **The drain in the hook (`session.py:258-262`).** It uses `\builtin read` (immune to aliases and to a user function named `read`) and `[[ -t 0 ]]` (a keyword). `read` was added to `HOOK_BUILTINS` (`session.py:96`), so `enable -n read` degrades the session. A function named `builtin` is a known gap already. There is only one `E` write (`session.py:264`) and the drain sits right before it, so no path writes `E` without draining. After `D` nl-shell stops forwarding, so nothing an attacker prints can keep the drain loop alive.
- **Forwarded bytes kept or logged (§6.1).** `_pending` and `_mirror` are zeroed before being cleared. Capture returns nothing from the first written byte on (`session_terminal.py:252-253, 319-328`), and `forwarded` is set before the next PTY read, so the echo of a typed byte (a password typed into a program, say) is never captured. No logging calls in the new module. Test (c) scans objects, globals and DEBUG logs.
- **End-marker and record forgery.** The alt-screen filter runs after `_Output.feed` finds the end marker, so printed text can't use alternate-screen sequences to hide or fake the marker. The new `_marker_start` (`session.py:1178`) holds back only a real prefix of the per-session marker, which is correct. Control records still come only from fd 3.
- **Mismatched resets and split sequences.** `?1049h` closed by `?47l` doesn't resume capture (tested). A sequence fed one byte at a time is still caught (I checked this directly: the output was `b"AB"`). Alt-screen state is per run, so one command's unclosed `?1049h` doesn't hide the next command's output.
- **Restore on every exit path (§6.5).** `end()` runs in `finally` (`session.py:724-726`). It records the termios settings before anything else in `begin()`, and puts back the settings, the blocking flags and the `SIGWINCH` handler inside nested `finally` blocks. That holds even if `begin()` itself raises partway through. Tests (g) cover normal, degraded and exception exits.
- **Resource use.** The mirror queue is capped at 1 MiB and the settle step at 1 s. Input is read only when nothing is queued, in chunks of at most 1 KB. A real terminal that stops reading doesn't stall `D` or the timeout (tested).
- **Terminal answerback and OSC 52 through the mirror.** These are already a Known gap, with the #78 gate line updated (`threat_model.md`, "The §6 mirror is not filtered yet"). This addresses the iteration-1 carry-forward. One note for the filter issue, not a finding: the filter has to run on the stream before the mirror queue truncates it, or a cut in the middle of a sequence could join two pieces into a new one.

No Critical, High or Medium findings. Both findings above are Low and fixable by the builder.
