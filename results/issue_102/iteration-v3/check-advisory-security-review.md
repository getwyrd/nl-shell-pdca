# Security review (advisory) — session-terminal-ownership (#102)

Attacker-reachable inputs this diff touches: **command output** (threat model "Where untrusted input enters" item 1), which flows into the new §6 mirror (`mirror`), the alternate-screen capture filter (`_AltScreen.filter`) and `_Output`. Real-terminal input is the user's own keystrokes (trusted), but a terminal's answer to a query that output sent counts as attacker-induced. That case is already listed under Known gaps ("The §6 mirror is not filtered yet"), so it is not raised here on its own.

## Findings

- **Low** — `src/nl_shell/session_terminal.py:68` (`_PRIVATE_MODE`, also `:70` `_PRIVATE_MODE_START`). Input: command output, controlled by the text-only attacker. The regex treats a bare `0x9b` byte as an 8-bit CSI (control sequence introducer) anywhere in the stream. But `0x9b` is also a normal UTF-8 continuation byte (`Û` = `C3 9B`, Cyrillic `ћ` = `D1 9B`, and many CJK characters). Ubuntu terminals (VTE, xterm in UTF-8 mode) do not act on C1 codes inside UTF-8 text. So the filter and the real terminal can disagree about which screen is showing, in both directions:
  (1) `printf 'Û?1049h'; echo REST` — the terminal shows the text on the main screen, but capture stops for the rest of the command. The output is shown but never captured, so the model sees a cut-off result (for example, an error line it never gets).
  (2) `printf '\033[?1049hALT'; printf 'Û?1049lINJECT'; printf '\033[?1049lMAIN'` — capture starts again while the terminal is still on the alternate screen. `INJECT` is captured, and the user sees it only for a moment before the real reset wipes it.
  I checked both by calling `_AltScreen` directly. `filter('Û?1049hHIDDEN'.encode())` returns `b'\xc3'` with `mode=1049`. Case (2) returns `b'SEEN-ONLY-ON-ALT\x1b[?1049lMAIN'`. No "What must hold" property breaks: captured output is untrusted either way, and an attacker can already hide captured text on the main screen (conceal attribute, `\r` overwrite). That is why this is Low. Still, this is a new mismatch between what is shown and what is captured, and it came from the 8-bit-CSI support added in this round. The test at `tests/test_session_terminal.py:186` only covers the friendly case, a lone `\233?47h` that no UTF-8 lead byte comes before.
- NEEDS-HUMAN [impl] — The fix for the Low finding above (`src/nl_shell/session_terminal.py:68,70`): treat `0x9b` as CSI only when it is not a UTF-8 continuation byte (no lead byte `0xC2`–`0xF4` before it in the current character). Or drop 8-bit CSI matching, since Ubuntu's default terminals run in UTF-8 and ignore it. Then add `'Û?1049h'` / `'ћ?47l'` cases to `test_alternate_screen_is_mirrored_but_not_captured` (`tests/test_session_terminal.py:174`), asserting that capture continues.

## Checked, no finding

- **Forwarded bytes kept nowhere (§6.1).** `_pending` is zeroed before it is cleared (`session_terminal.py:311`), and the mirror copy is zeroed too. Capture stops once `forwarded` is set, which happens before the PTY echo can come back. `flush()` also returns nothing after forwarding. The sentinel test (`test_forwarded_input_reaches_the_program_and_is_kept_nowhere`) scans objects, closures, module globals and DEBUG logs.
- **Window start.** `tcflush(TCIFLUSH)` runs in `begin()` (`session_terminal.py:212`) before the paste. Forwarding starts only after `_write_all` has sent the whole paste, so no typed byte can land inside the confirmed command's bytes. Setting the master non-blocking before the paste is safe: `_write_all` (`session.py:1235`) waits and retries on `BlockingIOError`. "What the user confirms is exactly what runs" still holds.
- **Window end / decision 6.** Before every ≤1 KB write to the master, `forwarding_over()` reads fd 3 and stops at `D`. The drain (`session.py:261`) uses `\builtin read` and is guarded by `[[ -t 0 ]]`. Once nl-shell has stopped forwarding, nothing an attacker's output can trigger writes to the slave's input, so the loop cannot be kept running. The remaining race is named in Known gaps, and the brief raises it for sign-off. Not re-raised.
- **Resource use.** The mirror queue is capped (`MIRROR_LIMIT` 1 MiB), the held-back tail is capped at 4096 bytes, and `settle` is capped at 1 s. The regexes run in linear time on crafted digit runs. A stalled terminal cannot stop `D` / `E` detection or the timeout (`test_a_terminal_that_stops_reading_does_not_stall_the_run`, `test_a_full_input_buffer_does_not_stall_the_run`).
- **Shared fd flags.** `_open_private` (`session_terminal.py:132`) opens the terminal again with `O_NOCTTY|O_NONBLOCK|O_CLOEXEC` and leaves the shared fds alone. The path comes from `ttyname` or `/proc/self/fd`, never from the attacker.
- **Mode restore (§6.5).** `end()` runs in `finally` around the whole window (`session.py:720`), with nested `finally` blocks so `tcsetattr` always runs. The three restore tests pass (T3: 499 passed).
- **Unfiltered mirror (OSC 52, terminal queries).** This is in Known gaps, and the #78 wiring gate in `threat_model.md` now names the rendering filter. Nothing wires `terminal=` to the real stdin yet. Not re-raised.
