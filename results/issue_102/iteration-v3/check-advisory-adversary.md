# Adversarial review — #102 session terminal ownership (iteration 3)

pytest isn't installed in this sandbox, so I couldn't re-run the gate suite. I used the
host's real bash 5.3 and `ptyprocess`, and drove `Session.run(…, terminal=…)` from plain
scripts against the patched tree and a scratch copy (`work/`) with the drain removed.

- NEEDS-HUMAN [human] — **A keyboard Ctrl-C typed as a command finishes degrades the session, and no Known gap says so.** `src/nl_shell/session_terminal.py:297-308` forwards `\x03` whenever nl-shell hasn't read `D` yet. Unlike `Session.interrupt()`, it doesn't check `Phase.RUNNING`. The interrupt docstring already warns that "one that races the command's end degrades the session" (`src/nl_shell/session.py:678-680`). This patch exposes that same race to every user keypress. Concrete case: `run("sleep 0.2", terminal=…)` with `\x03` typed on the stand-in terminal 0.200–0.203 s in. On the second try (delay 0.203 s) the session degraded: once with `control record 'D' arrived out of order (inside a snapshot)`, once with `the snapshot's H differs from the baseline`. The SIGINT reaches bash while its prompt hook runs, and the line discipline acts on it at once, so the decision-6 drain can't absorb it. The same race shows up with the drain removed, so the drain didn't cause it. Forwarding did. The (b) test (`tests/test_session_terminal.py:207`) only presses Ctrl-C in the middle of `sleep 5`, so it never hits this. The threat model's Known gaps (`.oss-scanner/threat_model.md:212`) and spec §6.1 (`docs/design/specs/pty-protocol/v1.md:438`) name only the printable-byte race, which costs one stray prefix. This one costs a degraded session until `restart()`. A human should decide whether to accept it for v1 (and add a Known-gaps line), or ask for a bash-side fix, since nl-shell alone can't close a race against bash's own timing.

- Attempted to refute the decision-6 evidence; could not. With the drain lines deleted from the rcfile (scratch copy), 3/3 runs of "type `echo INJECTED; ` during `sleep 0.6`, then run `true`" returned `'INJECTED\n'`. With the patch, 10/10 came back clean. So (d) exercises the production drain (`src/nl_shell/session.py:258-262`), not a copy. Typing continuously across `D` (`echo INJ;` every 1 ms, 15 rounds) never leaked into the next command either. That fits the claim that the residual race needs nl-shell to lag past the snapshot plus 50 ms.

- Attempted to break the start of the window (Ctrl-C written right after `begin()`, before readline has read the paste); could not. The run returned status 130 and the session stayed healthy.

- The C4 red leg (`gate-logs/C4-verify.log`, "18 of 18 failed") is a `ModuleNotFoundError` for every test, as the brief designed. It proves the module is new, not that each test checks behaviour. I checked behaviour separately only for (d), above. The others (alternate-screen filter, mirror backpressure, flag restore) rest on the green leg and the reviewer's reading. I found no tautology in them on inspection: e.g. `test_alternate_screen_is_mirrored_but_not_captured` (`tests/test_session_terminal.py:174`) asserts exact captured text and that the hidden text is on the screen. That's a note, not a refutation.

- Attempted and found nothing new: SIGWINCH restore when the previous handler wasn't set from Python (`session_terminal.py:234`; `signal.signal` returned `0`/SIG_DFL here, and restoring it works). `select.select` instead of poll (`session.py:783`), which the base `_select` helper (`session.py:1230`) already does. Shared `O_NONBLOCK` (now a private reopened description, `session_terminal.py:132-160`). `begin()` raising part-way: `end()` runs from the `finally` at `session.py:727-729` and only restores what was saved.
