# Result — issue 10 / persistent-bash-pty-session

## 1. Spec (from brief.md)              ← Check verifies against THIS
- Defect / goal: A session object that starts one long-lived interactive bash on a PTY with nl-shell's control channel on fd 3, sends a confirmed command byte-for-byte, and reports when it started and finished, its exit status and `PIPESTATUS`, its captured output, and the session snapshot — all from control-channel records, never from printed text. `cd` and `export` persist between commands; a running command can be interrupted with Ctrl-C; protocol violations put the session into degraded mode.
- Success criterion: `python3 -m pytest tests/test_session.py` passes on the host (real bash 5.x, no VM, no sudo), and that file covers, each with a bounded timeout (a hang fails the test, it never stalls the gate): (a) `cd /tmp` then `pwd` → the second command's captured output is `/tmp`; `export FOO=bar` then `printf %s "$FOO"` → `bar`. (b) spec §Conformance vectors 1–8 and 10 exactly as tabled: `true` → start record 1, done record `1 0 0`, then a snapshot ending in `E` · `false | true` → status 0, pipestatus `1 0` · `(exit 3)` → status 3 · `printf 'D 99 0 0\n'` and `printf '\x1b]133;D;0\x07'` → printed on the PTY, the control channel carries only the real start/done records, the reported status is 0 · `echo 'done!!'` → output `done!!` · `alias ll2='ls -la'; g(){ :; }` → the next snapshot's function list gains `g` and its aliases contain `ll2` · `PROMPT_COMMAND=:` → degraded mode within 3 s, with a reason (detected by the back-at-a-prompt rule in Design) · `sleep 5` then the Ctrl-C byte (`\x03`) forwarded to the PTY → its `D` record arrives less than 2 s after `\x03` is written, with status 130, and the session is NOT degraded (it was running an external command, not at a prompt, for the whole wait). (c) vector 9 typed raw: `exec 3>&-` → degraded mode (control channel closed). (d) vector 12: a command containing `ESC [201~`, `ESC`, or another C0 control except TAB/LF is refused by the session without writing anything to the PTY. (e) vector 11 with `TERM` set: output between `ESC [?1049h` and `ESC [?1049l` (and `ESC [?47h`/`l`) is mirrored but not captured, and capture resumes after it (drive it with `printf` of those sequences around a marker word, so the test doesn't depend on `less`). (f) a command with no output, a multi-line command, a here-doc, and a background job (`sleep 1 &`) each produce exactly one start/done pair; the background job's `D` has status 0, the session is not degraded, and after `sleep 3 &` the next snapshot's `J` is still `0` (`J` counts *stopped* jobs, and a running background job is not stopped) while the session stays usable for the next command. (g) a snapshot carries the v1 fields `T`, `B`, `X`, `P`, `J`, `H`, `V` besides `F`/`L`, the first snapshot is kept as the baseline, and changing `PS0` puts the session in degraded mode (`H` differs); so does appending an array element, `PROMPT_COMMAND+=(':')` (H is computed over every element, see Design). (h) a `~/.bashrc` in the test's temporary HOME that sets an alias and its own `PROMPT_COMMAND` → the alias is in the first snapshot and the user's `PROMPT_COMMAND` still runs, after nl-shell's hook; a `~/.bashrc` containing `bind 'set enable-bracketed-paste off'` and `set -o vi` → a two-line command still arrives byte-for-byte and gives exactly one start/done pair. (i) bash writes no history: `HISTFILE` is unset in the session. (j) control-channel wiring: inside the session `[ -p /dev/fd/3 ]` is true (fd 3 is a FIFO, not the PTY), every record read in tests (a)–(i) ends in `\n` with no `\r`, and a record containing `\r` fed to the record parser is malformed (→ degraded). (k) terminal ownership with an `os.openpty()` pair as the "real" terminal: its termios attributes are equal before and after a forwarded run; after resizing it to 40×100 and delivering `SIGWINCH`, `stty size` in the session prints `40 100`; a sentinel byte string forwarded while `cat > /dev/null` runs does not appear in the captured output, in the result object, or in any attribute of the session object (checked by scanning `vars()` recursively for the sentinel).
- Repo + branch target: eduralph/nl-shell @ main
- Scope (one logical fix) / out of scope: One session unit (new module(s) under `src/nl_shell/`) implementing pty-protocol v1 §1–§6: start `bash --noprofile --rcfile <rcfile> -i` on a PTY via ptyprocess with a pipe's write end as fd 3 in the child (§1.1); the rcfile as the spec's reference (§1.3), with two fixes stated in Design (`\\n` inside `PS0`, and `H` over every `PROMPT_COMMAND` element) plus the v1 snapshot records `T`, `B`, `X`, `P`, `J`, `H`, `V` (§3) and `bind 'set enable-bracketed-paste on'` (the spec's first open question — force it so `~/.bashrc` can't turn bracketed paste off); parse records (§2), enforce the S → D → snapshot → E order and enter degraded mode on every §4.2 trigger, with a reason, and offer a restart (a method that starts a fresh session; the REPL message is #78's); send a command as one bracketed paste + CR and refuse forbidden bytes (§5); terminal ownership (§6): a forwarding loop that, between send and done record, puts a given real terminal in raw mode, forwards its input bytes to the PTY master unchanged and keeps none of them, copies PTY output to the terminal, captures output for the caller except on the alternate screen (§6.2), copies the window size on `SIGWINCH` (§6.3), and restores the terminal afterwards. Unknown record types are ignored (spec §Versioning). Add `ptyprocess` to `pyproject.toml` `dependencies`. Update `.oss-scanner/threat_model.md` §How to exercise it (the issue asks for this): how the session tests run and that they need only bash. / out of scope: wiring into the REPL or `cli.py` (#78); the policy gate and its fd-3 / control-character rejection (#12 — the session's own refusal in (d) is defence in depth, not the gate); sudo passthrough and the per-session `SUDO_PROMPT` (#13, ADR-0015); history write-back to `~/.bash_history` (§7 — #17); taint labels and the state block (#11); a rendering filter for mirrored output (OSC 52 etc. — not owned by this issue, see Open questions); the architecture doc 05 code-layout table (one docs pass after the batch).

### Advisory — adversary

# Adversarial review — issue 10 / persistent-bash-pty-session (iteration 2)

The red→green evidence holds up. The iteration-1 hook-tamper fix does not: one command forges exit statuses and hides itself from the snapshot without degrading the session.

- **NEEDS-HUMAN [human] — making the hooks read-only does not stop a sourced script from forging records. A function named `builtin` hijacks every call inside the hook.** `src/nl_shell/session.py:114-115` marks `__nls_done`, `__nls_ret` and `__nls_user_pc` read-only. But every record the hook writes (`session.py:94-108`) goes through `builtin printf …` and `command tr/cksum`. In bash's default (non-POSIX) mode, a user function named `builtin` or `command` runs in place of the real one. Being read-only doesn't protect the callers from that. Run end to end against the patched `Session` (host bash 5.3.9, the real rcfile), one confirmed command did all of this:
  `builtin(){ if [[ $1 == printf && $2 == 'F %s\n' ]]; then command printf 'F %s\n' "${3//builtin /}" >&3; elif [[ $1 == printf && $2 == 'D %s %s %s\n' ]]; then command printf 'D %s 0 0\n' "$3" >&3; else command builtin "$@"; fi; }`
  Results: the session stays **not degraded**. `H` stays equal to the baseline (`1324652430 1556`, because `H` hashes the read-only functions, which never changed). `F` leaves out `builtin`. After that, `false` reports status `0`, pipestatus `(0,)`, and `(exit 7)` reports status `0`. This is exactly the threat the carry-forward named ("redefine the hook to write false `D`/`F`/`L` records while PROMPT_COMMAND and PS0 keep their text"), reached through a different name. The brief says exit codes on the control channel are *trusted*, and #12's gate will rely on `F`/`L`, so this breaks a trusted input. `test_replaced_done_hook_cannot_hide_state` (`tests/test_session.py:369`) only tries redefining `__nls_done` itself, so it passes. I tagged this `[human]`, not `[impl]`: inside bash there may be no full fix, because every defence (`unset -f`, `set -o posix`, `enable`) is itself a builtin a function can shadow. A human needs to decide whether to accept it as a known limit of in-band hooks (and record it in the threat model), or require a mitigation. Partial mitigations:
  - have the hook check `declare -F builtin command printf tr cksum` and write a poison record if any exists (that check can also be shadowed);
  - compare `F` with the baseline outside bash (useless once `F` is forged).
  At minimum, add a test that defines `builtin(){ …; }` and `command(){ …; }` and expects degraded mode, or a documented xfail.
- **Not refuted — the C4 red→green.** `gate-logs/C4-verify.log`: 39/39 tests failed with `ModuleNotFoundError` with the fix reverted, and passed with it. The imports happen inside the tests as the brief asks, so the red run counts as real failures, not collection errors. The tests use the production `Session` and `ProtocolTracker` (`tests/test_session.py:61`), not a copy. T3 is green (187 passed).
- **Not refuted — the oversized-number fix.** `pty_protocol.py:41-45` limits numeric fields to 18 digits, and `_handle` (`pty_protocol.py:206-211`) now catches `ValueError` as well, so a 5000-digit `D` record degrades the session instead of raising. `test_oversized_numeric_field_degrades` (`tests/test_session.py:414`) tests both the tracker and a live session. Small point, not a defect: `\d` also matches non-ASCII digits (e.g. `S ٣`). `int()` accepts those, so nothing crashes, but `[0-9]` would match §2 more exactly.
- **Not refuted — tampering through the non-read-only state variables** (`__nls_seq`, `__nls_started`, `__nls_ps0`, `__nls_once`, `session.py:84-87`). Changing them only knocks the `S`/`D` sequence numbers out of step, and `_sequence` (`pty_protocol.py:225-239`) then degrades. That fails closed.

What I tried to refute and couldn't: the C4 evidence, the bounded-number parse, and the sequence-variable tampering. What I did refute: the claim that read-only hooks stop forged records (the `builtin`/`command` shadowing above).

### Advisory — security-review

# Security review (advisory) — issue 10 / persistent-bash-pty-session

**Attacker-reachable inputs this diff touches:** command output (threat model item 1, mirrored and captured by `session.py`), and session state (item 4: `PATH`, aliases, functions and hooks set by a confirmed `source` of a repository script or by direnv), which the rcfile reports as the snapshot. Item 4 is how the round-1 finding was reached, and it is how I reached the findings below. Forwarded keystrokes are trusted input, but they must never be kept.

All three bypasses below were run against the patched code in `$PDCA_TARGET/src` (host bash 5.3.9, system `ptyprocess`). The probe scripts are `probe.py`, `probe2.py` and `probe3.py` in this run's sandbox.

- NEEDS-HUMAN [impl] — **Medium now; High once #12 reads the snapshot** ("a session change goes undetected by the gate"). `src/nl_shell/session.py:101` writes `$PATH` raw (`builtin printf 'P %s\n' "$PATH"`). It is the only snapshot field not passed through `tr` or `cksum`, so a newline in `PATH` lets session state inject whole control records. **Input:** `PATH` set by a sourced repository script (item 4). **What goes wrong:** a `PATH` ending in `\nJ 0\nH <baseline H>\nV <baseline V>\nE\nZ` closes the snapshot early with forged `J`/`H`/`V` values. The baseline values are easy to compute inside the session. `run()` returns that forged snapshot as a success, and `session.degraded` stays False. The real `J`/`H`/`V`/`E` records that follow are only read once the *next* command has been written to the PTY. Two places cause this. `run()` sends at `session.py:461` without first reading the control channel (`session.py:441-442`). The `E` branch at `session.py:513-516` returns before the degraded check, so even when the stray records arrive in the same read, the forged result is still returned. **Reproducer** (probed, 3 of 3 runs): `export LD_PRELOAD=/nonexistent.so; PATH="$PATH"$'\nJ 0\nH <h>\nV <v>\nE\nZ'` → `result.snapshot.vars_sum == baseline.vars_sum`, `degraded=False`. The next `run()` raises `SessionDegraded: control record 'J' arrived out of order (while waiting for 'S 2')`, but only after that command's bytes have gone to bash. So the gate would have classed the next command against a snapshot that hides `LD_PRELOAD`. **Suggested fix:** encode `P` the same way as `L`/`T`/`B` (or reject a `PATH` that contains a newline, which degrades the session). Before `command_sent()`, read whatever is waiting on the control channel and degrade on any stray record. In the `E` branch, check `self._tracker.degraded` before returning. **Test gap:** no test puts a newline in any reported value.

- NEEDS-HUMAN [human] — **Medium** (same rating as the round-1 finding this iteration was meant to fix: "the session doesn't enter degraded mode when its hooks were changed"; High once #12 relies on `F`/`L`). The `readonly -f __nls_done __nls_ret` fix (`session.py:114-115`) blocks redefining the hook, but the hook trusts code it doesn't protect. Every record is written through `builtin …` and `command tr` / `command cksum` (`session.py:96-107`). Bash calls a *function* named `builtin` or `command` before the real builtin, and `command tr` / `command cksum` are looked up on `PATH`. **Input:** a sourced repository script (item 4). Both routes below hide a new alias from `L` with `H` unchanged and no degraded mode (probed):
  1. `builtin(){ case $1 in alias) command builtin alias -p | command grep -v evil_nls;; compgen) command builtin compgen "${@:2}" | command grep -vx builtin;; *) command builtin "$@";; esac; }; alias evil_nls='rm -rf'`. The next snapshot has no `evil_nls` in `L`, no `builtin` in `F`, and `H` equals the baseline.
  2. A directory with a `tr` script (`grep -v evil_nls | /usr/bin/tr "$@"`), then `export PATH=<dir>:$PATH; alias evil_nls='rm -rf'`. bash still has the alias, but `L` lacks it and the session is not degraded. A fake `cksum` on `PATH` can forge `H`/`V` the same way.

  `test_replaced_done_hook_cannot_hide_state` (`tests/test_session.py:369`) covers only the "redefine `__nls_done`" route. This is a human call rather than an `[impl]` one: the snapshot is reported by the same shell it describes, so hardening only raises the bar. Options include writing `F`/`L` without external tools (bash parameter expansion instead of `tr`), sending the raw `declare` text so Python computes `H`, and flagging a function named `builtin`/`command`/`declare` or a `PATH` change against the baseline. The question is whether code from a confirmed `source` is in scope, or covered by the "code already running as the user" exclusion, the same reasoning that makes "children inherit fd 3" a known gap. The answer decides what #12 may trust `F`/`L`/`H` for.

- NEEDS-HUMAN [impl] — **Low** (the scale has no denial-of-service class, so Low is the nearest fit). `src/nl_shell/session.py:205,210` (`_Capture.data`) and `session.py:259` (`_OutputSplitter._since_start`) grow without limit for as long as a command prints. The control channel has a 1 MiB cap (`pty_protocol.py` `MAX_RECORD`), but PTY output has none. **Input:** command output (item 1), for example `cat` of a large attacker file, or a repository script that prints forever under `run(..., timeout=None)`. nl-shell's memory grows until the OOM killer (the kernel's out-of-memory handler) steps in. **Reproducer:** `session.run("yes")` with no timeout. **Suggested fix:** cap captured bytes, keep the tail, and record that the output was truncated. The state block only uses a truncated copy anyway.

Checked with no finding:
- **Forwarded input is never kept.** `_forward` (`session.py`, near the end of the file) reads into a local variable and writes it straight to the PTY. Capture stops the first time input is forwarded. The splitter's `_window` and the capture's `_tail` hold only PTY output, and the test scans `vars()` recursively.
- **Printed records can't reach the parser.** Vectors 4 and 5 are tested, and the parser rejects `\r`, oversized numbers and over-long records, all of which degrade the session.
- **Forbidden bytes are refused before anything is written.** `check_command` runs before any write and covers paste-end, ESC, NUL, DEL with paste-start, and CR.
- **Other writable `__nls_*` variables fail closed.** Changing `__nls_seq`, `__nls_started` or `__nls_ps0` only breaks the sequence, which degrades the session.
- **The rcfile's temp directory is safe.** It comes from `mkdtemp` (mode 0700) and is removed once bash has read the rcfile.
- **No unfiltered output reaches the user yet.** Mirrored PTY output is still unfiltered (OSC 52 etc.), but the brief scopes that out until #78 makes the mirror user-facing. It is not a finding on this diff.
