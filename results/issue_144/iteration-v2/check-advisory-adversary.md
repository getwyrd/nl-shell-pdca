Marks after a separator still count toward the run limit (`á́-́́́` is rejected).
- NEEDS-HUMAN [impl] — `src/nl_shell/render.py:58` (`BLANK_SYMBOLS`) / `src/nl_shell/render.py:162-174`. **Input:** proposal `command` `ls /tmp/\U00016fe4` (U+16FE4 KHITAN SMALL SCRIPT FILLER). It is category Mn, script Kits, and in UCD 16.0 it is neither Default_Ignorable nor White_Space (`/usr/share/unicode/DerivedCoreProperties.txt` has no DI entry for it). **What goes wrong:** the word after `/` is the filler alone, so it has one script and passes the mixed-script check. It is a single mark, so it passes the mark limit. `proposal.parse` returns a `Command`, and `render.escape` prints it raw. The user sees `ls /tmp/`, but bash gets a different path. This is the same kind of hole as U+1D159 from iteration 1: a filler drawn as nothing. **Fix:** add U+16FE4 to the named blank set next to U+2800/U+1D159, and add `"khitan-filler-u16fe4"` to `HIDDEN` in `tests/test_charsafety.py:100`.
- NEEDS-HUMAN [human] — `src/nl_shell/render.py:162-174` / brief "Invariant to restore" (it cites UTS #39 §3.1). **Input:** `curl 𝐜url.com` (U+1D41C MATHEMATICAL BOLD SMALL C, script Common) and `echo ｃurl` (U+FF43 FULLWIDTH LATIN SMALL LETTER C, script Latin). Both are accepted and printed raw. Each looks like `curl` but is a different word to bash. The §5.1 check ignores Common, and fullwidth letters are Latin, so this is correct per the brief's Scope (3). But §3.1 (the General Security Profile, which restricts characters by Identifier_Status, and NFKC (Unicode compatibility normalization) would fold both to ASCII) is cited in the invariant and not implemented. A human should decide whether "the policy follows UTS #39" in the threat model (`.oss-scanner/threat_model.md:130`) claims too much, or whether this belongs with #74 (the escaped confirm UI) or the deferred confusables work.
