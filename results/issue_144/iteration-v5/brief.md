# Brief — character-safety policy based on UTS #39 (from #16)

> Child 2 of the split of #16. Replaces #143's hand-picked hidden-character set
> with a policy built from Unicode properties (UTS #39, Unicode Security Mechanisms), as
> the iteration-3 sign-off asked. Decisions confirmed by the human at Plan (2026-10-15):
> mixed-script words in a proposal are rejected; Unicode data is vendored from the UCD,
> pinned to Python's `unicodedata` version (made concrete at plan review: pinned to Unicode 16.0.0, the
> version of the Python 3.14 that CI and the gate run; see Scope (4)); at most 2 combining marks per base character;
> rejection applies anywhere in a proposal `command`, quoted or not.

- **Slug:** charsafety-uts39-policy
- **Defect:** #143's hidden-character predicate (`src/nl_shell/render.py`, C0/C1/DEL/bidi/Cf/U+2028-9/tags/surrogates) lets through characters that render as nothing, as blank, or as a look-alike letter from another script. A model proposal can therefore hide or disguise part of a command (`ls<U+3164>` is a different word to bash than `ls`; `сurl` with Cyrillic U+0441 is not `curl`). Verified on the iteration-3 build: U+3164, U+115F, U+1160, U+FFA0, U+034F, U+FE00–U+FE0F, U+E0100, U+17B4, U+180B and U+2800 were accepted and printed raw (`iteration-v3` adversary and security reviews).
- **Success criterion:** `python3 -m pytest tests/test_charsafety.py` passes and covers, each fed as a stub response through `Repl` with the recording stub: (1) each of U+3164, U+115F, U+1160, U+FFA0, U+034F, U+FE00, U+FE0F, U+E0100, U+17B4, U+180B, U+2800, U+00A0, U+3000, U+E000 (private use) and U+0378 (unassigned in Unicode 16.0) inside a `command` → rejected (`No usable proposal came back from the model.`); and the same character in a request → `:context` prints it as its `\xHH` / `\uHHHH` / `\UHHHHHHHH` escape (lowercase hex). (2) `e` followed by three U+0301 in a `command` → rejected; with two U+0301 → accepted. In `:context`, a request with `e` + three U+0301 prints `e`, two raw U+0301, then the six characters `\u0301`. (3) mixed-script words in a `command` are rejected: `сurl example.com` (Cyrillic U+0441 + Latin), `ls /tmp/сurl`, `cat Dокумент.txt`. (4) these are accepted and shown unchanged: `ls Документы`, `cat αρχείο.txt`, `cat 日本語ファイル.txt` (Han + Katakana, allowed by the UTS #39 Japanese combination), `echo café` (precomposed é, and `e` + one U+0301). (5) the vendored tables record their Unicode version as `16.0.0`, and the policy takes every property it uses (including Cn and the Mn/Me categories) from those tables, so U+0378 is rejected and a code point assigned in 16.0 (U+1C89, CYRILLIC CAPITAL LETTER TJE, a Cyrillic letter) is accepted in `ls \u1c89` whatever the interpreter's `unicodedata` version. `tests/test_backend.py` still passes.
- **Falsifiability:** RED on the shipped C4 gate (`engine/scripts/run-verify.sh`, plain pytest). With this slice's production change reverted, #143's predicate stays: none of the vectors in (1)–(3) is in its set (none is C0/C1/DEL/bidi/Cf/separator/tag/surrogate — U+3164 and U+115F/U+1160/U+FFA0 are Lo, U+034F/U+FE0F/U+E0100/U+17B4/U+180B are Mn, U+2800 is So, U+00A0/U+3000 are Zs, U+E000 is Co, U+0378 is Cn), so they are accepted and printed raw, and test (5)'s import of the tables module fails — failures > 0. The tests never read the UCD files, so the gate needs no extra package.
- **Invariant to restore:** Text nl-shell shows from a proposal, `:context` or an error is exactly the text that is there: no character that renders as nothing or as blank reaches the user unmarked, and a proposal carrying one is rejected; a proposal `command` containing a word that mixes scripts is rejected (threat model must-hold "What the user confirms is exactly what runs" — the bullet of that name, `.oss-scanner/threat_model.md:127-129` on main; UTS #39 §3.1 general security profile, §5.1 mixed-script detection). Defined by Unicode properties, not by a hand-kept list.
- **Repo + branch target:** eduralph/nl-shell @ main, built on the wave base that folds #143's accepted patch (and, through it, #92). If #143 is not accepted this bundle is not scheduled.
- **Depends on:** 143
- **Ordering note:** Stacks on #143: it changes `src/nl_shell/render.py` and the parser's rejection in `src/nl_shell/proposal.py`, both created there. No overlap with #92's target loader, so no conflict with #62.
- **Surfaces:** data
- **Difficulty:** medium
- **Scope:** (1) Hidden set (rejected in a proposal `command`, escaped on every display path): #143's set, plus every code point with Default_Ignorable_Code_Point (UCD `DerivedCoreProperties.txt`), every White_Space code point (`PropList.txt`) except U+0020, LF and TAB, U+2800 BRAILLE PATTERN BLANK, and general categories Co (private use) and Cn (unassigned in the vendored 16.0.0 tables — not the runtime `unicodedata`, which is 15.0/15.1 on the Python 3.12/3.13 that `requires-python = ">=3.12"` still allows). (2) Combining marks: at most 2 consecutive characters of category Mn or Me after one base character; a `command` with more is rejected; on display, the 3rd and later marks are escaped. (3) Mixed-script words in a proposal `command`: split the `command` into words at ASCII whitespace and ASCII punctuation (Python's `string.punctuation`); a word passes if the intersection of its characters' Script_Extensions sets (UCD `ScriptExtensions.txt`, falling back to `Scripts.txt`), ignoring Common and Inherited, is non-empty, after the UTS #39 §5.1 augmentation (Han ⇒ +Bopomofo, Hiragana, Katakana, Hangul combinations: Hanb, Jpan, Kore); otherwise the proposal is rejected. Typed input and `:context` are not checked for mixed script (the gate's typed-input handling is #12's). (4) Data: vendor only the needed ranges as a generated Python module (e.g. `src/nl_shell/_unicode_tables.py`) with the Unicode version in it, produced by a generator script in `scripts/` that reads the UCD files from `/usr/share/unicode/` (Ubuntu package `unicode-data`, 16.0.0 — the same version as Python 3.14's `unicodedata`, which CI (`.github/workflows/tests.yml:19`) and the gate run); the module also carries the general category data the predicate needs (Cn, Co, Mn, Me, and #143's Cf), and the predicate reads every property from it, never from `unicodedata`; commit the generated module; no new runtime dependency; `requires-python` is unchanged. (5) Rejection applies anywhere in a `command`, quoted or not — stricter than `docs/design/specs/policy-gate/v1.md:58-61` ("outside quotes"); this is consistent with that spec (it is a MUST-reject rule; rejecting a superset breaks none of its requirements), so the spec is not edited here; say so in the threat model and note that #12, which has the bash parser, may relax it to outside-quotes only. (6) Update the threat model's "What the user confirms is exactly what runs" bullet (find it by that text; on main it is `.oss-scanner/threat_model.md:127-129`, and #143 edits its last sentence) to name this policy. Do not touch the sudo bullets above it. Tests import changed/new modules inside test functions only. / out of scope: the prompts loader, backend, stub, `:context` wiring and REPL flow (#143); whole-script confusables and skeleton matching against a word list (e.g. an all-Cyrillic `с` alone) — #74 shows non-ASCII as escapes in the confirm UI; the confirm UI and line-wrap handling (#74); typed-input warnings (#12); the `--- <role> ---` separator spoof (#11); the HTTP client (#77).
