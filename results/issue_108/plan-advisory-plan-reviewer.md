# Plan advisory — issue 108 / router-english-sentence-rule

- NEEDS-HUMAN — **The "peer to mirror" points at a detection that never fires for the vector it has to serve.** The brief says: "the existing `first_token` `ValueError` branch (`src/nl_shell/router.py:38-48`) is where an unbalanced quote is already detected; the new signal reuses that detection rather than re-lexing the line." But `first_token` calls `lexer.get_token()` only once (`router.py:40-43`). With `whitespace_split = True`, shlex stops reading at the first whitespace after a word, so it only raises `ValueError` when the bad quote is *inside the first word*. That is why the existing vector `what's using port 80` (`tests/test_repl.py:100`) hits the branch. For the new vector `find what's using port 80`, `get_token()` returns `"find"` and never reads `what's`, so there is no `ValueError` and nothing to reuse. Following the brief literally gives a red test on that vector. Do has to lex the whole line, which is the "re-lexing" the brief rules out. Revise the Citations line: name the full-line lex as part of the change, or drop the "rather than re-lexing" constraint.
- NEEDS-HUMAN — **A `ValueError` is not the same as "an unbalanced single quote", and the brief treats them as one.** In posix mode, shlex raises `ValueError` for an unclosed double quote ("No closing quotation") and for a trailing backslash ("No escaped character") as well as for an unclosed `'`. The Design section says an "unbalanced **single** quote (the `ValueError` branch in `first_token`)" is a natural-language signal "on its own". Two readings follow: (a) any lexer error means natural language, so `git commit -m "wip` routes to the model, or (b) only an unclosed `'` does. The brief doesn't choose, and no vector pins either one. Rule 3 rejects double quotes, but the quote signal is described as separate from the four conditions, so rule 3 doesn't settle it. Add one vector, or one sentence, that fixes which errors count.
- NEEDS-HUMAN — **How the quote signal ranks against the other conditions is unspecified.** "On its own" could mean it overrides rule 1 (`echo it's fine` → natural language?), rule 3 (`find . -name what's` → natural language despite the `-`?) and the "first token resolves" precondition. The brief also doesn't say whether it is checked before the builtin/`$PATH` lookup (`router.py:61-66`) or only after it. None of the ten vectors decides this, so two implementations can both pass the success criterion while routing these lines differently. Do and Check will each guess. State the order explicitly (e.g. "checked first, overrides rules 1–4"), or add one `echo …'…` vector.
- NEEDS-HUMAN — **`first_token` has a second caller the brief doesn't mention.** `src/nl_shell/failure_classes.py:46` imports `first_token`, and `failure_classes.py:388` relies on it returning a plain `str`, with the whitespace fallback on bad quoting. If Do follows the "reuse the `ValueError` branch" advice by changing `first_token`'s return type or behaviour (e.g. to report the quote error), it silently changes `_unresolved_word` in a module the scope never lists. Add to the brief: `first_token`'s signature and behaviour stay unchanged; the new signal lives in `route()` or a new helper. Name `tests/test_failure_classes.py` as a suite that must stay green.
- NEEDS-HUMAN — **"Words" is not defined, and the rules depend on it.** Rule 2 ("at least 4 words"), rule 3 ("no word starts with `-`") and rule 4 (function-word match, lowercased) all count "words", but the brief doesn't say whether that means `str.split()` or shlex tokens. The two differ on quoted input (`find 'my big file' in here`) and on the unbalanced-quote lines, where shlex can't split at all. The ten vectors don't tell the two apart, so this won't break the criterion, but it leaves an undocumented edge that the new docstring ("what it still misses") is meant to describe. One line in Design would close it.
