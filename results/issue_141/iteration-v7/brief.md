# Brief — issue 141 / persistent-bash-session-tamper-checks (re-plan, round 5: option B)

> Re-planned after five builds (`iteration-v1..v5`). Rounds 3–5 each found a new way to change
> the terminal in the gap between the hook-time reading and readline taking the terminal
> (self-removing DEBUG trap, `MAILPATH`, a job reopening fd 4 through `/proc`, signal traps).
> The human chose **option B** (2026-10-17): drop the fd-4 handshake, and claim for the three
> terminal bits readline sets itself only what can be guaranteed. Everything else from the
> round-4 brief (`iteration-v5/brief.md`) is kept unless this brief says otherwise.

- **Slug:** persistent-bash-session-tamper-checks
- **Kind:** enhancement
- **Defect:** After #140, a confirmed command can still change bash or its terminal so that the NEXT confirmed paste runs bytes other than the confirmed ones, or so that a paste is mangled, without the session degrading. Close that for the closed list below, so that **I1 holds: the bytes bash executes for a paste are exactly the confirmed bytes, or nothing is sent** (threat model "What must hold"; spec `pty-protocol/v1` §5.1).
  **Why option B (the design decision of this re-plan).** While readline reads a line it forces a fixed set of terminal fields ("the readline-forced fields", R). Measured live on the host's bash 5.3.9 (Plan revision, 2026-10-17: termios read from the PTY master while readline waited, then after a foreground `stty icrnl inlcr istrip inpck`, then while a command ran): R is at least `c_lflag` ISIG on, ICANON off, ECHO off (also v3's trace, `iteration-v3/check-advisory-adversary.md:5`: `ISIG, prepped`); `c_iflag` ICRNL, INLCR, ISTRIP, INPCK off; `c_cc` VMIN=1, VTIME=0, VLNEXT and VDISCARD disabled. The foreground `stty icrnl inlcr istrip inpck` was invisible while readline held the terminal and visible while the next command ran. Do confirms R against readline's `rltty.c` (`prepare_terminal_settings`) in bash 5.3.9 and widens it if readline forces more, naming each extra field in build-notes. The old phrase "the masked bits" in this brief now means all of R. So a change the shell makes to a field in R cannot change the bytes readline reads from a paste. It changes how the command runs afterwards (Ctrl-C/Ctrl-Z off, no echo). No reproducer in five rounds produced a marker this way. Rounds 3–5 used an fd-4 pipe handshake to read the masked bits after the hooks, and every round found a way around it, because any process of the user can reopen bash's fd 4 through `/proc` (v5 security review, 5 of 5 runs). Option B drops the handshake. The claim is split into three parts:
  **(1) Bash state that can change paste bytes degrades before the next paste.** That is everything in Table A below, captured in `H` after the last code that can run synchronously before readline (the user's `PROMPT_COMMAND` elements already run before `__nls_snap`, `session.py:126-131`, `:177`). **All traps** move into `H`, not only DEBUG/RETURN: on the base, traps are only reported in `T` (`session.py:164`, `:177`), so a signal-trap handler could run `bind …` while readline waits, after the snapshot. `T` stays as a record for the gate.
  **(2) The whole termios state while readline holds the terminal** is read from outside bash (via the PTY master) **immediately before every paste** and compared, every field including R, with a baseline taken in that same state at the first prompt. Fields outside R (`intr`/`susp`/… characters, IXON, IEXTEN, the other flags) carry the shell's own settings, so a confirmed `stty intr '|'` shows here. Fields in R must equal readline's forced values; a mismatch means something changed the terminal while readline held it (e.g. a background job's `stty -isig` or `stty istrip`), and is tampering. Any difference degrades with code `outside-check` and the paste is not written. This pre-paste check of R against readline's forced values is explicitly allowed and expected. The check-to-write race is the Known gap #147 (decision 1).
  **(3) The fields in R of the shell's OWN settings** (as they are when readline does not hold the terminal) are compared with their startup values (after `~/.bashrc`) no later than the end of the first command that runs under a change: that `run()` ends in `SessionDegraded` with code `outside-check`, and the paste after it is refused. That one command runs with the changed settings. This is a new Known gap (follow-up **#149**). Part (3) is what catches a foreground `stty -isig` or `stty icrnl`; part (2) cannot see it. How and when to read them is Do's choice, but it must not depend on bash waiting for nl-shell (no handshake). A reading that cannot tell the shell's settings from readline's must fail closed (degrade), not pass.
  **Table A rows added to `H`** (compared to the baseline; a difference degrades at that command's snapshot): **every trap** (`trap -p` for all signals plus `DEBUG`, `RETURN`, `ERR`, `EXIT`), `extdebug`, `functrace`, `errtrace`; `xtrace` and `BASH_XTRACEFD`; `declare -p PS4` and `declare -p MAILCHECK`; the enabled/disabled state of every builtin the hooks call, exposed as a module-level tuple `HOOK_BUILTINS`. Its contents are defined by the rcfile, not by a hand list: exactly the set of names written as `\builtin <name>` or `builtin <name>` in the hook functions, `PS0` and nl-shell's `PROMPT_COMMAND` element of the patched `RCFILE`, plus `builtin` itself. On `0771812` that is `printf`, `declare`, `set`, `shift`, `return`, `eval`, `:`, `shopt`, `compgen`, `alias`, `enable`, `jobs`, `trap`, `builtin`, plus whatever the new rows add (e.g. `bind`). `unset` is called only while the rcfile loads (`session.py:176`, `:178`), so it is left out. Tests read `HOOK_BUILTINS` inside each test, never at module level, so its absence on the red leg is a per-test failure, not a collection error. Also: readline on/off, emacs/vi mode, readline variables (`bind -v`) EXCEPT `history-size` (decision 5), ALL key bindings in every keymap (functions, macros, `bind -X` shell commands), history expansion (`set -H`). The locale-sensitive readline variables (`convert-meta`, `input-meta`, `output-meta`) stay in `H`, so `LC_ALL=C` degrades (failing safe, accepted). Every command substitution in the hooks captures stderr (`2>&1`), so a failing or disabled builtin never yields an empty, baseline-matching value (on the base, `trap -p` and `declare -p` drop stderr: `session.py:139`, `:151`, `:159`, `:177`).
  **Pinned after `~/.bashrc`** (kept from rounds 3–5; both are user-visible and the spec must say so): `readonly PS4` (bash traces `PROMPT_COMMAND` itself, so a planted `PS4` would run before any snapshot; decision 3), and `unset MAILCHECK; readonly MAILCHECK` (bash's mail check runs `MAILPATH` message text after `PROMPT_COMMAND`, after `H`; round-4 finding). If `~/.bashrc` already made either readonly, the pin fails and the session starts degraded with a reason naming it.
  **Baseline hooks that call redefinable code: Known gap #150, not fixed here.** A trap (other than `EXIT`) or a `bind -X` binding set by `~/.bashrc` is in the baseline, so `H` does not change for it, yet it can call a function a confirmed command redefines (`F` is only reported) and run after the snapshot. Do not add a start check for this; name it in the Known gaps (Docs).
  **Builtins and reason codes** (kept from round 4). `B` stays reported-only; `H` holds the enabled state of `HOOK_BUILTINS` only. **Interface:** `ProtocolTracker.degrade(reason: str, code: str = "other")` stores `degraded_code` next to `degraded_reason` (`pty_protocol.py:172-175`); `Session.degraded_code` is a property like `Session.degraded_reason` (`session.py:470`); `SessionDegraded` gains a `code` attribute next to `reason` (`session.py:225-232`), filled at every `raise SessionDegraded(...)`. New codes: `outside-check`, `stopped`, `tiocsti`. Of #140's sites only these are tagged: the H compare `pty_protocol.py:295` → `h-changed`; missing-record paths `pty_protocol.py:273` and `session.py:568-572` → `missing-record`; "the shell exited" `session.py:702` → `exited`. Every other #140 site keeps `other`, and the reason TEXT at every #140 site stays byte-for-byte the same (e.g. `tests/test_session.py:926` matches `"H differs"`). Disabling a builtin that stops the hooks writing records (at least `printf`, `builtin`, `set`) degrades with `missing-record` through the prompt rule (decision 6).
  **Outside checks at startup and while waiting:** read `tiocsti_path` (constructor keyword, default `"/proc/sys/dev/tty/legacy_tiocsti"`, read-only); missing, unreadable or not `0` → start degraded with code `tiocsti` and a reason naming the path. A stopped bash (`/proc/<pid>/stat` state `T`, parsed after the last `)`) degrades with code `stopped`: checked before every paste and on every poll tick of `Session._wait_for_result` (`session.py:522-578`) and `_wait_for_prompt` (`session.py:614-630`). bash's fds 0/1/2 (via `/proc/<pid>/fd`) are compared with the baseline before every paste and at each `E`; a difference degrades with `outside-check`. No separate background poller. The 5 s figures below are test timeouts, not spec numbers.
