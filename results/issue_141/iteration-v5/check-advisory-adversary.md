## Findings

- NEEDS-HUMAN [human] — `src/nl_shell/session.py:246` / `:938-942`. The brief's invariant (`brief.md:34`) says nothing outside nl-shell may run between the hook-time reading and readline taking the terminal. The patch closes this for DEBUG/RETURN/CHLD traps, PS4/xtrace and the mail check. It does not close it for ordinary signal traps. Their handlers sit only in `T`, which is reported but not compared (`session.py:235`, `:250-251`). A handler that runs after `_hook_check` writes the fd-4 line, and before readline saves the shell's terminal settings, can change `ISIG`/`ICANON`/`ECHO`. Reading (b) cannot see those bits by design (`:939-942`), so the next paste would run with the changed setting. The trigger depends on timing (the signal has to arrive in that short gap), so this is not a fixed reproducer. Decision (1) covers a background job changing termios *after* the pre-paste reading (#147). This gap is earlier: between reading (a) and readline's prep. A human should decide whether #147 covers it, or whether it should be named in the threat model's Known gaps. If neither, the spec's §3 claim about reading (a) says more than the code guarantees.
- NEEDS-HUMAN [impl] — `tests/test_session.py:1185` (with its helper ending at `:1162`). The mail-check test passes when the next paste *is written*, as long as its output has no `-isig` token. It does not assert zero PTY writes or that the session stays healthy for the right reason. So if the mail check ran but the `stty` in the message failed or was not echoed, the test would still pass. Today's fix stops mail checking outright, so a stricter test should hold: after the planted MAILPATH and the new-mail step, assert the session is healthy and `stty -a` shows `isig`. That proves the message never ran, not just that the result looked fine.
- Checked and not a finding: a leftover line on fd 4 fails safe. `_hook_check` writes only after seeing bash blocked in `read(4)` and checking that fd 4 is nl-shell's own pipe (`session.py:899-936`). If a read returned early, the next hook would not block, and `_wait_for_hook` would degrade with `outside-check` after `_SETTLE` instead of passing.
