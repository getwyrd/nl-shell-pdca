# Adversarial review — issue #141 (round 3)

Re-ran live on the host (bash 5.3.9, `legacy_tiocsti` = 0, `ptrace_scope` = 1) by driving `nl_shell.session.Session` straight from scripts in `scratch/`. pytest is not installed in this sandbox, so I did not re-run the suite. The frozen C4 log (`gate-logs/C4-verify.log`: 41 of 140 red before the fix, green after) is consistent with the brief's red-leg list.

- NEEDS-HUMAN [impl] — **A self-removing DEBUG trap turns signals off after the D check, and the next paste runs with `-isig` while the session reports healthy.** Confirmed command: `trap 'if [[ $BASH_COMMAND == *__nls_snap* ]]; then trap - DEBUG; stty -isig; fi' DEBUG`. The trap runs at the top level of `PROMPT_COMMAND` (`src/nl_shell/session.py:279`), *after* `__nls_done` has written D and nl-shell has done its in-hooks check (`session.py:1078`, `session.py:204`). It runs `stty -isig`, then removes itself before `__nls_snap`'s `trap -p` arguments are expanded, so the H trap row (`session.py:230`) shows the baseline. No delay was injected. Traced live (`scratch/late_isig2.py`): the D check saw `ISIG, cooked`. The E check (`session.py:760`) saw `ISIG, prepped`, because bash was already in readline when Python handled E. The pre-paste full compare (`session.py:967`) saw `ISIG, prepped` and passed. **The second paste was written**, and only that command's own D check found `-isig`. So the session degraded after the next confirmed command had already run with Ctrl-C/Ctrl-Z off. Results: 10 of 10 runs with no injected delay, and 5 of 5 with a 0.15 s delay. Brief (j) says `stty -isig` must be "degraded before the next paste", and brief (h) says a `trap … DEBUG` must degrade at that command's own snapshot. Neither happens here. By reading the code (not tested live; the sandbox blocked writing a test `~/.bashrc`), the same window is open to any code that runs after D: the user's `PROMPT_COMMAND` elements (`session.py:206-212`) call functions a confirmed command can redefine (F is reported only). Fix direction: take the synchronized ISIG reading at the *last* point hook-time code can run (a second fd-4 handshake just before E, or move the D handshake there). Also check `trap -p DEBUG` inside `__nls_done` before D, so a trap that removes itself still shows. Add this reproducer as a test row.
- NEEDS-HUMAN [impl] — **The E-time termios check is in practice always late, and the spec says the opposite.** In every traced run the check at `session.py:760` → `session.py:984` read readline's prepped settings, so its `not _readline_prepped(attrs) and not ISIG` branch never fires. `docs/design/specs/pty-protocol/v1.md:278` says "When `E` … arrive[s], bash runs its hooks, not readline". `v1.md:289-290` says the D-time settings "are the ones the next command runs with". The finding above shows both claims are false. The spec and the code comments (`session.py:956-960`) claim more than the code delivers. Fix them together with the finding above.
- NEEDS-HUMAN [human] — **`readonly PS4` (`session.py:179`, `v1.md:59`, `v1.md:215`) is a design change the brief did not ask for.** The brief's (r) row and decision 13 say to *detect* PS4 changes in H ("reuse the v5 detection"). The patch instead blocks them: any later `PS4=…` the user confirms, including harmless ones like `PS4='+ '` or a sourced script that sets PS4, now fails with "readonly variable" and bash drops the rest of that line. `tests/test_session.py:1333-1345` locks this in as expected behavior. The patch does close the round-1 hole (the payload ran before the snapshot), and I found no way around it: `local PS4` and `declare PS4` are both refused. Whether a user-visible behavior change is acceptable is a scope call for the human. Test (r) at `tests/test_session.py:1310-1330` also no longer exercises the brief's literal line as an attack. The line stops at the readonly error, so `set -x` never runs. The split tests at `:1348-1381` cover the xtrace rows one at a time, which answers the round-2 finding.
- Attempted, could not break: **a race against the check right before the paste** (`session.py:725` → `:967`). A background job pulsing `ISTRIP` on and off with SIGTTOU ignored (`scratch/toggler.py`, a prompt-aware 0.3 ms pulse) produced 21 degrades and 152 healthy pastes. None of the 152 was altered (`é` always reached bash as `c3 a9`). The check-then-write window exists by construction, but I could not hit it.
- Attempted, could not break: `stty -icanon -echo -isig` (now fails closed at D, `session.py:978`). Delayed D check (bash waits on fd 4). A slow `stty istrip/icrnl/inlcr` job at the prompt (caught by the full compare). `enable -n <hook builtin>` paths: `HOOK_BUILTINS` (`session.py:98-114`) matches every builtin the hooks call; `unset` is used only at rcfile load. `exec 4< <(yes)` (reasoned from the code, not run), which defeats the fd-4 handshake: `__nls_k` stays 0, but a late D check would then see prepped settings and fail closed at `session.py:978`, so it should cost false degrades, not a missed change.
