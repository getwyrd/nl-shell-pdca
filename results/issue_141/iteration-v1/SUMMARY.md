# Adversarial review — issue_141 (persistent-bash-session-tamper-checks)

I re-ran attacks live against the patched code at `$PDCA_TARGET` (host bash 5.3.9, real PTY, scripts in this sandbox's `scratch/`). pytest is not installed here, so I did not re-run the suite. I read the frozen C4 log instead. Its red leg fails 28 of 127 tests on the attack assertions (`DID NOT RAISE SessionDegraded`), not on import, so the red→green evidence looks real. One of the 28, `test_j_tiocsti_off_starts_healthy`, fails on the red leg with a `TypeError` (the new `tiocsti_path` keyword), so that one is API-shape evidence, not attack evidence.

## Findings

- NEEDS-HUMAN [impl] — The `stty -isig` check is bypassed by adding `-icanon -echo`. `src/nl_shell/session.py:937` skips the ISIG test whenever `_readline_prepped(attrs)` is true, and `session.py:1057` defines "prepped" as just "ICANON and ECHO both off". `_termios_view` also masks ISIG/ICANON/ECHO out of the compare (`session.py:319`). So a confirmed `stty -icanon -echo -isig` looks exactly like readline holding the terminal, at D, at E and before the paste. Live result: `run("stty -icanon -echo -isig")` → healthy; `run("echo hi")` → healthy; `run("stty -a …")` → output shows `-isig -icanon -echo`, and `session.degraded` is False. Every later command then runs with signals off, which is the case brief (j) says must degrade before the next paste. The (j) test only tries bare `stty -isig`, so it can't catch this. Fix: don't infer "readline has the terminal" from termios bits alone (for example, take the ISIG reading only at D, when bash is known to be in the hooks), and add `stty -icanon -echo -isig` as a test row.

- NEEDS-HUMAN [human] — The outside check runs before the paste is written, but nothing stops a background job left by an earlier confirmed command from changing termios in the gap. The check is at `session.py:699` and the write at `session.py:702`. Live: `run("(trap '' TTOU; sleep 1; for i in $(seq 200000); do stty susp '#'; stty susp '^Z'; done) >/dev/null 2>&1 &")` stays healthy (the job is asleep at its snapshot). On the next `run(...)`, the paste was **written** in 7 of 12 trials (4 of 12 with `intr '|'`) and only degraded afterwards, at E. I did not get an injected command to run: no marker in 24 trials. Still, "immediately before the paste" does not deliver "or nothing is sent" (I1) when bash has a live background job that ignores SIGTTOU. The new Known-gaps list in `.oss-scanner/threat_model.md` (patch hunk at `:181-195`) does not name this race. A human should decide whether this is a new Known gap (with a follow-up) or whether a live background job should degrade or block the paste.

- NEEDS-HUMAN [human] — Common benign commands now degrade the session with `h-changed`, because H includes the full `bind -v` output (`session.py:234`). Live: `HISTSIZE=7` → degraded `h-changed` (readline's `history-size` follows `HISTSIZE`); `LC_ALL=C` → degraded `h-changed` (the locale changes readline's meta/convert-meta variables). This fails closed, so it is not a security hole. But it makes the session restart after ordinary commands. Excluding those variables would weaken the `convert-meta` row the brief requires. That is a scope and usability trade-off, not a builder slip.

- NEEDS-HUMAN [human] — Test (r) does not assert what the brief asks. The brief says "no marker". `tests/test_session.py:1251` instead accepts a marker created during the confirmed command's own hooks and only checks that it doesn't grow afterwards. The PS4 payload really does run while the hooks are traced, before the snapshot (spec text added at patch `v1.md` hunk `:211-217`). The implementation is honest about this, but the brief's success criterion for (r) was quietly relaxed. A human should accept or reject that change.

## Attempted and could not refute

- I tried plain `stty -isig` under full CPU load (32 busy loops, 15 trials) to make Python read termios after bash had already re-entered readline. It was caught every time (0 of 15 missed).
- `enable -n` of each name in `HOOK_BUILTINS`, the `printf`/`builtin` silencing path (no D record means `missing-record`), and the `2>&1` on every hook command substitution all match the brief. The (s) test runs every listed name in its own session.
- fd 0/1/2 identity checks: the `at_prompt=False` exception for fd 1 being the control pipe applies only at E. The pre-paste check is strict, so `exec 1>&3` cannot hide there.
- A background `stty intr '|'` already running at the confirmed command's own snapshot is caught at that snapshot (`outside-check`).

### Advisory — security-review

# Advisory security review — persistent-bash-session-tamper-checks (#141)

**Attacker-reachable inputs this diff touches:** session state (threat model input 4): what a confirmed command, a confirmed `source` of a repo script, or `~/.bashrc` does to bash's traps, options, builtins, readline settings and key bindings, plus the PTY's terminal settings (termios, the kernel's per-terminal settings such as the interrupt character) and bash's fds, which the new outside checks read.

All tests below ran live against the patched tree (`$PDCA_TARGET/src`), real bash 5.3.9, `legacy_tiocsti = 0`, `ptrace_scope = 1`. The scripts are in this sandbox under `scratch/`.

## Findings

- NEEDS-HUMAN [human] — **Critical-class outcome, but possibly out of scope (see below).** `src/nl_shell/session.py:699`–`702`. The termios check before a paste and the paste write are two separate steps. Any process that can open the PTY can change termios in between: for example a background job left by an earlier confirmed command, or a script run by a confirmed `source`/`make`. **Who controls it:** the text-only attacker, through a script the user confirms once. **What goes wrong:** the confirmed paste is cut by an interrupt character set by that process. The rest of the paste then runs as a new line, and the session reports healthy. **Reproducer** (`scratch/repro_race.py`): confirmed command `(trap '' TTOU; sleep 1.5; while :; do stty intr '|'; stty intr '^C'; done) >/dev/null 2>&1 &` (its own snapshot is clean), wait 2 s, then `run("true || touch MARK")`. On 1 of 12 tries the paste went through: `run()` returned a healthy result whose output showed readline running ` touch MARK~`, and the file `MARK~` was created. The user had confirmed `true || touch MARK`, which never touches anything. On a second try, `run()` returned a healthy result with empty output, so the paste was silently lost. 10 of 12 tries degraded correctly (`outside-check`). The spec says these checks make I1 hold "before every paste" (`docs/design/specs/pty-protocol/v1.md:196` and `:269`), and the new Known-gaps list in `.oss-scanner/threat_model.md:181-195` reads as complete ("These are not covered"). Neither mentions this race. This needs a human decision, not a rebuild: either treat it as "code already running as the user" (out of scope; then list it as a Known gap with a follow-up, the way fd-3 fake records are listed under #135), or change the design. For example, refuse to paste while the session has live jobs (`J > 0`). That would not cover a `setsid`'d process that opens `/dev/pts/N` directly, so it moves a trust boundary.

- NEEDS-HUMAN [impl] — **Medium** ("the session doesn't enter degraded mode when … changed"). `src/nl_shell/session.py:734` and `:937`. **Input:** a confirmed `stty -isig`, from the user or from a sourced script. **What goes wrong:** the only reliable time to see `-isig` is when `D` arrives (readline turns ISIG back on while it waits for a line, so the E-time and pre-paste checks cannot see it). The check at `:937` also skips silently whenever readline already holds the terminal. If Python handles `D` after bash has finished the hooks and entered readline, the check passes, and every later command runs with Ctrl-C and Ctrl-Z off while the session stays healthy. **Reproducer** (`scratch/repro_isig.py`): wrap `Session._check_termios` to sleep 0.15 s first, then `run("stty -isig")`. The run returns healthy, and the next `run("stty -a | grep -o -- '-\?isig'")` prints `-isig` with the session healthy. Without the injected delay it degraded correctly 8 of 8 times, including under CPU load, so in practice the snapshot's own run time is the safety margin. That margin is not guaranteed. The patch's test (`tests/test_session.py:1151`) only covers the case where the timing works out. Suggested fix: if the D-time read finds readline already holding the terminal (`_readline_prepped(attrs)`), the check could not see the command's settings, so degrade (fail closed) instead of skipping. Or sync with the hook before it leaves for readline. Add a test that delays the D-time check, as above.

## Checked, no finding

- **Signal traps that fire later** (`trap '…bind "\r": " ; touch MARK\n"…' USR1; (sleep 1; kill -USR1 $$) &`): bash 5.3 runs the pending trap only after readline returns the next line. So the rebinding comes too late for that paste, and that command's snapshot degrades it (`h-changed`, no marker). Refuted live.
- **DEBUG/RETURN traps and functrace evading `$2`:** `$2` is expanded at the top level of `PROMPT_COMMAND`, after any DEBUG trap has fired for that command. A trap that removes itself leaves nothing behind after `E`, and a RETURN trap it plants shows in `$2`.
- **`enable -n` of each hook builtin:** `enable -a` is read with `2>&1`, so a disabled `enable`/`builtin` marks every name "not enabled" instead of producing an empty value that matches the baseline. If `builtin` itself is disabled, `\builtin printf ''` (`session.py`, in `__nls_done`) does a PATH lookup, or runs `command_not_found_handle`, once. That happens during the confirmed command's own hook, and the session then degrades with `missing-record`. Child-1's hooks did the same, so this patch does not make it worse.
- **xtrace/PS4** (test (r)): the `PS4` payload runs for the confirmed command's own traced hook lines, before its snapshot. That counts as the confirmed command's own effect, and it does not run for a later paste. The test (`tests/test_session.py:1247-1254`) checks "no new marker" instead of the brief's "no marker". That is not a security gap, but the adequacy reviewer may want to note it.
- **termios mask:** `ISTRIP`/`INPCK` are masked, but readline clears them because `CS8` (in `cflag`, which is compared) is set. `IXON`/`IXANY` are masked even though readline (built without `USE_XON_XOFF`) leaves them alone, so the spec text at `v1.md` "ignoring what readline changes" is slightly wrong for these two. There is no attack: `check_command` refuses ^S/^Q (`pty_protocol.py:153-155`). All other `c_cc` characters (`VINTR`, `VSTOP`, `VERASE`, …), `oflag`, `cflag` and the rest of `lflag`/`iflag` (for example `IUCLC`) are compared.
- **fd check:** a closed fd turns into `proc-unreadable` (fails closed). Allowing fd 1 to be the control pipe only applies when `E` arrives, not before the paste.
- **`tiocsti_path` and `proc_root`** come from the constructor (trusted). Parsing `/proc/<pid>/stat` uses `rfind(")")`, so a `comm` with parentheses cannot shift the fields.
- **Readline coverage:** `bind -p/-s/-X` recurse into the meta and Ctrl-X submaps, and `bind -v` includes `editing-mode`, `keymap` and `keyseq-timeout`.
