# Adversarial review — issue_141 (persistent-bash-session-tamper-checks)

I re-ran attacks live against the patched code at `$PDCA_TARGET` (host bash 5.3.9, real PTY, scripts in this sandbox's `scratch/`). pytest is not installed here, so I did not re-run the suite. I read the frozen C4 log instead. Its red leg fails 28 of 127 tests on the attack assertions (`DID NOT RAISE SessionDegraded`), not on import, so the red→green evidence looks real. One of the 28, `test_j_tiocsti_off_starts_healthy`, fails on the red leg with a `TypeError` (the new `tiocsti_path` keyword), so that one is API-shape evidence, not attack evidence.

## Findings

- NEEDS-HUMAN [impl] — The `stty -isig` check is bypassed by adding `-icanon -echo`. `src/nl_shell/session.py:937` skips the ISIG test whenever `_readline_prepped(attrs)` is true, and `session.py:1057` defines "prepped" as just "ICANON and ECHO both off". `_termios_view` also masks ISIG/ICANON/ECHO out of the compare (`session.py:319`). So a confirmed `stty -icanon -echo -isig` looks exactly like readline holding the terminal, at D, at E and before the paste. Live result: `run("stty -icanon -echo -isig")` → healthy; `run("echo hi")` → healthy; `run("stty -a …")` → output shows `-isig -icanon -echo`, and `session.degraded` is False. Every later command then runs with signals off, which is the case brief (j) says must degrade before the next paste. The (j) test only tries bare `stty -isig`, so it can't catch this. Fix: don't infer "readline has the terminal" from termios bits alone (for example, take the ISIG reading only at D, when bash is known to be in the hooks), and add `stty -icanon -echo -isig` as a test row.

- NEEDS-HUMAN [human] — The outside check runs before the paste is written, but nothing stops a background job left by an earlier confirmed command from changing termios in the gap. The check is at `session.py:699` and the write at `session.py:702`. Live: `run("(trap '' TTOU; sleep 1; for i in $(seq 200000); do stty susp '#'; stty susp '^Z'; done) >/dev/null 2>&1 &")` stays healthy (the job is asleep at its snapshot). On the next `run(...)`, the paste was **written** in 7 of 12 trials (4 of 12 with `intr '|'`) and only degraded afterwards, at E. I did not get an injected command to run: no marker in 24 trials. Still, "immediately before the paste" does not deliver "or nothing is sent" (I1) when bash has a live background job that ignores SIGTTOU. The new Known-gaps list in `.oss-scanner/threat_model.md` (patch hunk at `:181-195`) does not name this race. A human should decide whether this is a new Known gap (with a follow-up) or whether a live background job should degrade or block the paste.

- NEEDS-HUMAN [human] — Common benign commands now degrade the session with `h-changed`, because H includes the full `bind -v` output (`session.py:234`). Live: `HISTSIZE=7` → degraded `h-changed` (readline's `history-size` follows `HISTSIZE`); `LC_ALL=C` → degraded `h-changed` (the locale changes readline's meta/convert-meta variables). This fails closed, so it is not a security hole. But it makes the session restart after ordinary commands. Excluding those variables would weaken the `convert-meta` row the brief requires. That is a scope and usability trade-off, not a builder slip.

- NEEDS-HUMAN [human] — Test (r) does not assert what the brief asks. The brief says "no marker". `tests/test_session.py:1251` instead accepts a marker created during the confirmed command's own hooks and only checks that it doesn't grow afterwards. The PS4 payload really does run while the hooks are traced, before the snapshot (spec text added at patch `v1.md` hunk `:211-217`). The implementation is honest about this, but the brief's success criterion for (r) was quietly relaxed. A human should accept or reject that change.

## Attempted and could not refute

- I tried plain `stty -isig` under full CPU load (32 busy loops, 15 trials) to make Python read termios after bash had already re-entered readline. It was caught every time (0 of 15 missed).
- `enable -n` of each name in `HOOK_BUILTINS`, the `printf`/`builtin` silencing path (no D record means `missing-record`), and the `2>&1` on every hook command substitution all match the brief. The (s) test runs every listed name in its own session.
- fd 0/1/2 identity checks: the `at_prompt=False` exception for fd 1 being the control pipe applies only at E. The pre-paste check is strict, so `exec 1>&3` cannot hide there.
- A background `stty intr '|'` already running at the confirmed command's own snapshot is caught at that snapshot (`outside-check`).
