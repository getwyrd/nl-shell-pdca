- **Defect:** After #140, a confirmed command can still change bash or its terminal so that the NEXT confirmed paste runs bytes other than the confirmed ones, or so that a paste is mangled, without the session degrading. Close that for the closed list below, so that **I1 holds: the bytes bash executes for a paste are exactly the confirmed bytes, or nothing is sent** (threat model "What must hold"; spec `pty-protocol/v1` §5.1).
  **R, and why part 3 is gone.** While readline reads a line it forces a fixed set of terminal fields ("R"). Measured on bash 5.3.9 and confirmed against readline `rltty.c` `prepare_terminal_settings` in round 6 (`iteration-v7/build-notes.md`, "R itself"): `c_lflag` ISIG on, ICANON off, ECHO off, FLUSHO off; `c_iflag` ICRNL, INLCR off; ISTRIP, INPCK off **only when `c_cflag` CSIZE is CS8 or readline's meta flag is set (conditional; `iteration-v7/build-notes.md:238`)**; `c_cc` VMIN=1, VTIME=0, VLNEXT disabled, VDISCARD disabled when its key is bound (conditional). The ISTRIP/INPCK part of the claim below therefore depends on CSIZE staying CS8 and `input-meta` staying as at baseline; both are checked by other rows that this bundle names as required for it: CSIZE is outside R, so part 2's whole-termios compare catches a change (guard row in (j)); `input-meta` is in `bind -v`, so `H` catches it. Because readline forces R while it reads the paste, **the shell's own values of R cannot change paste bytes**; they only change how the following commands run (Ctrl-C/Ctrl-Z off, no echo). So checking the shell's own R is not needed for I1. Every way to read it without a handshake depends on nl-shell being scheduled inside a short window (round 7: D..E; at `S` the command itself may change the terminal), so it either raises false alarms or misses. It moves to #149. The claim of this bundle has two parts:
  **(1) Bash state that can change paste bytes degrades before the next paste.** Everything in Table A below, captured in `H` after the last code that can run synchronously before readline (the user's `PROMPT_COMMAND` elements already run before `__nls_snap`, `session.py:126-131`, `:177`). **Every trap except `EXIT`** moves into `H` (on the base traps are only reported in `T`, `session.py:164`, `:177`, so a signal-trap handler could run `bind …` while readline waits). `EXIT` stays out of `H` (sign-off decision 2026-10-17: it runs only at bash exit; #140's `exit-trap` test stays as is). `T` stays as a record for the gate.
  **(2) The whole termios state while readline holds the terminal** is read from outside bash (via the PTY master) **immediately before every paste** and compared, every field including R, with a baseline taken in that same state at the first prompt. Fields outside R carry the shell's own settings, so a confirmed `stty intr '|'` shows here. Fields in R must equal readline's forced values (VDISCARD conditional, as built in round 6); a mismatch means something changed the terminal while readline held it (a background job's `stty -isig` / `stty istrip`). Any difference degrades with code `outside-check` and the paste is not written. The check-to-write race is Known gap #147.
