- **Slug:** heuristic-nl-vs-command-router
- **Defect:** (gap, not a bug) nl-shell has no input router. Every non-empty, non-exit line gets the same reply, `NOT_YET` (`src/nl_shell/repl.py:15`, printed at `src/nl_shell/repl.py:47`), whether the user typed a shell command (`ls -la`) or a natural-language request (`show disk usage`). Issue #15 asks for the M0 placeholder router: if the first token of the input is an executable found on `$PATH` or a bash builtin, the input is a **command**; otherwise it is **natural language**.
- **Success criterion:** `python3 -m pytest tests/test_repl.py` passes, and it contains a table-driven test that feeds each input below through `Repl` (the scripted read function already in that file) with `$PATH` pointed at a temporary directory holding fake executables `ls`, `git` and `find` only, and asserts that the REPL's reply for that line identifies the route shown. The two replies must be distinct, fixed strings (one for each route), each still telling the user that nothing runs yet and which milestone brings it (bash session: M0.2; model backend: M0.8). Table: `ls -la` → command · `git status` → command · `find large files in my home` → command (known heuristic limitation, pinned on purpose) · `cd /tmp` → command (builtin) · `export FOO=1` → command (builtin) · `  ls` (leading spaces) → command · `show disk usage` → natural language · `what's using port 80` → natural language, and the REPL must not raise (unbalanced quote) · `frobnicate the widgets` → natural language · a path to an executable file created in the temp dir (e.g. `<tmp>/build.sh`) → command. Also: `:quit` / `:exit` still end the loop before any routing, and blank lines still print nothing (the existing tests keep passing, updated only where they assert the old `NOT_YET` reply).
- **Falsifiability:** RED is reachable on the C4 gate as shipped (`engine/scripts/run-verify.sh`, plain pytest, no extra environment). On the red leg the production files are reverted, so `Repl` prints the single `NOT_YET` reply for every line; the table test then runs and fails its route assertions (tests ran, failures > 0 — a genuine red). This holds ONLY if `tests/test_repl.py` still imports cleanly with the production change reverted — see Test file. `$PATH` is controlled by the test, so the result does not depend on what the host has installed.
- **Repo + branch target:** eduralph/nl-shell @ main
- **Ordering note:** single-issue batch, no scheduling fields. Outside this batch, M0.6 (#14, prefix modes) and M0.2 (#10, PTY) will also edit `src/nl_shell/repl.py`; whichever lands second rebases. #14's prefixes are meant to be checked BEFORE this router (architecture §5.1: "otherwise the intent classifier picks bash or natural language"), so keep the router a separate call the REPL makes after its own prefix/exit handling.
- **Surfaces:** data
- **Difficulty:** low
- **Scope:** Add the heuristic router as its own small module under `src/nl_shell/` (its own unit, so #40 can keep it as the classifier's fallback without touching the REPL), and have `Repl.run` route each non-empty, non-exit line through it and print the route-specific reply instead of the single `NOT_YET` line. Routing rule, exactly as the issue states: first token is an executable on `$PATH` (read at call time, not cached at import) or a bash builtin → command; anything else → natural language. The first token must be found without raising on input that is not valid shell quoting. A first token that contains `/` counts as a command if it names an executable file. Update the existing tests in `tests/test_repl.py` that assert the old `NOT_YET` reply, and add the module to the code-layout table in `docs/design/architecture/05-building-block-view.md` §5.3 (it is a living doc that lists modules as M0 lands). / out of scope: prefix modes and meta-commands (`\`, `?`, `@`, `@@`, `:context` … — #14); actually running anything (PTY, #10) or calling a model (#16); the trained classifier (#40); bash keywords (`if`, `for`, `while` — they collide with English and the issue names builtins only); leading env assignments (`FOO=1 make`) and aliases/functions from the user's shell — the heuristic is a placeholder, M3 replaces it; any change to `cli.py`.
- **Repro instruction:** On a clean checkout of `eduralph/nl-shell` `main` (f9e01b7): `python3 -m nl_shell`, type `ls -la`, then `show disk usage` — both print the same `nl-shell can't run anything yet…` line. In tests: `tests/test_repl.py::test_ctrl_c_clears_the_line_and_keeps_going` (input `ls`) and `::test_input_is_not_run_yet` (input `show disk usage`) both assert that same `NOT_YET` reply.
