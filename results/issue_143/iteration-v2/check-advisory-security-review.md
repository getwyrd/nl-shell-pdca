# Security review — prompts YAML, `:context`, recording stub (#143)

**Attacker-reachable inputs this diff touches:** the model's output (threat model "Where untrusted input enters" item 5), which here is the raw response a backend returns to `proposal.parse`, and is shown in the REPL. The prompts files (`targets/<id>/prompts/prompts.yaml`, `$XDG_CONFIG_HOME/nl-shell/prompts.yaml`) and the user's typed request are trusted under the threat model (nl-shell's own config files; what the user types). The patch still escapes them on every print path.

## Findings

No finding. This is what I checked:

- **Model output → screen, parse step.** `src/nl_shell/proposal.py:168-218` rejects without repair. It catches invalid JSON, `RecursionError` from deep nesting and the >4300-digit integer `ValueError` (`:183`). It rejects duplicate keys, so `{"kind":"refuse","kind":"command",…}` can't be read as last-key-wins (`:157-161`, tested). It rejects `NaN`/`Infinity` (`:164`), non-string enum values (`:221-225`), out-of-range `command` length (`:203`), and any `command` holding a character `render.is_hidden` flags (`:205`). The rule-2 combinations are checked at `:208-217`. Every value that reaches the screen is either an enum (`risk`, `reason`, mapped through the fixed `REASON_TEXT` table, `src/nl_shell/repl.py:42-65`) or a `command` that passed the hidden-character check.
- **Model output → screen, render step.** I checked whether `command` text can spoof nl-shell's own UI. `show_proposal` (`src/nl_shell/repl.py:56-62`) prefixes every LF-split line with `  | `. Every other line-break character is rejected by `is_hidden` (`src/nl_shell/render.py:34-47`): CR, VT and FF are C0, NEL is C1, and U+2028/U+2029 are listed. So a `command` can't create an unprefixed line. The header-spoof vector (`rm -rf ~\nProposed command (risk: read-only, 1 line):`) is tested at `tests/test_backend.py:475-485`. The REPL also escapes the whole reply a second time at `src/nl_shell/repl.py:124`, and `tests/test_backend.py:561` covers that (the carry-forward gap from iteration 1 is now closed).
- **Hidden-character test coverage on the attacker path.** `tests/test_backend.py:488-508` feeds ESC, CR, DEL, NEL, U+202E, U+200B, U+FEFF, U+2028 and U+E0041 as model output, in both `\u`-escaped JSON and raw-UTF-8 JSON (`ensure_ascii` True and False), and asserts rejection. The lone surrogate case runs on a UTF-8 `TextIOWrapper` (`:417-431`), so it would crash if a surrogate got through. Coverage is not just the happy path.
- **`:context`.** `prompts.render_input` (`src/nl_shell/prompts.py:210-215`) escapes hidden characters and backslashes, so a real ESC and the typed text `\x1b` print differently (tested at `tests/test_backend.py:194`). It holds only the system prompt, the examples and the user's request. No state block or command output exists yet, so no secret or tainted text can reach it in this patch. The `--- <role> ---` separator spoof is deferred to #11 by the brief, and today it can only come from trusted text.
- **Start-up errors.** `cli._error` (`src/nl_shell/cli.py:68-70`) escapes every start-up message, including #92's existing `target.toml`/config paths and the PyYAML error text that quotes the broken line. Tests cover both the prompts and the `target.toml` U+202E cases (`tests/test_backend.py:324-374`).
- **YAML loading.** Only `yaml.safe_load` is used (`src/nl_shell/prompts.py:127`). The `!!python/object/apply:os.system` vector is tested and doesn't run (`tests/test_backend.py:308`). Unhashable keys raise a `ConstructorError`, which is a `YAMLError` and becomes `PromptsError`. Example `response` values must themselves pass `proposal.parse` (`:164`), so a default or user file can't seed the few-shot examples with hidden characters in a `command`.
- **Things I didn't raise.** `clarify`/`refuse` with an extra `risk` is accepted. The spec schema and rule 2 allow it, and `risk` isn't shown for those kinds. `StubExhausted` or any backend exception would end the REPL with a traceback, but the only backend is the test stub. The real client is #77's job, and #77 should catch backend errors. Characters outside this predicate (non-Cf default-ignorables, look-alike scripts) belong to #144 by the brief's scope. The threat model's "Known gaps" are not made worse.

Gate evidence: T3 suite green (394 passed, `gate-logs/T3-suite.log`). The C4 red→green run passed, and T2 confirms the threat model was updated. The threat model's (#74) attribution was moved to M0.8/#143 (`.oss-scanner/threat_model.md:288-291`), and the stub sentence was added under "How to exercise it".
