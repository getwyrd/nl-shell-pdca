# Advisory security review — issue 155 (failure-classifier-by-exit-code), round 8

**Attacker-reachable inputs this diff touches:** session state in the snapshot (aliases as `alias -p` text, function names, `PATH`, `enable -n` text: threat model item 4); the confirmed command text when it came from a model proposal (item 5); and, indirectly, command output, because `to_reader` decides whether that output may reach the reader. The command's own output never enters `classify` (the signature has no `output`/`stderr` parameter, `src/nl_shell/failure_classes.py:119`). The package names from the lookup come from the provider (#156), which the brief treats as checked data. The classifier still passes them through a display filter (`src/nl_shell/failure_classes.py:391-416`).

**Verdict: no new finding at this round.** The round-7 fix (`alias -- NAME=` form) is correct, and it is covered by an attacker-shaped test. The known misses of the text-only rule are listed in the patch's own Known-gaps bullet (`.oss-scanner/threat_model.md:190-203`), so under the threat model they are not findings on their own.

## What I checked

- **Round-7 fix, `alias -- ` form** (`src/nl_shell/failure_classes.py:114-115`). Bash's `print_alias` writes `alias -- ` only when the name starts with `-`, and always single-quotes the value. Probes: `-s x` with `alias -- -s='sudo'` → privileged; `-- x` with `alias -- --='sudo'` → privileged; `it'\''s sudo` (bash's escape for an embedded `'`) is read as one value → privileged. Test rows `alias-dash-name` and `alias-dash-multi-line-value` (`tests/test_failure_classes.py:352-355`) are the attacker case, not just the friendly one, and `ls x` with that multi-line `-z` alias stays other (`:377`), which pins that the inner `alias ls=sudo` line is not read as a real alias.
- **Round-6 fixes are still in place.** Multi-line values are read by their quoting (`:301-347`). A repeated name becomes `None` (treated as privileged). An unclosed quote turns every later name into `None`. Memo (`:237-251`): only "not privileged" results are saved, with the chain height, and the depth cut-off is checked again on reuse (`depth + height - 1 > 8`). A privileged result ends the whole call, so a saved height is never cut short. `a8; a0` / `a8 a0` rows exist (`tests/test_failure_classes.py:348-349`). A cycle or open name returns privileged before the memo is read, so saved results never depend on `open_names`.
- **Bounded work.** `_parse_aliases` always moves `pos` forward. The unclosed-quote path is one `finditer` pass. Each alias value is checked at most once. All regexes are linear: no nested quantifiers, and the lookbehind is fixed-width. The 1200-group, `{`×40000 and nested `${X:-` rows run within the 2 s bound in C4 (`gate-logs/C4-verify.log`: green with fix, 272/273 red without).
- **Display safety.** The 127 word and package names must be printable ASCII without spaces, 1–64 characters (`:413-416`). At most 1000 lookup items are read and 5 are shown. A lookup that raises or returns `None` gives no suggestion. Every other message is fixed text or an int from the control channel (trusted).
- **`PATH` probing** (`:382-387`). Attacker-set `PATH` entries only cause `stat`/`access` calls, one per entry, and only for a plain, simple 127 command. A relative or empty entry returns no suggestion (the safe direction). A NUL byte or an over-long entry makes `isfile` return False rather than raise.
- **`to_reader`** is True only for OTHER (`:141`). PRIVILEGE, NOT_FOUND, NOT_EXECUTABLE, SIGNAL and INTERRUPTED never send output to the reader, which matches the brief and ADR-0015/0017.

## Notes (not findings, no action this slice)

- Low, not attacker-reachable today — `src/nl_shell/failure_classes.py:114,270,298`. Python's `\s` and `str.split()` treat characters such as `\x1c` and U+00A0 as whitespace, but bash only splits words on space, tab and newline. An alias whose name holds one of these is silently dropped by `_parse_aliases`, and `str.split()` cuts the command word in two. Probe: `is_privileged("s\x1c x", (), "alias s\x1c='sudo -v'\n")` → `False`, and the parser returns `{}`. To use it, the confirmed command text must contain that character. The proposal parser rejects controls and non-space White_Space in model proposals (#143, threat model "What must hold"). So only text the user typed or pasted can carry it, and the threat model trusts that. A cheap hardening for #12, or a later pass, in the safe direction: treat any line that starts with `alias ` but does not match `_ALIAS_START` as an unknown alias, and split on `[ \t\n]` instead of `str.split()`. Not raised as NEEDS-HUMAN: it is outside the attacker model and inside the brief's review bound.

No NEEDS-HUMAN items from the security lens.
