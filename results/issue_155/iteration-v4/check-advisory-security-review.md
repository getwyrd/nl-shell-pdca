# Security review (advisory) — issue 155, failure-classifier-by-exit-code

**Attacker-reachable inputs this diff touches:** the confirmed command text passed to `classify` (often a model proposal, threat model "Where untrusted input enters" item 5, which text-only attackers can steer), and the session snapshot's aliases, function names and `$PATH` (item 4, session state). The lookup result (#156 data) is also handled defensively. Command output is never read by the module (`src/nl_shell/failure_classes.py:546-603` takes only `result.status`, `ran`, `pipestatus`, `snapshot` and `command`), so item 1 does not reach it.

What's at stake: the brief's invariant ("a failed command bash could have run as a privilege program is never offered a correction and its output never goes to the reader; the only accepted misses are the ones in Known gaps"). A miss here falls under the threat model's **High** item "a privileged or destructive step is classed lower". No caller exists yet (the reader hookup is #61, correction offers are #17), so none of the findings below can be exploited today. They become live once the classifier is wired in.

I confirmed each finding by calling `classify` directly on the patched tree (`probe.py` in this sandbox, status 1, `$PATH` set to a missing directory).

## Findings

- NEEDS-HUMAN [impl] — **High** — `src/nl_shell/failure_classes.py:229-243` and `:425-429`. **Input:** the confirmed command text (model proposal or user). **What goes wrong:** rule 1b (an unclear command word counts as privileged) is never applied to a command substitution inside double quotes. The `"` branch of `_scan` copies `$(`…`)` and backticks into the word as plain characters. The re-split at `:425-429` then applies only rule 1a (the literal-name match) to the pieces. Bash still runs the command inside, so a privilege program whose name is built from an expansion gets through. Quoting a substitution is the normal style, so this is the most likely form a steered proposal would take. The brief says a command word includes the word "after `$(` [or] an opening backtick". The Known-gaps bullet (`.oss-scanner/threat_model.md:190-196`) covers expansion in **argument** position, and this is not argument position. **Reproducer** (each returns `other`, `offer_correction=True`, `to_reader=True`, while the unquoted `echo $(sud${X}o x)` correctly returns `privilege`): `echo "$(sud${X}o x)"`, `` echo "`sud${X}o x`" ``, `v="$(run$# x)"; ls`. **Fix:** when a re-split piece list contains `$(` or backtick operators, run `_unclear_command_word` on it too (or on the substitution's contents only, if `git commit -m "fix: x (y)"` must stay `other`). Add these three rows to the 1b table. The current quoted rows (`tests/test_failure_classes.py:212`, `echo "$(sudo x)"`) only test the literal name, which is the friendly case.

- NEEDS-HUMAN [impl] — **High** — `src/nl_shell/failure_classes.py:343-346`. **Input:** the confirmed command text. **What goes wrong:** inside `[[ … ]]`, every token is skipped until `]]`, including `$(` and backtick operators. Bash runs command substitutions inside `[[ ]]`, so their command words are never checked by 1b. **Reproducer:** `[[ -n $(sud${X}o x) ]]` and `[[ -n $(pk$#exec x) ]] && ls` both return `other`, `offer_correction=True`, `to_reader=True`. **Fix:** inside `in_test`, still handle `$(` and backtick operators (push and restore `expect` as the main loop does), and skip only plain words. Add both rows to the test.

- NEEDS-HUMAN [impl] — **High** (same class as above, narrower) — `src/nl_shell/failure_classes.py:396` and `:420-429`. **Input:** session state (`snapshot.functions`, set by `~/.bashrc` or a confirmed `source`) plus the command text. **What goes wrong:** a snapshot function name is treated as privileged only when it is a command word. Bash can still run it from argument position, through `eval`. Aliases are checked on every word (`:423`), but functions are not. **Reproducer:** snapshot with `functions=("f",)`, where `f`'s body runs `sudo`. Command `eval f` (or `eval "f"`) at status 1 returns `other`, `offer_correction=True`, `to_reader=True`, while `f` alone returns `privilege`. The Known-gaps bullet covers reaching sudo "from inside a shell function body other than by the function's own name". Here the function is called by its own name, so the gap does not cover it. **Fix:** in the 1a loop, treat any word (including re-split pieces) that names a snapshot function as privileged, the same way aliases are handled. This over-matches, which is the safe direction. Add `eval f` as a row.

- NEEDS-HUMAN [impl] — **Low** — `src/nl_shell/failure_classes.py:382-385` and `:398-406`. **Input:** command text. **What goes wrong:** after `coproc NAME`, the `{` that opens the body is not seen as a command-starting keyword. `expect` is already False after `NAME`, so the first command in the body skips 1b. **Reproducer:** `coproc N { sud${X}o x; }` returns `other`. This is rare, and 1a still catches literal names. **Fix:** after a `coproc` word followed by a plain name, treat a following `{` or `(` as starting a command. Add the row.

## Checked, no finding

- **Output never consulted:** the test results carry hostile output (`tests/test_failure_classes.py:54`), and the classifier ignores it. The signature has no `stderr`/`output` parameter.
- **Display safety of `message`:** the command word shown on 127 must fully match `[A-Za-z0-9._+-]{1,64}` (`:82`, `:471`). Package names must be printable ASCII and at most 64 characters, at most 5 are shown, and at most 100 items are read from the lookup (`:83`, `:498-502`). Lookup exceptions are swallowed (`:504`). An ESC or bidi character in a command word makes it unclear, so the result is `privilege` before the 127 branch.
- **`$PATH` probe (`:479-484`):** only absolute directories are probed, joined with a word limited to `[A-Za-z0-9._+-]`, using `isfile`/`access` only. No path is opened. A relative or empty entry stops the suggestion.
- **Bounded work:** the alias chain depth and the re-split depth are both capped at 8 (`:70`, `:427`, `:438`). Clean aliases are cached (`:440-444`), and alias cycles count as privileged. I saw no unbounded recursion. The brief's timing rows are in the test, and the C4 log shows them green (`gate-logs/C4-verify.log:6557-6559`: 259 of 260 red pre-fix, green post-fix).
- **Literal 1a forms, broken quoting, `$'…'`, line continuation, redirections, process substitution `<(…)`, leading `$(`, assignments with `$(…)`, `time -p`, `f()`/`function f`:** the forms I tried were classified as the brief expects.
- **Threat-model edit:** the new Known-gaps bullet matches the brief's text. Once the first two findings are fixed it stays accurate. If they are not fixed, it understates the misses: quoted substitutions and `[[ $(…) ]]` would need to be listed too.
