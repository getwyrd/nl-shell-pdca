# Security review — failure-classifier-by-exit-code (round 3)

**Attacker-reachable inputs this diff touches:** the confirmed command text (threat model item 5, model output, which file names and fetched text can steer) and the session snapshot's `aliases` and `path` (item 4, which `~/.bashrc` or a sourced repository script can set). Both feed `is_privileged` and `_unresolved_word` in `src/nl_shell/failure_classes.py`. The command's output is never read (`classify` ignores `result.output`), so item 1 is not touched. The exit status comes from the done record, which the threat model trusts.

There is no caller yet (wiring is #17 / REPL work), so every finding is **Low** today. Each one gets worse once a failed command's `Failure` decides whether nl-shell offers a correction and sends output to the reader.

I checked the round-2 bypasses on the patched tree: `sud${X}o`, `sud$'\0'o`, `s{u,}do`, `pk$'exec'`, `sud${X/q/o}o`, `sud${X@Q}o`, `sud${#X}o`, `s?do`, `/usr/bin/s*o`, a line continuation inside `sudo`, `printf -v c sudo; $c` and `read … <<< x:sudo; $b` all come back privileged. The round-2 items are fixed. The `MAX_EXPANSIONS` "too big means privileged" rule has a test row (`tests/test_failure_classes.py:246`, `echo {1..100000}`). Display safety for the not-found word and the package names (`_safe_to_show`, `:541-547`) uses `render.has_hidden`, and the tests cover ESC, U+202E and the 64/65-character limit. I found no problem there.

## Findings

- NEEDS-HUMAN [impl] — **Low**, `src/nl_shell/failure_classes.py:377-395` (`_brace_expand`) and `:294-331` (`_as_braces`). **Input:** the confirmed command text, or the value of a snapshot alias whose name appears as a word (item 4). **What goes wrong:** both functions recurse once per brace group or nested `${…:-`. A long enough word raises `RecursionError`. `is_privileged` catches only `_TooMany` (`:435-449`), so the error escapes `classify` and no class comes back at all. Once this is wired up, a crash in the post-command path can take the REPL turn down with it. **Reproduced** on the patched tree with status 1: `classify(r, "x " + "{a,b}"*1200)` raises `RecursionError` (with 900 groups it correctly returns PRIVILEGE through `_TooMany`). `"x " + "${X:-"*1200 + "}"*1200` raises it too. So does a snapshot alias `alias x='{a,b}…'` (1200 groups) with the command `x`. A `.bashrc` alias like that makes every failed run of that word crash the classifier. **Fix:** in `is_privileged`, treat `RecursionError` like `_TooMany` and return True (over-matching is the safe direction), or cap the brace and `${` nesting depth and raise `_TooMany` past it. Add test rows for the 1200-group command and for the alias.

- NEEDS-HUMAN [impl] — **Low**, `src/nl_shell/failure_classes.py:379-394` (`_brace_expand`'s loop over `{` positions, calling `_brace_close` at `:334-352`). **Input:** same as above: command text or a snapshot alias value. **What goes wrong:** for every `{` that never closes, `_brace_close` scans to the end of the word, so the time grows with the square of the length. The `MAX_EXPANSIONS` cap does not apply, because nothing gets expanded. **Measured:** `"x " + "{"*5000` takes 0.33 s, `"{"*20000` takes 5.3 s and `"{"*40000` takes 20 s, all inside one `is_privileged` call. With an alias value it repeats on every failed command that names the alias. **Fix:** find each brace's matching close in one linear pass (a stack), or give up on a word with more than a fixed number of `{` and raise `_TooMany`. Add a timing-bounded test row (for example 40 000 `{` must finish quickly and come back privileged).

- NEEDS-HUMAN [human] — **Low**, `src/nl_shell/failure_classes.py:257-258` (the comment that puts values the text does not hold out of reach) and `:398-411` (`_expanded`). **Input:** the confirmed command text. **What goes wrong:** a privileged program whose name is put together at run time is still missed. A failed run then becomes OTHER with `offer_correction=True` and `to_reader=True`. Confirmed with bash: `c=pk; ${c}exec x` runs `pkexec` (bash printed pkexec's "Cannot run program x"), and `is_privileged` returns False. The same happens with `c=pke; ${c}xec x`, `p=do; ${p}as x` and `x=run; ${x}0 y`. `$(printf s)udo x` is also False, and no word matcher can ever catch it. `c=su; ${c}do` only passes because `su` is on the list. This is the third round that finds spelling-level bypasses of decision 1. A text matcher cannot be complete against bash expansion. The real control is still the policy gate's always-confirm for privileged commands, and #12's parse is meant to replace this splitter. A human should decide one of two things. (a) Accept the leftover gap: write it into the threat model's Known gaps ("the failure classifier's privilege match is best-effort until #12; a failed privileged command built from variables or substitutions may be offered a correction"). (b) Flip the default: treat a failed command as PRIVILEGE whenever its text holds any `$`, backtick or `{` expansion next to word characters. That stops the rounds of whack-a-mole but costs more suggestions. Sending this back for another spelling-by-spelling fix will not settle it. It may overlap the 11 deferred findings held for handover, which I could not see.
