# Adversarial review — failure-classifier-by-exit-code (#155)

**Evidence.** The red→green proof holds. `gate-logs/C4-verify.log` shows 148 of 149 tests fail before the fix and all pass after it. The one test that passes before the fix is the ASCII-only source check, which is expected. The tests build a real `session.CommandResult` and call the real `classify`, so they exercise the production code, not a copy. I could not re-run pytest here (it is not installed), so I imported the patched module directly and probed it.

Findings:

- NEEDS-HUMAN [impl] — `src/nl_shell/failure_classes.py:95` (`_COARSE_SPLIT`) and `:216-220` (`_coarse`): brace expansion is split apart instead of expanded, so a privileged command written with a brace is missed. Bash expands `s{u,}do x` to `sudo sdo x`, `{s,}udo x` to `sudo udo x`, and `pk{e,}xec x` to `pkexec kxec x` (checked with `echo` in bash). `is_privileged` returns False for all three, so `classify(status=1, …)` gives OTHER with `offer_correction=True` and `to_reader=True`. This is the same bug class as the `$'sudo'` finding that iteration 1 was sent back for. The code comment at `:76-79` says brace expansion is handled, but the splitting is what breaks it. Fix: also emit the brace-expanded alternatives (or the word with `{`, `}` and `,` deleted, plus each alternative joined to its prefix and suffix). Add these three rows to `PRIVILEGED`.
- NEEDS-HUMAN [impl] — `src/nl_shell/failure_classes.py:94` (`_COARSE_DROP`) and `:216-220`: an expansion that is empty at run time joins the pieces around it, but the coarse pass keeps the variable name or splits at the expansion. Each of these runs the named program in bash (checked with `echo`, `X` unset), and each returns `is_privileged == False`: `pkexec$X x` (word becomes `pkexecX`), `doas$IFS x`, `sudo$X x`, `pke${X}xec x`, `pke$()xec x`, `do${X}as x`. `su${X}do x` and `su$(true)do x` only come back privileged by luck: the leftover piece `su` is itself on the list. Cheap over-matching fix: also emit a variant of each word with every `$NAME`, `${…}`, `$(…)` and backtick span deleted, then match that. Add rows for `pkexec$X x` and `pke${X}xec x`.
- NEEDS-HUMAN [human] — `src/nl_shell/failure_classes.py:256-273` (`is_privileged`): text matching cannot see a privilege program whose name is built at run time, such as `` `echo sud`o x `` or `$(printf '\x73udo') x` (both return OTHER, with correction offered and sent to the reader). It also cannot see one hidden in a snapshot function: with `functions=("s",)` and `s() { sudo "$@"; }`, `s x` returns OTHER. `Snapshot.functions` holds names only, so the body cannot be checked. The two `[impl]` rows above can be fixed; this wider class has no end. A human should decide whether decision 1 ("any shell word in the confirmed text") is enough protection until #12's parse lands, or whether a runtime signal is needed (for example, the `sudo` credential prompt seen on the PTY, or treating any snapshot function as possibly privileged).
- Not refuted (checked and held): the type guard; `ran=False` with blank text or comments (including `#!x`, CRLF and tab-indented); the 130-over-privilege precedence; aliases of aliases and `alias --`; quoted and backslashed spellings (`su''do`, `\sudo`, `sud\o`); `$'\x73udo'`, `$'sudo'`, `$'\U00000073udo'`; globs (`su[d]o`, `/usr/b?n/sudo`, `*udo`); NBSP and tab separators; redirections, `time`, `!`, `exec`, `coproc` and `<(…)` all giving no 127 suggestion; `~/bin` on `$PATH` treated as unknown; package display limits; a lookup that returns `str` or `None`. A lookup that raises, or returns an `int`, still propagates its exception (`:306`). The brief says the classifier trusts the provider, and iteration 1 already deferred this, so I am not filing it again.
