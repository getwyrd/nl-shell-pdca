# Security review (advisory) — issue 155, failure-classifier-by-exit-code

Attacker-reachable inputs this diff touches: the confirmed command text (threat model item 5, the model's proposal, which untrusted text can steer) and session state in `CommandResult.snapshot` (item 4: functions, `alias -p` text, `$PATH`). Exit status, `ran` and pipestatus come from the control channel and are trusted. `classify` never reads `output`, so command output (item 1) cannot change the class.

Severity uses the threat model's scale (`.oss-scanner/threat_model.md:277-310`). Every miss below is "a privileged … step is classed lower" (High, `:290`). The result: the failed command gets `offer_correction=True` and `to_reader=True`. That breaks the brief's Invariant and "What must hold" `:109-112`, and none of these forms is in the Known-gaps bullet (`:190-196`). I confirmed each with bash 5.3.9 by putting a harmless `ech${X}o` where the privilege name goes: bash runs the hidden command every time.

- NEEDS-HUMAN [impl] — **High** — `src/nl_shell/failure_classes.py:232-246`. **Input:** the confirmed command text. **What goes wrong:** the double-quote branch closes at the first unescaped `"`, even inside a `$(…)`. Bash starts a fresh quoting context inside `$(…)`, even within double quotes. So a `"…"` pair nested in a quoted substitution throws the scanner out of step with bash, and an inner `"'"` can wrap the real command in what the scanner reads as single quotes. After the re-split, that text is only an argument piece (rule 1a), so rule 1b never sees it. **Reproducer:** `echo "$(echo "'"; sud${X}o y; echo "'")"` at status 1 → `other`, offer=True, reader=True. The unquoted form `echo $(echo "'"; sud${X}o y; echo "'")` gives `privilege`. In bash, `bash -c 'echo "$(echo "'"'"'"; ech${X}o RAN1; echo "'"'"'")"'` prints `RAN1`. **Fix:** in the `"` branch, when you reach an unescaped `$(` or backtick, track nesting up to the matching close, with quotes inside it handled as at top level, instead of scanning for the next `"`. Add this row to the 1b table.
- NEEDS-HUMAN [impl] — **High** — `src/nl_shell/failure_classes.py:414-418` (with `:395-401`). **Input:** the confirmed command text. **What goes wrong:** every `)` pops the `restore` stack, even one that no `(` or `$(` pushed. A `case` arm's `)` pops early. So does a `)` after a `[[ … =~ (a|b) ]]` test that ended at the `|`, because its `(` was skipped while `in_test` was set. Inside a re-split quoted word, the pop sets `quiet` back to True while bash is still inside the substitution, so every later command word in it goes unchecked. **Reproducers** (status 1 → `other`, offer=True, reader=True): `echo "$(case x in a) ls;; esac; sud${X}o y)"` and `echo "$([[ x =~ (a|b) ]]; sud${X}o y)"`. Bash prints `RAN2` and `RAN3` for the `ech${X}o` versions. The Known-gaps "first word of a `case` arm" exemption does not cover these: the hidden command comes after `esac`, or after a `[[` test. **Fix:** pop only for a `)` that closes a matching push. Ignore `case`-arm `)`, and keep `(`/`)` balanced inside `[[`. Or fail safe: when a pop would set `quiet` back to True while unsure, leave it False. Add both rows.
- NEEDS-HUMAN [impl] — **High** — `src/nl_shell/failure_classes.py:220-231` and `:476` (`_names_privilege_program`, `:331-336`). **Input:** the confirmed command text. **What goes wrong:** `$'…'` keeps its `$` and is not decoded, so its text is `$sudo`. `$"…"` goes through the plain-character branch (`:275-279`) and then the `"` branch, so it also comes out as `$sudo`. Both are fine for rule 1b in command position, which is all the tests check (`tests/test_failure_classes.py:248-250`). But rule 1a is defined as "basename after quote removal", and both forms are quoting. Bash's quote removal gives exactly `sudo`, so 1a misses them in argument position and inside a re-split word. **Reproducers** (status 1 → `other`, offer=True, reader=True): `env $'sudo' x`, `bash -c $'sudo x'` (the `$'` twin of the required row `bash -c 'sudo x'`), `env $"sudo" x`, and `timeout 5 $'\163udo' x`. Bash runs every one (`RAN4`–`RAN7`). **Fix:** for 1a and for the re-split, produce a second text for `$'…'` with the C escapes decoded (or at least the `$` removed when there is no backslash), and drop the `$` before `"…"`. Check 1a against both texts. Decoding only `\x`/octal/`\u` escapes is a fixed, linear step, not the bash expander the brief bans. Add the four rows.
- NEEDS-HUMAN [impl] — **test coverage** — `tests/test_failure_classes.py:212`, `:287-289`. The quoted-substitution rows cover only one level with no nested quotes and no `)` other than the closing one. That is the friendly case for the code fixed this round. Add the five 1b/1a rows above. A row with a here-doc body holding an odd `'` (for example `cat <<EOF\n'\nEOF\nsud${X}o x; echo \'`) would also be useful: it classifies `privilege` today, but only by luck. The brief calls here-doc handling over-match only, and the quote desync shows it can go the other way.
- NEEDS-HUMAN [human] — **pattern, not one defect.** This is the fifth round, and each round has found a new way to put the hand-written scanner out of step with bash. This round's misses come from the new `quiet` mode for re-split pieces (`:365-366`, `:391-392`, `:416`). A safer, still text-only bound: once a re-split piece list contains a `$(` or backtick, check every word after it with rule 1b, not just tracked command words. Like the 1c decision, that would over-match. The human set the 1c bound, so whether to tighten it again, or to accept a residual list in Known gaps until #12, is their call.

Checked with no finding: the alias cycle, depth and self-reference shortcut (`:492-504`), including the `clean_aliases` cache (it only stores False results, and a deeper path is only ever stricter); the fallback union for broken quoting (`:290-297`); the `#`-after-substitution fix (`:200`, `:284-287`); quoted `[[`/`function` (`:343-348`); `<(…)`, `$((…))` and `[[ $(…) ]]`; 127 display safety (`:85-86`, `:530`, `:558`): words and packages are ASCII-printable and capped at 64 characters and 5 packages, and the `os.path.join` word cannot hold `/`; a lookup that raises or returns huge output is capped and caught (`:550-564`). Cost: 20k–120k-character nested and broken-quote inputs each finished in under 0.1 s. The C4 gate passed (288 of 289 red before the fix, green after) and T3 passed; neither runs the reproducers above.
