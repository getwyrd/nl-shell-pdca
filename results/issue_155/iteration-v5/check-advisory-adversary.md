# Adversarial review — issue 155 (failure-classifier-by-exit-code), iteration 5

The evidence holds up. The C4 log (`gate-logs/C4-verify.log`, last lines) shows 288 of 289 tests red with the fix reverted and all green with it. The one pass is the ASCII self-check the brief allows. The tests call the real `nl_shell.failure_classes.classify` with real `CommandResult` objects, so they test the production code, not a copy. T3 is green (941 passed).

I could break the fix itself. I ran each case below through the patched module (`python3 -I` against `target/src`). For each one I also ran the same text in bash 5.3, with `echo` in place of `sudo`, to confirm bash really runs the hidden command. None of these cases fits the new Known-gaps bullet, and none is in the test file.

- NEEDS-HUMAN [impl] — **A `case` pattern's `)` inside a quoted substitution turns off rule 1b for the rest of the substitution.** At `src/nl_shell/failure_classes.py:414-416`, every `)` pops the `restore` stack, including the `)` that closes a `case` pattern, which never pushed anything. Inside a re-split quoted word (`pieces=True`), this pops the `$(` frame and sets `quiet` back to True while bash is still inside the substitution. After that, `:422` (`expect = not quiet`) never sees another command word. Failing cases at status 1, each giving `other` with offer=True and reader=True: `echo "$(case x in a) :;; esac; sud${X}o y)"`, `echo "$(case x in a) :;; esac; run$# y)"`, and the backtick form ``echo "`case x in a) :;; esac; sud${X}o y`"``. Bash runs the command after `esac` (`bash -c 'echo "$(case x in a) :;; esac; ec${X}ho RAN1)"'` prints `RAN1`). The same text without the double quotes is correctly `privilege`, so only the quoted path is broken. The Known-gaps bullet covers only "the first word of a `case` arm", and the word here comes after `esac`. Fix: track `case`…`esac` depth, or only pop a frame that a matching `(`, `$(` or backtick pushed. Add these rows.
- NEEDS-HUMAN [impl] — **A process substitution inside `[[ … ]]` is never checked.** At `src/nl_shell/failure_classes.py:395-401`, the `in_test` branch skips every token except `]]` and the list operators. Only `$(` and backticks are handled before it (`:377`). `<(` and `>(` are scanned as a `redir` token plus a `(` op, so they fall into the skip. Bash runs process substitutions inside `[[ ]]`: `bash -c '[[ -n <(ec${X}ho RAN2 >&2) ]] && echo t'` prints `RAN2`. Failing cases at status 1: `[[ -n <(sud${X}o x) ]]` and `[[ -n >(sud${X}o x) ]] && ls` both give `other`, offer=True, reader=True. This is the same kind of bug the iteration-4 carry-forward reported for `$(` inside `[[`, and the fix missed the process-substitution form. Fix: inside `in_test`, treat a `<`/`>` redir followed by a glued `(` as a substitution opener (push `restore` and set `expect=True`). Add both rows.
- NEEDS-HUMAN [impl] — **`eval` or `sh -c` with a backslash or `$'…'` in a word that has no whitespace gets past rule 1a.** The re-split trigger at `src/nl_shell/failure_classes.py:90` and `:483` is only whitespace and operators. `_names_privilege_program` (`:331-336`) already removes leftover `'`/`"` (so `eval "su''do" x` is caught), but it does not remove backslashes or ANSI-C quoting (`$'…'`, bash's escape-decoding quotes). Failing cases at status 1, all giving `other` with offer=True and reader=True: `eval 'sud\o' apt update`, `eval sud\\o x`, `eval \$\'sudo\' x`, `sh -c 'sud\o'`. Bash's second round of quote removal makes each one a plain literal `sudo`, and bash runs it (`eval 'ech\o' RAN3`, `eval \$\'echo\' RAN5` and `sh -c 'ech\o RAN6'` all print). These are quoting, not expansion, so the Known-gaps bullet ("named through an expansion in argument position") does not cover them. The quoted form with a space (`bash -c "sud\\o x"`) is already caught, because it gets re-split. Fix: also re-split, or strip and recheck, any word that still holds `\`, `'`, `"` or `$'` after quote removal. This goes past the brief's literal re-split trigger, but it is the same over-match direction `:336` already takes. Add the rows.
- What I checked and could not break: alias cycles, self-referencing aliases and the clean-alias cache (`:492-504`); `#` after a glued substitution close (`:200`, `:284-287`); quoted `[[` and `function` (`:343-348`); a leading assignment with `$(…)` (`:382-391`); `coproc NAME {` (`:434-441`); `time -p`; fd-number and `&>` redirections; nested double quotes inside `$(…)`; and a `)` inside single quotes in a quoted substitution. All of these classified correctly.
- Reviewer verdict: the checks `C4 PASS` and `T3 PASS` in `check-gates.json` are accurate. But any claim that this round closes the iteration-4 "substitution inside `[[`" and "rule 1b inside quoted substitutions" findings is only partly true. Both fixes have a second spelling that still gets through (the first two bullets above).
