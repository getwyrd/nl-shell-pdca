Rules (decisions 1–4 of #62 confirmed 2026-10-19; 1c, 2, 3 re-decided by the human at this re-plan, 2026-10-20):
  1. **Privileged** if either holds, in the confirmed text or, for any word naming a snapshot alias, in that alias's value (follow chains of aliases; a cycle or a chain over 8 deep counts as privileged):
     - **1a (literal, any word):** any shell word anywhere (after `|`, `&&`, `||`, `;`, `&`, inside `$(…)` or backticks, behind `env`/`time`/`nohup`/`timeout`/`xargs`/assignments) whose basename after quote removal is one of the ten names in the Invariant. The list comes from policy-gate spec §4 (`docs/design/specs/policy-gate/v1.md:111`) plus the `-rs`/`.ws`/`sudoedit` variants. **Quoted-word re-split:** a word that, after quote removal, still contains whitespace or a shell operator (`bash -c 'sudo x'` gives the word `sudo x`) is split again with the same splitter, and 1a is applied to the pieces, repeating for nested quoting. Nesting deeper than 8 levels counts as privileged. Only 1a applies to the pieces: they are not command words for 1b, so `git commit -m "fix: x (y)"` stays other.
     - **1b (unclear command word, decision 1c):** a **command word**, after quote removal, is not plainly a name. A command word is the first word of each simple command: at the start of the text; after `|`, `|&`, `||`, `&&`, `;`, `;;`, `&`, `(`, `$(`, an opening backtick or a newline; after exactly these keywords: `if then else elif do while until ! time { coproc`; and past any leading `NAME=value` assignments and redirections. The full keyword list is closed: the word after `for`, `select`, `case`, `in`, `function`, `[[` is NOT a command word, nor is any word between `[[` and `]]`. `)` and a closing backtick are split off as operators, and the word after them is NOT a command word (so `echo $(ls) $X` stays other; the first word of a `case` arm is therefore checked by 1a only, see Known gaps). **Redirections:** an optional fd number followed by `<`, `>`, `>>`, `<<`, `<<<`, `<>`, `>|`, `>&`, `<&`, `&>` or `&>>` is one redirection operator (its `&` is NOT the background operator), and the word after it is its target. A redirection and its target are skipped when finding the command word (`>out ls` → command word `ls`); the target is checked by 1a only. Here-doc bodies are not recognised; their lines are split like commands (over-match, accepted cost). A command word is plain only if it is exactly a bash builtin or keyword, or it fully matches `(~/)?[A-Za-z0-9._+/-]+`. Anything else counts as privileged: any `$`, backtick, `{`, `}`, glob character, backslash, newline or space left in it. When quoting is broken and the router's whitespace fallback applies, the leftover quote characters make it not plain, which is the safe direction. Words in argument position are checked by 1a only.
     - **Function (decision 2):** a command word that names a snapshot function (`snapshot.functions`) counts as privileged. `Snapshot` holds names, not bodies.
     Privilege result: one fixed neutral message (it must not claim "wrong password" or "not authorized", and must not suggest re-running anything), no correction offer, not to the reader. Accepted cost: no fix offers for failed privileged commands, for commands whose name is built from an expansion, for the user's own shell functions, for any command whose text mentions a privilege name anywhere (including inside a quoted message), or for lines inside a here-doc body that look like unclear command words.
  2. **`ran=False`.** Blank or comment-only text → none. Otherwise privileged text → privilege (decision 3, ADR-0015). Otherwise → other (a syntax error).
  3. **Input type.** Only `session.CommandResult`; anything else raises `TypeError`.
  4. **127 suggestion.** Only for one simple command (no list, pipe, substitution, leading assignment) whose first word did not resolve: not a snapshot function or alias, not a bash builtin or keyword (minus `snapshot.disabled_builtins`), not an executable file in any `snapshot.path` directory (an empty or `.` entry means "unknown": no suggestion). Lookup contract: `Callable[[str], Iterable[str]]`. A bare `str` result is one name, `None` or an exception means none. The classifier trusts the provider to have checked names (#156 does) and only applies display safety.

  **Cost bound:** classification is linear in the text plus alias values. No recursion that grows with the input, and no step that rescans the rest of a word once per character. This follows from rule 1b replacing expansion: nothing gets expanded.

  **Tokenizing:** follow the router (`router.first_token`, `src/nl_shell/router.py:38-48`: `shlex` in posix mode, never raises, whitespace fallback on bad quoting). Rule 1 needs a whole-text word splitter built the same way that also splits shell operators and `$(` / backtick openers off words. Rule 4 may use `first_token` itself. The bash keyword set is the output of `compgen -k` (`if then else elif fi case esac for select while until do done in function time { } ! [[ ]] coproc`), added beside `router.BASH_BUILTINS` (`router.py:26-35`), which leaves keywords out on purpose. Do not change `router.py`. A module comment says #12's parse replaces both. The command word comes from the confirmed text, never from stderr.

  **Threat-model bullet** (put it in plain words, about this length): "The failure classifier's privilege match is text-only until #12's parse (`failure_classes`). A privilege program named through an expansion in **argument** position (for example `timeout 5 ${X}sudo x` or `bash -c "$CMD"`), named through an expansion as the first word of a `case` arm, or reached from inside a shell function body other than by the function's own name, is not seen, so the failed command may be offered a correction and its output sent to the reader. Command words that are not plain names, and names of shell functions, are treated as privileged."

  / out of scope: the real package data, SQLite, `target.toml`, `targets.py` (#156); connecting the provider to `classify` (the first caller: #17 or REPL wiring); offering or running corrections (#17); `?why` (#14); calling the reader, and dropping ADR-0025 secret-labelled output before it (#61; `to_reader` here means only "eligible by exit status", and the module docstring says so); the policy gate's parse (#12); real sudo behaviour (#24, #75); message localisation (ADR-0022); any bash expansion of words.

# Security review (advisory) — issue 155, failure-classifier-by-exit-code

Attacker-reachable inputs this diff touches: the confirmed command text (threat model item 5, the model's proposal, which untrusted text can steer) and session state in `CommandResult.snapshot` (item 4: functions, `alias -p` text, `$PATH`). Exit status, `ran` and pipestatus come from the control channel and are trusted. `classify` never reads `output`, so command output (item 1) cannot change the class.

Severity uses the threat model's scale (`.oss-scanner/threat_model.md:277-310`). Every miss below is "a privileged … step is classed lower" (High, `:290`). The result: the failed command gets `offer_correction=True` and `to_reader=True`.
