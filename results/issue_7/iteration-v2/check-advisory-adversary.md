Re-ran the script from the patch (`target/scripts/docs_checks.py`) against throwaway repos in my scratch folder. pytest is not installed here, so I could not re-run the 79 bundle tests myself. I judged C4 from `gate-logs/C4-verify.log`: green 79/79, red 79/79. The red leg only shows "script missing" (exit 2 vs the expected 1/0). That is the most a new-file feature can show, and the brief accepts it. `docs_checks.py links` on the live tree says `OK (60 relative links checked)`, matching the brief.

- NEEDS-HUMAN [impl] — **The diverged-history fix misses the #6 ratification move. A frozen proposal can be edited and the check stays green.** `scripts/docs_checks.py:254` looks up frozen status at the base tip under the *same path* the PR changed, and `:273` diffs only merge-base..head. Repro: at the merge-base, `proposals/draft/0001-arc.md` has `status: draft`. The PR branch edits its body. Main then does the ratification (`git mv` into `accepted/`, status set to `accepted`). Running `docs_checks.py immutability main pr` prints `docs-immutability: OK`, exit 0. `git merge pr` then reports "Auto-merging docs/design/proposals/accepted/0001-arc.md", and the PR's body edit lands in the now-accepted, frozen proposal. This is the exact step issue #6 will take on proposal 0001, the only proposal that exists today (`docs/design/proposals/README.md:19`). Fix: follow renames between merge-base and base tip (`git diff -M --name-status merge_base base_tip`) and check a changed path against the frozen copy at its renamed base-tip path. Add a diverged-history ratification test.
- NEEDS-HUMAN [impl] — **False failure on a fenced code block inside a list item.** `scripts/docs_checks.py:292` (`FENCE_RE`, at most 3 leading spaces) together with `:333` (indented lines inside a list never count as code) means a fence indented 4 spaces under `1. Step` is not seen as a fence. Repro: `1. Step\n\n    ~~~\n    see [x](missing.md)\n    ~~~\n` gives `page.md:4: broken link 'missing.md'`, exit 1. The brief's must-pass rule (b) says links inside fenced code blocks are ignored. The backtick version of the same case passes only by accident, because the inline-code mask at `:300-302` pairs the two triple-backtick fences as one code span. In the same family, a real indented code block inside a list item (`- Item\n\n        [x](missing.md)\n`, 8 spaces) is also flagged (exit 1). Since the job has no path filter and runs on every PR, these would block unrelated docs PRs.
- NEEDS-HUMAN [impl] — **False negative: an escaped backtick hides a real broken link.** `scripts/docs_checks.py:302` treats `\`` as the start of a code span. `Use \` then [x](gone.md) and \` end.` reports `OK (0 relative links checked)`, but CommonMark renders that link as live and broken. This is lower risk than the two above, but it is a must-fail case under (b) that the "unclosed-backtick" test does not cover.
- Checked and could not refute: byte-exact CRLF comparison (`split_lines` keeps line endings, and `compare` also requires matching endings on the status line); smuggling a second line into the status line via a bare `\r` (bytes `splitlines` splits it, so the line count changes and the check fails); renames and deletes of frozen files; status-only checks after inserted or shifted lines; Accepted→Proposed and Accepted→Implemented; non-ASCII paths (the `-z` output is parsed correctly). An Accepted ADR may take any text after `Superseded by ADR-NNNN` on its status line, so prose can be hidden in frontmatter. The brief explicitly allows this ("any text after that prefix allowed"), so it is not a defect of this diff.
- Reviewer-claim check: T3's "114 passed" is consistent with 35 existing tests plus the 79 new ones. The C4 "red without the fix" claim is technically true, but it proves only that the tests call the script. It says nothing about whether the rules are right, so the bypass in the first bullet went unnoticed by every gate.
