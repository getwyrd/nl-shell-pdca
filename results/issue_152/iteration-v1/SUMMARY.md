# Adversarial review — issue_152 (teacher endpoint, `--dev-teacher`)

**Verdict:** I could not break the main claim. With no `--dev-teacher`, nl-shell makes no TCP connection, and the evidence for that is real. The findings below are minor: two cosmetic message bugs, and a note about how much one test covers.

## What I tried to refute, and could not

- **The red→green proof.** `gate-logs/C4-verify.log` shows 87 of 220 tests failing with the production change reverted. Most of those failures (about 77) are in `tests/test_teacher_endpoint.py` and come from that file's own assertions; the other 10 are the `:status` pin updates. They are not leftovers from the `:status` churn in `test_cli.py`, `test_targets.py` or `test_backend.py`. Test (f), `test_default_path_opens_no_tcp_connection`, fails on `assert len(local) >= 1` (`0 >= 1`). That is the "REPL is not wired to the client" leg the brief asked for. With the fix, all 220 pass, and T3 (the full suite) passes 730 tests.
- **Does (f) run the production path?** Yes. The `start` fixture only swaps `Repl.interactive` for a `Repl(...)` built with every keyword `cli.main` passes, `backend=` included. So the real `TeacherClient` built at `src/nl_shell/cli.py:88-90` sends the request. The client connects through `socket.socket.connect` (`src/nl_shell/teacher_client.py:387` for Unix sockets, `:424` for TCP), which is the function the test patches. The test also checks that the server on the default socket got `REQUEST` and that the server at the config URL got 0 connections. If selection leaked the config URL, the test would go red.
- **Inputs that slip past `select_endpoint` (`src/nl_shell/teacher_client.py:214-262`).** I tried `--dev-teacher=` (empty), `teacher_url = ""` with and without the flag, `HTTP://x` (upper-case scheme; `urlsplit` lowercases it, so it agrees with the `http_target` check at `:168`), user info, `127.1`, `127.0.0.1.`, `::ffff:127.0.0.1`, `[::1%lo]` and `0.0.0.0`. Every one is either refused or, when the host is not exactly loopback, gets the warning. None leads to a TCP connection without the flag, and none hides the warning for a host that is not loopback. Without the flag, the function returns `default` before it even reads the URL (`:229-235`).
- **Config bounds (`src/nl_shell/config.py:91-101`).** Bool, NaN, inf, huge TOML integers (compared before `float()` is called), 0 and negatives are all refused. `MAX_MODEL_TIMEOUT_S = 3600` is a named constant, as the brief required.
- **Missing runtime dir.** `Endpoint("unix", None)` reaches `TeacherClient._post`, which raises `ServerNotRunning` (`src/nl_shell/teacher_client.py:528-529`). It does not crash.
- **Escaping of `:status` lines.** `describe_endpoint` (`:283-290`) returns the raw URL or path, but the REPL escapes every reply when it prints it (`src/nl_shell/repl.py:138`). No unescaped terminal output.

## Findings

- NEEDS-HUMAN [impl] — `src/nl_shell/teacher_client.py:232,244,251,257` together with `src/nl_shell/cli.py:111`: each URL in a start-up message is escaped twice, and once in a misleading way. The code builds `f"{_quote(url)!r}"`. `_quote` turns an ESC byte into the four characters `\x1b`, and `!r` then doubles the backslash. So a URL such as `http://h\x1b` shows on stderr as `'http://h\\x1b'`. A URL that really contains a backslash, or the literal text `\x1b`, prints exactly the same, so the user cannot tell them apart. A URL containing `'` switches repr to double quotes. `_error` runs `render.escape` again on top. The output is still safe, because nothing hidden reaches the terminal, but the message does not show the URL accurately. Fix: quote by hand (`f"'{_quote(url)}'"`), or apply `!r` to the raw URL and leave the escaping to `_error`.
- NEEDS-HUMAN [impl] — `src/nl_shell/teacher_client.py:265-270` (`_scheme`): an `http` URL that `urlsplit` cannot parse gets the wrong reason. For example, `--dev-teacher 'http://[::1'` makes `urlsplit` raise "Invalid IPv6 URL". `_scheme` then returns `None`, and the message says the URL "must be an http:// or https:// URL", even though the user did type `http://`. The more accurate path, which reports `BadEndpoint` "does not parse" from `http_target` (`:166-167`), never runs for this input. The test `test_url_that_cannot_be_used_is_refused[*-http://[::1]` passes because it only checks for "refused" and the URL. Fix: on `ValueError`, fall back to a raw prefix check, or let `http_target` give the reason.
- (Note only, no action needed.) `tests/test_teacher_endpoint.py`, `test_select_endpoint_opens_no_connection` (diff around test-file line 424): the patched `socket.socket.connect` is `lambda *a: ...`, which records calls but would also hide a real call by turning it into a no-op. That part is fine. The weakness is the scope: the test only covers `select_endpoint`. The brief's claim that `select_endpoint` "opens no connection" is enforced by reading the code, not by a test of the full `cli.main` path with `--dev-teacher` and no request. Test (f) covers the default path, so this is low risk. I'm noting it only so nobody reads (b)'s "nothing connects" test as covering more than it does.

# Security review (advisory): teacher-endpoint-dev-teacher-flag

**Attacker-reachable inputs this diff touches:** the dev teacher endpoint (threat model "Where untrusted input enters" item 11; attacker: **LAN peer**). The patch decides when nl-shell may connect to it. Everything else it reads is trusted by the threat model: `config.toml` keys (trusted, except that a model endpoint in it "is refused without `--dev-teacher`", `.oss-scanner/threat_model.md:101`), the `--dev-teacher` argv (the user's own input), and `XDG_RUNTIME_DIR` from nl-shell's own process environment (not the state-block env of item 3).

**Verdict: no finding.** The patch closes the endpoint rule the threat model already describes, and I found no way around it.

What I checked, against the patched source at `$PDCA_TARGET`:

- **No TCP without the flag.** In `src/nl_shell/teacher_client.py:213` onward (`select_endpoint`), every `dev_teacher is None/False` path returns `default_socket(...)`, a `unix` endpoint, whatever `teacher_url` holds. `cli.py` passes only `args.dev_teacher`, which is `None` unless `--dev-teacher` is on argv. Test (f) (`tests/test_teacher_endpoint.py`, `test_default_path_opens_no_tcp_connection`) covers the attacker-relevant case: a live TCP server at a config `teacher_url`, no flag, and it asserts zero `AF_INET`/`AF_INET6` connects, zero `create_connection` calls, and that the TCP server saw nothing. That is the case that matters, not only the friendly path. This upholds "Locally complete: no outbound connection in the default config" and "the command model … get[s] no network access in the default config" (a High item on the scale).
- **No fallback guess for the socket.** If `XDG_RUNTIME_DIR` is unset, empty or relative, `default_socket` returns `Endpoint("unix", None)`. It never picks a TCP or `/run/user/<uid>` fallback.
- **Plaintext warning can't be dodged by a host that looks like loopback.** `is_loopback` does no DNS lookup and only accepts `localhost`, `127.0.0.0/8` and `::1`. I ran these edge cases: `http://[::1%25lo]`, `http://[::ffff:127.0.0.1]`, `http://0.0.0.0`, `http://localhost.`, `http://127.0.0.1.nip.io`, `http://2130706433`, `http://0x7f.1`, `HTTP://10.0.0.1`. All of them **get** the warning. Every one errs toward warning, never toward silence.
- **Odd schemes and URLs are refused before any client gets them.** `_scheme` accepts only `http`/`https`. `http_target` (`teacher_client.py:154-181`, child-1's code, not changed here) rejects userinfo, query or fragment, control characters, non-ASCII text and a bad port before the `Endpoint` is returned. On refusal the session falls back to the default socket.
- **Terminal escapes in startup messages.** Every URL put into a refusal or warning message goes through `_quote`, which calls `render.escape`. The tests send ESC and U+202E through both the flag and the config. The `:status` line from `describe_endpoint` (`teacher_client.py:282`) prints the URL without escaping. That is safe only because an `http`/`https` endpoint reaches it after `http_target` has rejected control and non-ASCII characters. The unix path printed there comes from the user's own `XDG_RUNTIME_DIR`. No finding, but `describe_endpoint` depends on its caller having validated the URL first.
- **Resource use.** `[model] timeout_s` is limited to the range (0, 3600]. Bool, NaN, inf and huge TOML integers are refused (`config.py`, `_timeout`). The client also clamps its waits (child-1). Test (d) shows the configured deadline cuts off a slow-drip server.
- **Known gap, not made worse.** With `--dev-teacher`, the state block goes to a LAN endpoint that is unauthenticated and, over `http://`, unencrypted. That is threat model item 11. The patch adds the warning for it and does not widen it.
- **Gates.** C4 and T3 passed (`gate-logs/T3-suite.log`: 730 passed). T2 reported "no security-relevant path touched". The threat model already describes this behaviour (`:101`, item 11, "Locally complete"), so it doesn't need an update for this patch.

No NEEDS-HUMAN items.
