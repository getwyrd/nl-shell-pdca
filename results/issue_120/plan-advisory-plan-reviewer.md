# Plan review — issue 120 / buffer-background-pty-output

- NEEDS-HUMAN — **The brief contradicts itself on which bytes count as background output, and the spec forbids the obvious fix.** The Invariant says "Between a command's `D` record and the next `S` record, every byte read from the PTY master is background output". That matches spec §6.6 (`docs/design/specs/pty-protocol/v1.md:489-491`, "Between a done record and the next start record"). But criterion (d) says "bash's own prompt (`$ `, printed after `E`) is not counted as background output", and Design › What counts starts only "after bash's own prompt redraw". The prompt and the end marker are both written between D and S. Under the Invariant they are background output; under (d) they are not. The brief does not say how the session finds where the prompt ends, and spec §4.2 says "nl-shell does not parse the PTY stream for prompts" (`v1.md:402-403`). The brief also says nothing about a user's `PROMPT_COMMAND` output, which `tests/test_session.py:1004-1013` pins as "not the command's". Under the new rule it lands at every prompt, between D and S, so it would show up as background output after every command. That breaks (b)'s "waiting becomes false" right after an idle period. The planner should name the boundary: for example, bytes read after `_wait_for_prompt()` sees bash blocked in `read(0)` count, and prompt-hook output does or does not count. Without that, (d) is a design decision handed to Do rather than a criterion.

- NEEDS-HUMAN — **Criterion (c)'s exact byte counts depend on the payload the brief doesn't fix.** "the block then holds exactly the last 65536 bytes of what it wrote and reports 983040 dropped bytes" only holds if the PTY passes the job's bytes through unchanged. The PTY has ONLCR on: existing tests expect `b"hello\r\n"` for `echo hello` (`tests/test_session.py:1009`), so every LF the job writes reaches the master as two bytes. A payload that contains newlines turns the 1 MiB that was written into more than 1 MiB that was read, and both numbers come out wrong. The criterion should pin a payload with no LF (e.g. `head -c 1048576 /dev/zero | tr '\0' x`). It should also say whether the counts refer to bytes the job wrote or bytes read from the master.

- NEEDS-HUMAN — **Criteria (a) and (c) assume reading happens on its own, but the Design leaves that open.** (c) needs the job to finish "while the session is still idle (it is not stalled on a full PTY)". Design › Reading while idle lets Do pick "a method the REPL's event loop polls, a reader thread, a select hook". If Do picks polling, nothing reads unless the test calls the method, so the test either drives it (and passes no matter what) or the job stalls (red for good). The brief should say whether the session reads by itself while idle or the test polls, and how often. Otherwise the no-stall property can't be falsified. A reader thread has its own unaddressed cost: it has to hand the fd back cleanly to `run()`'s `_drain_pty` / `_wait_for_result` reads (`src/nl_shell/session.py:756`, `:831-841`) and to `close()`. The brief names that race but says nothing about how a test would show it is absent.

- NEEDS-HUMAN — **The "Peers to mirror" note puts the out-of-scope display back into scope.** The brief says "The background block is written through it [`_Ownership.mirror` / `_write_mirror`, `src/nl_shell/session_terminal.py:357-395`], not through a new writer". But an `_Ownership` only exists inside `run()` (`terminal.own(self._proc.fd)`, `src/nl_shell/session.py:771-780`), and it writes straight to the real terminal. Between commands, prompt_toolkit owns the terminal (§6.5, `v1.md:485`), and showing the block is explicitly out of scope ("showing the block above the REPL prompt … — #78"). In this slice the block can only be handed to the caller as bytes, which is how (b) frames it. As written, Do may wire a terminal write while idle (forbidden by §6.6) or spend time trying to fit the mirror path in. Restate it as "the block is bytes returned to the caller; #78 sends it through the mirror/filter path."

- NEEDS-HUMAN — **"Mark the block as untrusted" is in scope, the taint labels are out of scope, and no criterion checks the mark.** The Scope line says "Mark the block as untrusted", but the out-of-scope list holds "the state block and taint labels (#11)". `src/nl_shell` has no taint or untrusted type to attach (grep finds only comments in `cli.py:110` and `failure_classes.py:6`). None of (a)-(d) checks the label. So this is either a hidden second change (inventing a taint type before #11) or an untestable promise. Drop it, or name the concrete form (a typed return value, a docstring?) and add a check for it.

- NEEDS-HUMAN — **The issue's "Done when" can't be met by this slice, and the docs update could overclaim.** The issue says "**Done when:** the three background-output vectors in the PTY spec's conformance table pass". Vectors 13 and 14 need a confirm and its notice (`v1.md:532-533`), which the brief defers to #74/#78. The brief still frames its tests as "the session-level form of … conformance vectors 13–15" and asks Do to update `v1.md:536-540` to "say which vectors the new tests cover". The brief should state that the PR must not close #120, or that #120 is being re-scoped. It should also say that the conformance paragraph must describe the session-level parts only and not list 13/14 as covered. Otherwise Check signs off on a closure the thread's own criterion rejects.

- NEEDS-HUMAN — **The screen half of criterion (a) passes vacuously.** "the text has not reached the stand-in terminal's screen" is true on `main` too: nothing reads the PTY between commands, and the stand-in (`tests/test_session_terminal.py:148-160`) is only attached through `run(terminal=…)` during a command. The red leg of (a) rests entirely on the "waiting" flag. That's acceptable, but the brief's Falsifiability should not present the screen check as evidence. If the intent is to catch the block leaking to the terminal, the test needs a command run after the idle period. It should then check that the stand-in's screen for that run does not contain `Run this?`.
