What I could still break:

- NEEDS-HUMAN [impl] — The diagram edge `targets -.-> input` at `docs/design/architecture/05-building-block-view.md:32` is wrong. The input router reads nothing from the target: `src/nl_shell/router.py` never mentions targets or prompts. The real built runtime consumer is the model backend's prompt building: `src/nl_shell/cli.py:64` loads `prompts.load(selection.target.folder, …)` and `src/nl_shell/repl.py:5-6` feeds those prompts to the backend. Failing case: a reader of the diagram would think routing is OS-specific and would not see that the command prompts are target data. Fix: draw the edge to `backend` (or to a start-up/REPL node) instead of `input`. Also, `targets -.-> gate` is drawn with no "planned" label, although gate integration is planned (`:75`). The test doesn't check either edge, only the node line at `tests/test_architecture_targets.py:24`.
- NEEDS-HUMAN [impl] — The chapter 05 consumer list leaves out the REPL's two ADR-0023 target inputs besides `target.toml`. ADR-0023:44 and :47 list `model.toml` → installer, **REPL** and `sensitive.toml` → gate, **REPL**. But the "REPL start-up (built)" bullet at `05-building-block-view.md:69-71` names only `target.toml`, and `model.toml` appears only under the Installer bullet (`:81-82`). The brief (item 1) asks chapter 05 to explain which parts REPL start-up reads. Fix: add a planned REPL bullet for the hash check against `model.toml` and the REPL use of `sensitive.toml`.
- NEEDS-HUMAN [impl] — The test still doesn't pin the planned status where it matters most. In `tests/test_architecture_targets.py:39-50`, the chapter 07 section check requires "REPL must refuse" and "must not load", but not the sentence "These integrity checks remain requirements awaiting implementation" (`07-deployment-view.md:39`) or "not implemented by the current target loader". Concrete case: delete `07-deployment-view.md:39` and the end of the adapter sentence. The chapter then reads as if integrity checking ships today, and all 3 tests still pass. Several other required facts were already true before the fix or are too weak to mean anything: `"ID"` is a substring of `"ID_LIKE"`/`"VERSION_ID"` (`tests/test_architecture_targets.py:25`), and `"untrusted"` and `"no network"` were already in §8.5 (`:56`). Tighten the checks to test status next to each requirement.
- NEEDS-HUMAN [human] — §5.3 now deletes the catch-all planned row and replaces it with "Other module statuses are outside this target-consumer inventory" (`05-building-block-view.md:113`). The test enforces this (`tests/test_architecture_targets.py:35`, `"Remaining M0 work" not in layout`).
