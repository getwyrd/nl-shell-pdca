# Adversarial review — persistent-bash-session-core (iteration 2)

I re-ran the session live against the patched target (`$PDCA_TARGET`, host bash 5.3.9, ptyprocess 0.7.0) with small probe scripts in my sandbox. pytest is not installed in my sandbox, so I did not re-run the suite itself. I read the frozen gate logs instead: `gate-logs/C4-verify.log` shows 65 of 65 tests failing with the change reverted (each fails on its own `ModuleNotFoundError`, because the import happens inside each test) and green with it, and T3 shows 242 passed. The tests drive the real `Session` class against a real bash. None of them re-implement production code. I found one real problem the iteration-1 findings did not cover:

- NEEDS-HUMAN [human] — `src/nl_shell/session.py:464-473` (the back-at-a-prompt rule) degrades healthy, common commands that use **command substitution** (`$(...)` or backticks). A `$(...)` child does not get its own process group, so `os.tcgetpgrp` keeps returning bash's pid while the external program runs. Each of these degraded after 1.01 s, live: `echo $(sleep 2)` · ``x=`sleep 1.5`; echo hi`` · `x=$(sleep 1.5 | cat)` · `cd "$(sleep 1.2; echo /tmp)"` · `for i in 1 2 3; do x=$(sleep 0.6); done` (no single substitution passes 1 s, but bash holds the foreground the whole time). The same commands without substitution pass: `( sleep 1.5 )`, `f(){ sleep 1.5; }; f`, `sleep 1.5 | cat` and `cat <(sleep 1.5)` all returned healthy at 1.51 s. So `out=$(make)`, `v=$(curl …)` or `cd "$(slow-tool)"` will knock the session into degraded mode, and the only way out is `restart()`, whose `close(force=True)` (`session.py:287`) sends SIGHUP and kills the command that is still running. The brief, the spec (`docs/design/specs/pty-protocol/v1.md:168-171`) and the threat model's Known-gaps bullet (`.oss-scanner/threat_model.md:174-177`) accept this limit only for commands that "run inside bash itself" (`read x`, `wait`, builtin-only loops). Command substitution of an external program is a much bigger class, and none of the three documents name it. No test covers it. A human has to decide whether this limit is acceptable for v1. If it is, the docs must name command substitution. If not, the rule needs another signal, for example "bash has no live child processes", which is not simple: background jobs are also children, so a lost `D` with a job running would then hang. That is a design choice, not a builder's tweak.

Refutation attempts that failed (the patch held up):

- **Iteration-1 carry-forward cases, re-checked live.** `set -u; unset PATH` returns healthy with no hang (`session.py:111` uses `${PATH-}`). A snapshot cut short after `D` now degrades, because the timer runs until `E` (`session.py:461-473`). `interrupt()` while idle writes nothing (`session.py:385-386`). `shopt -u promptvars` and `set +o emacs` degrade through `H` (`session.py:119-122`). The readonly hook-state variables are in `H` (`session.py:115-118`).
- **Decision 5: can a command that ran be reported as not run?** I tried `fi\ntouch m1`, `# x\ntouch m2`, `\ntouch m3`, `echo a\nfi\ntouch m4` and `(exit 4)\nsleep 0.5; touch m5`. Each gave exactly one `S`/`D` pair with `ran=True`, the status of the last line, and a healthy next command. No hidden runs. Tampering with the `S` guard (`unset __nls_ps0` inside a multi-line command, `declare -n __nls_ps0=…`, `__nls_started=0`) either sends a second `S`, a wrong `D` sequence number or a changed `H`, so it fails closed (`pty_protocol.py:236-266`, `:299`).
- **Hostile but ordinary shell options.** After `set -o posix`, `set -e`, `IFS=0123456789`, `set -f; shopt -s nullglob failglob`, `shopt -s nocasematch extglob` and `export LC_ALL=C.UTF-8`, the snapshot stayed complete and the next `true` succeeded.
- **Output lost between the PTY and the `D` record.** I ran 300 × `/bin/echo helloN` and 40 × `seq 20000` (about 108 KB each), first on an idle host and then with every CPU busy. Every output matched byte for byte. The drain after `D` (`session.py:433-437`) did not drop a tail in practice.
- **Evidence shape.** The red→green comes from the real production path. Fixtures import `nl_shell.session` lazily (`tests/test_session.py:67-70`), and the framing check on every record (`:77-79`) runs in teardown on real fd-3 traffic. I found no tautological assertion in the vectors I read (`tests/test_session.py:138-339`).
